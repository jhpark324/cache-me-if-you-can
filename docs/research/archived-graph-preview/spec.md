# 지식 그래프 시안 명세

> 2026-11-02: 사용자가 이 시안을 디자인 참고 기준에서 폐기했다. 아래 내용은 당시 실험 명세의 이력이며 새 제품 디자인·기능 요구사항으로 승계하지 않는다. 그래프 라이브러리만 [ADR-004](../../decisions/ADR-004-graph-visualization-library.md)로 정식 채택했다.

## 목표와 범위

현재 기획의 기록·주제·선택적 세부 지식 및 관계를 사용자가 요청한 **3D 그래프**와 목데이터로 탐색한다. 로컬 정적 HTML/CSS/JS이며 실제 데이터 저장, AI 답변, API, 로그인, 공유, 일정 관리, 검색 성능 평가를 구현하지 않는다.

## 수용 기준

| ID | 조작·상황 | 기대 결과 |
| --- | --- | --- |
| AC-001 | 첫 진입 | 합성 데이터 표시, 학습·일상/감정·메모 기록과 주제가 연결되어 보인다. |
| AC-002 | 노드·검색 결과 선택 | 현재 저장 내용·주제·공개 범위·관련 기록이 상세에 표시되고 연결된 항목으로 이동한다. |
| AC-003 | 검색·유형·공개 범위 필터 | 결과·그래프·개수가 함께 변경된다. 없는 검색어는 빈 상태와 초기화 동작을 제공한다. |
| AC-004 | 주변 보기·깊이·세부 지식 | 1/2단계 연결을 탐색하고 세부 지식은 부모 저장본 참조와 함께 선택적으로 보인다. |
| AC-005 | 3D 그래프 조작 | 드래그 회전·노드 이동·확대·축소·화면 맞춤·자동 회전·위치 초기화가 동작한다. 깊이 좌표가 있으며 제목은 카메라를 향한다. |
| AC-006 | 공개 범위·이력 | public을 인터넷 게시로 표현하지 않는다. 과거 버전은 상세 이력에서만 표시하고 기본 그래프는 현재 버전만 표현한다. 휴지통 기록은 제외한다. |
| AC-007 | 작은 화면·키보드 | 390px·1280px·1440px 화면에서 가로 넘침 없이 탐색하며 목록·버튼으로 노드를 선택할 수 있다. |
| AC-008 | 로컬 실행 | 고정 버전 라이브러리 포함. 외부 CDN/API 없이 동작하며 브라우저 오류가 없다. |

## 설계

Operate 화면. 밝은 종이색 작업면, 녹색 주제, 청색 학습·갈색 일상/감정·자주색 메모 기록. 왼쪽 탐색, 중앙 3D 그래프, 오른쪽 저장본 상세. 작은 화면은 패널을 버튼으로 여닫는다. 저장본 문장을 읽는 것을 우선하고 기본 그래프에 버전·색인 노드를 노출하지 않는다. 회전은 사용자가 켜며 reduced-motion에서는 카메라 전환을 즉시 처리한다.

- **3d-force-graph 1.80.1 + Three.js 0.180.0 + three-spritetext 1.10.0**, MIT. 실험 당시에는 시안 한정 선택이었으며, 이후 라이브러리만 ADR-004로 제품에 채택했다. 0.187.0 조합은 당시 OrbitControls/노드 클릭 검증에서 pointerup 오류가 발생하여 0.180.0 조합으로 고정하고 재검증했다.
- Three.js/WebGL의 실제 3D 렌더링, OrbitControls, 깊이 좌표, billboard 제목을 사용한다. 임베딩 실행·그래프 DB와 별개다. WebGL을 사용할 수 없으면 오류 안내와 동일 데이터 목록을 제공한다.
- 초기 위치는 재현 가능한 3D 좌표. 노드 이동 후 위치를 고정하고 초기화로 복원한다. 대규모 성능은 검증하지 않는다.
- 노드 = Concept, Capture, 선택적 Node. Node는 capture_id/revision을 참조한다.
- 관계 = 주제 연결·관련·보충·파생·저장본 안의 부분. 유사도에서 인과를 만들지 않는다.
- 필터는 Capture에 먼저 적용하고 그 기록과 연결된 Concept/Node/Relation을 구성한다. 휴지통·이전 버전은 기본 그래프에서 제외한다.
- 검색은 목데이터 제목·본문·주제의 문자열 일치이며 실제 의미 검색이 아니다.
- 접근성: Canvas만으로 탐색하지 않아도 되도록 동등한 HTML 기록 목록 및 상세 연결 버튼 제공.

## 참고한 프로젝트와 대안

2026-11-02 공개 소스 확인. 아래 도구는 역할이 달라 직접적인 성능 순위로 비교하지 않는다.

| 프로젝트/대안 | 확인한 구현 | 판단 |
| --- | --- | --- |
| [Trilium](https://github.com/TriliumNext/Trilium/blob/main/apps/client/src/widgets/sidebar/NoteMapGraph.tsx) | note map이 force-graph를 필요할 때 로드 | 자연스러운 연결 탐색·지연 로딩 참고. |
| [Logseq](https://github.com/logseq/logseq/blob/master/package.json) | pixi.js, d3-force, graphology 의존성 | 렌더링·레이아웃 분리 참고. 이 시안에서 자체 렌더러를 만들 필요는 적다. |
| [SiYuan](https://github.com/siyuan-note/siyuan/blob/master/app/src/layout/dock/graph/GraphEngine.ts) | 자체 WebGL 렌더러, Canvas 폴백, 레이아웃 Worker | 큰 그래프의 후속 최적화 참고. |
| [3d-force-graph](https://github.com/vasturiano/3d-force-graph) | Three.js/WebGL + 3D force graph + 회전·선택 | 사용자의 3D 요청에 맞춰 시안에 채택. Trilium의 2D force-graph와 같은 저자의 라이브러리이며, Trilium이 3D판을 사용한다는 뜻은 아니다. |
| [Cytoscape.js](https://js.cytoscape.org/) | 스타일·방향 관계·선택·그래프 질의·레이아웃 | 2D 탐색이 중심일 때 후보. |
| [force-graph](https://github.com/vasturiano/force-graph) | Canvas + force 레이아웃 | 자유로운 연결망에는 좋은 대안. 관계별 스타일·라벨·조회는 더 직접 구성해야 한다. |
| [Sigma.js](https://www.sigmajs.org/) | Graphology + WebGL | 대규모 전체 그래프를 실제로 요구할 때 비교 후보. 현재 처리량 우위는 실측하지 않았다. |

## 작업 순서

1. 명세 및 고정 목데이터 작성.
2. 라이브러리를 로컬 포함하고 그래프·상세·필터 구현.
3. 브라우저에서 기능 및 세 화면 폭 검증, 결과 기록.

## 미정

제품용 최종 UI, 그래프 기본 노출 범위·노드 상한, 자동 레이아웃 전략, 실제 API 연결, 대규모 한글 라벨 성능은 후속 구현에서 결정한다.
