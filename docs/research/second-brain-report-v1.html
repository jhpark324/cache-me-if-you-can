01 / PRODUCT THESIS

새 메모리 엔진보다,
내 과거를 믿고 되찾는 경험.

추천: 직접 소유하는 작은 경험 모델 + 검증된 검색·에이전트·시각화 라이브러리. 기존 제품과의 차이는 기능 목록이 아니라, 저장과 회상의 정확성으로 증명한다.

사용자가 정한 방향

변경하지 않을 제품 중심

현재 AI 대화에서 “세컨브레인에 저장해줘”라고 요청한다. 현재 LLM이 보이는 맥락을 구조화해 Skill → MCP → 로컬 서버로 저장한다. 세션을 직접 고르거나 원문을 따로 업로드하는 것이 필수 절차가 아니다.

이후 웹 채팅·그래프·타임라인으로 자신의 고민, 결정, 행동, 배움과 변화 과정을 찾는다. 코딩 에이전트의 작업 상태보다 사용자의 경험을 중심에 둔다.

보고서의 제안 · 미확정

구현을 시작할 기본 조합

코어Python 모듈형 단일 서버 / FastAPI
데이터SQLite 원본 + FTS5 + sqlite-vec
회상제한된 LangGraph + 로컬 도구
웹React·Vite + Cytoscape.js

배포Python 패키지에 웹 정적 빌드 포함

이 조합은 최종 결정이 아니다. D01–D32에서 대안과 교체 조건을 비교할 수 있다.

한 문장 제품 정의

“AI와 함께 생각하고 작업한 순간을 내가 선택해서 보존하고, 그때의 맥락과 근거를 연결해 다시 활용하는 개인용 Second Brain.”

첫 공개 버전에 포함의도적으로 제외이유
선택 저장, 수정·되돌리기, 근거 확인모든 대화·화면의 상시 자동 수집선택권과 신뢰가 먼저이며 수집 누락은 솔직히 드러낸다.
웹 채팅 + 주변 그래프 + 타임라인전체 우주형 그래프만 있는 데모사용자가 질문에서 원래 경험까지 도달해야 한다.
로컬 저장 + 사용자가 고른 추론 경로자동 클라우드 전송·자동 과금 fallback로컬 데이터 소유와 오프라인 추론은 별개다.
한 사용자·한 기기·여러 MCP 클라이언트계정 SaaS·실시간 협업·멀티기기 동기화파일 정합·충돌·보안 범위를 제한한다.
근거가 있는 회고·자소서 사례 찾기자동 성격 진단·성과 숫자 생성기록되지 않은 삶이나 결과를 추측하지 않는다.

왜 지금 만들 가치가 있는가? Basic Memory처럼 선택 저장과 MCP를 이미 제공하는 도구가 있다. 따라서 ‘MCP가 붙은 메모리’는 차별점이 아니다. 하지만 누가 제안했는지, 사용자가 실제로 했는지, 언제의 경험인지, 무엇으로 확인할 수 있는지를 하나의 회상 UX로 만드는 방향은 검증할 가치가 있다. 기존 제품에 그런 기능이 전혀 없다는 주장이 아니라, 이 프로젝트의 집중 지점이다. [S01][S02][S04]

02 / OPEN-SOURCE LANDSCAPE

많이 겹친다. 그래서 더 정확히 비교한다.

아래 ‘기능 사실’은 공식 프로젝트 자료에 근거한다. ‘가져올 개념·채택의 대가·검증 질문’은 이 제품 요구에 대한 설계 판단이다.

GitHub 별 수는 조회된 페이지의 반올림 스냅샷이며 인기의 참고치일 뿐이다. 다운로드·활성 사용자·품질 순위로 해석하지 않는다. 라이선스와 지원 기능은 출시 직전 채택할 커밋 기준으로 다시 확인한다.

03 / DIFFERENTIATION AS A TESTABLE HYPOTHESIS

핵심 가설 H1

“기록은 있지만 믿기 어렵다”를 해결

기억 검색보다 기억의 주체와 상태를 정확히 보존하는 기능이 자소서·회고에서 더 큰 가치를 줄 수 있다. 최소 검증은 과거 프로젝트를 설명할 때 AI 제안과 실제 실행을 사용자가 다시 구분해야 하는 부담이 줄어드는지다.

핵심 가설 H2

그래프는 선택적 맥락 도구

넓은 전체 그래프보다 “이 경험이 나온 배경·그 이후”를 작은 범위로 보여주는 그래프가 유용할 수 있다. 도움이 없으면 그래프는 보조 화면으로 남기고, 검색과 타임라인을 기본으로 유지한다.

차별성이 검증되지 않으면?

자체 엔진 개발을 계속 밀어붙일 필요가 없다. Basic Memory나 Hindsight 위에 개인 경험 스키마·정정 UI·회고 화면을 제공하는 제품 계층으로 전환한다. 이 경우에도 사용자가 얻는 가치는 유지할 수 있지만, 라이선스·데이터 소유·엔진 정책의 제약을 수용해야 한다. [S01][S04]

가장 작은 초기 사용자군

여러 AI 도구로 프로젝트와 학습을 진행하며, 나중에 자신의 경험을 설명해야 하는 사람부터 시작한다. 개발자·학생·취업 준비자는 첫 검증 집단이지 영구적인 스키마 제한이 아니다. 건강·법률·민감한 인간관계의 자동 분석, 조직 전체 지식 관리로 시작하지 않는다.

선택 저장에는 필연적인 관측 편향이 있다. 답변은 “저장된 기록에서는…”으로 범위를 제한해야 한다. 기록이 적은 주제를 사용자의 경험 부족이나 성향으로 해석해서는 안 된다.

모듈 분리 ≠ 마이크로서비스

MCP·REST·에이전트는 인터페이스이고 저장·검색은 내부 서비스다. 별도 DB 서버나 브로커 없이 하나의 배포 단위로 시작한다. MCP Python SDK의 ASGI 통합과 FastAPI 정적 파일 서빙을 활용할 수 있다. [S20][S35]

임베딩은 CPU/GPU 작업이므로 이벤트 루프 밖의 제한된 worker에서 실행한다. worker를 별도 프로세스로 바꾸더라도 제품 전체를 마이크로서비스로 나눌 필요는 없다.

“SQLite 하나”의 정확한 뜻

하나의 DB 엔진만으로 코어 운영이 가능하다는 뜻이다. 영구 기억 DB와 삭제 가능한 채팅 체크포인트·레이아웃 캐시는 수명주기가 달라 별도 SQLite 파일로 둘 수 있다.

WAL은 읽기와 쓰기의 동시 진행을 돕지만 동일 DB 파일의 writer는 하나다. 짧은 트랜잭션, 재시도, 연결별 외래키 설정, 로컬 디스크 사용이 전제다. [S12]

시간 모델: 구간과 불확실성을 함께

“2026년 9월쯤”은 해당 시간대의 9월 구간으로 정규화하고 precision=month와 원래 표현을 보존한다. “지난달”은 대화 기준 시각이 확실할 때만 계산한다. 날짜를 모르면 null이다. 조회는 발생 구간의 겹침 여부를 사용하고 날짜 미상 결과를 별도 구역에 둔다. 시간 구분의 개념은 Graphiti의 접근에서 참고하되, 완전한 이중시간 그래프까지 MVP에 구현하지 않는다. [S03]

정정 시 관계의 재연결도 검토한다

기억을 수정하면 새 revision의 노드 스냅샷을 만들고, 과거 답변은 당시 revision을 가리키게 한다. 기존 edge를 수정된 주장에 무조건 복사하지 않는다. 내용·근거가 유지된 경우만 재연결하고, 바뀐 관계는 재검토 후보로 남긴다. 초기에는 이 보수적인 방식으로 시작하고, 반복 수정이 많아지면 논리적 노드 ID와 노드 버전 테이블을 분리하는 대안을 검토한다.

같은 주제 ≠ 같은 경험

한 사람이 같은 문제를 여러 번 고민했다면 각각의 Capture를 보존한다. 같은 요청 재전송은 request_id로 중복 제거하고, 의미가 비슷하다는 이유로 다른 시점의 경험을 합치지 않는다. 프로젝트 이름만 같아도 다른 프로젝트일 수 있으므로 alias 해소는 후보 조회와 사용자 병합·되돌리기를 허용한다.

설계 검토용 DDL이며 운영 마이그레이션 완제품은 아니다. SQLite로 파싱·FTS 기본 동작을 확인한 코어 예시다. causal evidence·현재 revision·cross-capture 참조 정책은 서비스 검증을 추가해야 한다. FTS 외부 콘텐츠 인덱스는 쓰기 시 동기화해야 한다. [S13]

CREATE TABLE captures (
  id TEXT PRIMARY KEY,
  current_revision INTEGER NOT NULL DEFAULT 1,
  saved_at TEXT NOT NULL,          -- server UTC; never generated by the LLM
  privacy TEXT NOT NULL DEFAULT 'normal'
    CHECK (privacy IN ('normal','sensitive','local_only')),
  deleted_at TEXT
);
CREATE TABLE capture_revisions (
  capture_id TEXT NOT NULL REFERENCES captures(id) ON DELETE CASCADE,
  revision INTEGER NOT NULL CHECK (revision > 0),
  title TEXT NOT NULL,
  summary TEXT NOT NULL,
  narrative TEXT NOT NULL,
  occurred_start TEXT,
  occurred_end_exclusive TEXT,
  time_precision TEXT NOT NULL DEFAULT 'unknown'
    CHECK (time_precision IN ('unknown','instant','day','month','year','range')),
  time_basis TEXT NOT NULL DEFAULT 'unknown'
    CHECK (time_basis IN ('explicit','relative_resolved','inferred','unknown')),
  original_time_text TEXT,
  timezone TEXT NOT NULL DEFAULT 'UTC', -- preserve configured IANA zone per capture
  source_client TEXT NOT NULL,
  source_locator_json TEXT CHECK (source_locator_json IS NULL OR json_valid(source_locator_json)),
  coverage TEXT NOT NULL
    CHECK (coverage IN ('visible_context','selected_excerpts','imported_transcript','summary_only')),
  schema_version INTEGER NOT NULL,
  content_hash TEXT NOT NULL,      -- dedup/version check, not proof of authenticity
  created_at TEXT NOT NULL,
  change_reason TEXT,
  PRIMARY KEY (capture_id, revision),
  CHECK ((occurred_start IS NULL AND occurred_end_exclusive IS NULL)
      OR (occurred_start IS NOT NULL AND occurred_end_exclusive IS NOT NULL
          AND occurred_start < occurred_end_exclusive))
);
-- Service invariant: captures.current_revision must identify an existing revision.
-- New capture + revision + nodes + FTS documents + job + receipt commit together.
CREATE TABLE memory_nodes (
  id TEXT PRIMARY KEY,
  capture_id TEXT NOT NULL,
  revision INTEGER NOT NULL,
  local_id TEXT NOT NULL,
  kind TEXT NOT NULL CHECK (kind IN
    ('question','consideration','decision','action','result','lesson','idea')),
  content TEXT NOT NULL,
  context TEXT,
  actor TEXT NOT NULL CHECK (actor IN ('user','assistant','tool','unknown')),
  assertion_basis TEXT NOT NULL CHECK (assertion_basis IN
    ('user_stated','assistant_suggested','tool_observed','inferred','unknown')),
  action_state TEXT NOT NULL DEFAULT 'unknown' CHECK (action_state IN
    ('considered','decided','planned','in_progress','completed','unknown')),
  review_state TEXT NOT NULL DEFAULT 'unreviewed'
    CHECK (review_state IN ('unreviewed','user_confirmed','corrected')),
  FOREIGN KEY (capture_id, revision)
    REFERENCES capture_revisions(capture_id, revision) ON DELETE CASCADE,
  UNIQUE (capture_id, revision, local_id)
);
CREATE TABLE evidence (
  id TEXT PRIMARY KEY,
  capture_id TEXT NOT NULL,
  revision INTEGER NOT NULL,
  speaker TEXT NOT NULL CHECK (speaker IN ('user','assistant','tool','unknown')),
  text TEXT NOT NULL,
  fidelity TEXT NOT NULL CHECK (fidelity IN
    ('client_excerpt_unverified','host_verified','summary_only')),
  locator_json TEXT CHECK (locator_json IS NULL OR json_valid(locator_json)),
  FOREIGN KEY (capture_id, revision)
    REFERENCES capture_revisions(capture_id, revision) ON DELETE CASCADE
);
CREATE TABLE node_evidence (
  node_id TEXT NOT NULL REFERENCES memory_nodes(id) ON DELETE CASCADE,
  evidence_id TEXT NOT NULL REFERENCES evidence(id) ON DELETE CASCADE,
  PRIMARY KEY (node_id, evidence_id)
);
CREATE TABLE concepts (
  id TEXT PRIMARY KEY,
  kind TEXT NOT NULL CHECK (kind IN ('project','topic','activity','person','organization')),
  name TEXT NOT NULL,
  normalized_name TEXT NOT NULL,
  UNIQUE (kind, normalized_name)
);
CREATE TABLE concept_aliases (
  concept_id TEXT NOT NULL REFERENCES concepts(id) ON DELETE CASCADE,
  alias TEXT NOT NULL,
  normalized_alias TEXT NOT NULL,
  PRIMARY KEY (concept_id, normalized_alias)
);
-- Ambiguous aliases may refer to multiple concepts; no global alias auto-merge.
CREATE TABLE node_concepts (
  node_id TEXT NOT NULL REFERENCES memory_nodes(id) ON DELETE CASCADE,
  concept_id TEXT NOT NULL REFERENCES concepts(id) ON DELETE CASCADE,
  PRIMARY KEY (node_id, concept_id)
);
CREATE TABLE memory_edges (
  id TEXT PRIMARY KEY,
  from_id TEXT NOT NULL REFERENCES memory_nodes(id) ON DELETE CASCADE,
  to_id TEXT NOT NULL REFERENCES memory_nodes(id) ON DELETE CASCADE,
  relation TEXT NOT NULL CHECK (relation IN
    ('related_to','motivated_by','revises','led_to','contradicts')),
  status TEXT NOT NULL CHECK (status IN ('proposed','accepted','rejected')),
  basis TEXT NOT NULL CHECK (basis IN ('explicit_in_capture','user_confirmed','inferred')),
  evidence_id TEXT REFERENCES evidence(id) ON DELETE SET NULL,
  created_at TEXT NOT NULL,
  CHECK (from_id <> to_id),
  UNIQUE (from_id, to_id, relation)
);

-- Similarity suggestions are ephemeral and are NOT written as causal edges.

  created_at TEXT NOT NULL,

);
CREATE TABLE index_jobs (
  id TEXT PRIMARY KEY,
  capture_id TEXT NOT NULL,
  revision INTEGER NOT NULL,
  profile_id TEXT NOT NULL REFERENCES embedding_profiles(id),
  state TEXT NOT NULL CHECK (state IN ('pending','running','ready','failed','cancelled')),
  attempts INTEGER NOT NULL DEFAULT 0,
  lease_until TEXT,
  next_retry_at TEXT,
  last_error_code TEXT,            -- no raw private payload in logs
  FOREIGN KEY (capture_id, revision)
    REFERENCES capture_revisions(capture_id, revision) ON DELETE CASCADE,
  UNIQUE (capture_id, revision, profile_id)
);
CREATE TABLE embedding_profiles (
  id TEXT PRIMARY KEY,
  model_id TEXT NOT NULL,
  model_revision TEXT NOT NULL,
  dimensions INTEGER NOT NULL CHECK (dimensions > 0),
  preprocess_version TEXT NOT NULL,
  distance_metric TEXT NOT NULL,
  state TEXT NOT NULL CHECK (state IN ('building','active','retired'))
);
CREATE TABLE search_documents (
  rowid INTEGER PRIMARY KEY,
  capture_id TEXT NOT NULL,

Skill이 지킬 계약

명시적인 저장 요청의 범위만 정리한다. 사용자 발언·AI 제안·도구 관측을 구분한다. 모르는 시점·실행 결과·성과는 unknown/null로 둔다. 원문을 볼 수 없으면 발췌를 만들어 인용하지 않는다.

대화의 전체 기록에 접근한다고 가정하지 않는다. 기존 기억과 연결하려면 먼저 ID를 검색·조회한다. 저장 도구의 성공 영수증을 받은 경우에만 완료를 말한다. 숨겨진 모델 추론이 아니라 대화에 드러난 사용자의 고민을 보존한다.

서버가 지킬 계약

JSON Schema/Pydantic 검증, 길이·노드 수 상한, enum·시간 범위·참조 무결성, 클라이언트 권한, idempotency를 강제한다. 근거가 없는 관계는 확정하지 않는다.

구조 검증만으로 “정말 사용자가 했다”는 의미적 진실을 증명할 수 없다. 위험한 불일치를 표시하고 사용자가 정정할 수 있게 한다. 비밀값 탐지는 보조 장치일 뿐 완벽한 개인정보 필터가 아니다.

저장 트랜잭션과 의미 검색 준비 상태

검증권한·스키마·요청 ID실패 시 아무것도 저장하지 않음.
한 트랜잭션원본·근거·FTS·jobreceipt까지 함께 commit.
즉시 반환저장됨 / 인덱싱 대기모델 다운로드를 기다리지 않음.

08 / RETRIEVAL & GRAPH EXPLORER

의미 검색은 입구,
그래프는 필요한 맥락을 따라가는 길.

모든 질문을 벡터 Top-K로 해결하지 않는다. 날짜·집계·명시 ID·후속 질문은 서로 다른 출발점을 갖는다.

사용자 질문우선 경로주의할 점
“우선순위를 잘못 잡았던 경험은?”FTS + 임베딩 → 여러 seed → 원래 Capture표현이 다른 경험을 찾되 비슷하다는 이유로 실제 경험을 확정하지 않음.
“2026년 9월에 저장한 건 몇 개야?”saved_at 범위 SQL + 정확한 countTop-K 결과 수를 전체 개수로 대답하지 않음.
“그 결정은 왜 했어?”이전 답변의 node ID → motivated_by + 근거모호한 지시어는 선택한 기억·대화 상태로 해소.
“그 뒤에 실제로 적용했나?”앞선 Capture + 같은 concept + 후속 시간 + action/result연관 기록이 없으면 실행하지 않았다고 단정하지 않음.
“생각이 어떻게 바뀌었어?”시간순 Capture + 근거 있는 revises·비교두 문장이 다르다고 자동으로 관점 변화·인과를 단정하지 않음.

로컬 저장 ≠ 외부 전송 없음.

OAuth로 외부 모델을 사용하면 질문·선택된 기억·도구 결과가 해당 모델 제공자에게 전달될 수 있다. store:false는 모든 보관·처리가 없다는 보장이 아니다. 각 provider의 실제 정책은 별도로 확인하고, 제품은 전송할 범위를 최소화해야 한다. 엄격한 local-only는 외부 모델·원격 임베딩·원격 trace를 차단하며 자동 fallback을 금지한다.

채팅의 일시 상태와 영구 Capture는 별개다. conversation state에는 최근 질문의 참조 ID·필터·확인한 근거를 보관하고, 사용자 선택 없이 새로운 경험으로 저장하지 않는다. 브라우저에는 provider 토큰이 아니라 필요한 앱 session만 전달하고, 외부 자격증명은 OS 자격증명 저장소에서 관리한다.

11 / PRIVACY, SECURITY & OPERATIONS

개인 기억을 맡기는 제품이라면,
저장보다 삭제와 복구까지 설계한다.

위협·운영 상황기본 통제안남는 위험·다른 선택
악성 웹페이지가 localhost에 접근loopback bind, 허용 Host·Origin 검사, 클라이언트별 최소 권한 token, 브라우저 CSRF/session 정책 [S19]CORS는 인증이 아니다. OS의 악성 프로세스 전체를 막는 샌드박스도 아니다.
민감 노트의 외부 모델 전송local_only 태그·실행 모드에서 egress 차단, 외부 전송 전에 허용 범위 필터태그를 사용자가 놓칠 수 있다. 규칙 탐지와 첫 연결 동의를 보완하되 완전 탐지로 약속하지 않는다.
메모 속 “비밀을 보내라” 지시검색 결과는 신뢰하지 않는 데이터로 처리, read-only 도구 allowlist, provider·shell 권한 분리프롬프트 문구만으로 방어했다고 주장하지 않는다. 악성 Capture 회귀 테스트가 필요.
토큰·개인 원문이 로그에 남음OS keyring, 로깅 기본 redaction, 원격 trace·텔레메트리 기본 꺼짐디버깅 시 원문 로그 opt-in도 만료와 삭제 정책 필요.
디스크·공유 PC 위협앱 데이터 디렉터리 권한, OS 전체 디스크 암호화 권장, 백업 암호화 옵션 검토SQLite 기본 파일이 암호화된다고 설명하지 않음. 별도 DB 암호화는 확장 호환·키 복구 비용을 검토.
업데이트·스키마 변경 실패마이그레이션 전 online backup, 앱 버전 lock, 무결성 검사, 복구 경로 [S14]임의 구버전 실행은 schema mismatch로 차단. 현재 DB를 바로 덮지 않는다.
네이티브 확장·모델 공급망배포 버전·해시 고정, 신뢰된 배포물만 로드, 모델 원격 코드 실행 기본 금지OS별 휠·CPU 아키텍처 시험. 자동으로 임의 확장을 설치하지 않는다.
local_only는 모델 설정뿐 아니라 검색 결과 반환에도 적용한다.

클라이언트 연결 시 외부 모델로 전달되는 경로인지 등록한다. local_only 기억은 외부/미확인 MCP 클라이언트의 검색·상세 응답에서도 제외한다. 웹의 로컬 에이전트에만 허용하는 등 동일한 정책을 모든 진입점에 적용해야 한다. 다만 이미 클라우드 AI에 말한 내용을 나중에 local_only로 저장해도 과거 전송을 되돌리지는 못한다. OS에서 파일을 직접 읽을 권한이 있는 악성 프로그램까지 이 앱의 토큰만으로 막을 수는 없다.

삭제는 네 단계의 상태 전이

즉시검색·UI에서 숨김tombstone과 권한 필터를 적용.
원본관련 revision 제거근거·관계·첨부·receipt 본문 검사.
파생물인덱스·채팅 캐시 정리재시도 job도 취소. 낡은 publish 금지.
백업잔존 범위 안내보존기간·암호화·폐기 정책 적용.

“삭제한 기억은 즉시 답변 근거로 사용하지 않는다”와 “저장장치에서 모든 바이트가 물리적으로 복구 불가능하다”는 다른 보장이다. SQLite·WAL·파일시스템·SSD·과거 백업까지 고려하지 않은 완전 소거 약속은 하지 않는다. 백업 복구 시에는 삭제 기록을 적용하거나, 과거 백업이 삭제 전 데이터를 되살릴 수 있음을 확인받는 절차를 둔다.

백업·내보내기·이식성

운영 백업은 SQLite online backup 또는 안전한 일관 스냅샷으로 만든다. WAL 사용 중 살아 있는 .db 파일만 복사하는 방식에 의존하지 않는다. JSON 내보내기는 ID·시간·관계·근거·revision을 보존하는 이식용 포맷으로, Markdown은 사람이 읽는 표현으로 제공한다. 둘 모두 provider 자격증명과 로컬 session token을 포함하지 않는다. [S12][S14]

모델 변경과 재인덱싱

새 모델은 별도 profile로 shadow index를 만든다. 도메인 기억은 수정하지 않는다. 생성 중 변경·삭제된 Capture를 재검사하고 준비가 끝난 뒤 활성 profile을 바꾼다. 데이터가 작다면 재시작 가능한 전체 재인덱싱이 복잡한 이중 쓰기보다 낫다.

설치 진단 명령의 역할

SQLite·FTS·벡터 확장 로드, 모델 파일·쓰기 권한·키링·포트·등록 클라이언트를 검사한다. Windows/macOS/Linux와 WSL을 실제 검증 조합으로 지정한다. WSL과 Windows 간 localhost·callback·파일 권한을 같다고 가정하지 않는다.

GATE 1 · 수직 기능 한 줄

MCP 저장 → SQLite → 웹 상세

동일 서비스로 생성·조회하고 Capture·근거·영수증·수정 revision을 완성한다. 이 단계에서는 FTS와 주제 조회만으로도 동작해야 한다. CLI로 시작하고 브라우저를 열 수 있어야 한다.

GATE 2 · 회상 경험

로컬 임베딩 + 웹 질문 + 출처

durable indexing, hybrid 기준선, 제한된 에이전트, 스트리밍·취소·근거 패널을 완성한다. “그 결정 이후?”와 날짜 미상 질문이 통과해야 한다.

GATE 3 · 연결 탐색

주변 그래프 + 타임라인 + 정정

Cytoscape 로컬 그래프를 검색 결과와 연결하고, 확정 관계와 후보를 구분한다. 그래프를 쓰지 않는 목록 대체 뷰도 제공한다. 실제 도움을 ablation과 사용자 과제로 확인한다.

GATE 4 · 공개 가능성

v0.1: 안전한 설치·삭제·복구

목표 OS별 설치, MCP 호스트 계약, 백업 복구, 데이터 내보내기, 보안 테스트, 라이선스 목록을 통과한 뒤 공개한다. 첫 공개 범위에 웹 채팅·그래프·타임라인을 포함한다.

라이선스 기본 제안: Apache-2.0

여러 AI 도구·상용 제품에서도 통합하기 쉬운 방향을 우선한다. Apache-2.0은 특허 및 재배포 고지 관련 명시 조항을 갖는다. MIT의 단순성과 AGPL의 수정·서비스 공개 의무를 중시하는 방향도 D31에서 비교한다. [S37]

이것은 법률 자문이 아니다. 실제로 복사·포크할 코드, 결합 방식, 배포 형태와 해당 버전 라이선스를 기준으로 검토해야 한다.

개념 참고와 코드 재사용을 구분

Basic Memory의 워크플로를 참고해 별도의 스키마를 만드는 것과 코드를 포크하는 것은 다르다. 포크한다면 AGPL 조건을 검토해야 하며 원하는 라이선스를 임의로 선언할 수 없다. [S01]

dependencies만이 아니라 임베딩 모델 가중치, 예제 데이터, 문서 이미지, 아이콘까지 배포 목록을 관리한다. 프로젝트 라이선스가 모든 의존성을 덮어주지 않는다.

오픈소스로 제공할 최소 약속

버전이 붙은 데이터 스키마·마이그레이션 문서, 공개 평가 방법, 호스트별 호환성 표, 보안 보고 경로, 작은 기여 가이드, 로컬 데이터 삭제·내보내기 설명을 제공한다. 기본 텔레메트리를 끄고, 진단 자료 공유는 개인 원문이 없는 형태로 사용자가 선택한다.

유료 서비스나 동기화를 먼저 설계하지 않는다. 먼저 개인 기록이 실제 회상에 쓰이는지 확인한다. 향후 수익 모델을 붙이더라도 로컬 데이터 읽기·백업·내보내기를 유료 장벽이나 서비스 존속에 종속시키지 않는 방향이 제품 정체성과 맞는다.

최종 제안

Evidence-aware Personal Recall — “내가 정말 무엇을 고민하고 결정하고 했는지, 근거를 따라 되찾는 경험”을 중심으로 만든다. MCP·벡터·그래프는 이를 위한 구성 요소다. 첫 구현에서는 기술적 새로움보다 허위 경험 방지, 정정 가능성, 후속 질문의 정확성, 쉬운 설치를 우선한다.
