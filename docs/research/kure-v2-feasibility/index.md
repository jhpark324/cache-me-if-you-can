## 범위와 방법

사용자가 KURE-v2 + MultiVectorEncoder + LanceDB 조합의 적합성 판단을 요청했다. 제품 기능을 구현하기 전의 독립 기술 실험이며, 실제 앱의 CRUD·인증·LangGraph 구현 완료를 뜻하지 않는다. 아래 기준을 결과 확인 전에 정하고 실험 자료와 실행 결과를 함께 보관한다.

- 합성 기록 36개와 정답이 있는 질문 24개를 학습·일상/감정·메모에 균등 배분한다. 정답 없는 질문은 별도로 관찰하며 정답 검색 지표의 분모에 넣지 않는다. 실제 사용자 기록은 사용하지 않는다.
- 입력 자료와 정답을 모델 실행 전에 고정한다. 결과를 본 뒤 질문·정답을 바꿔 점수를 높이지 않는다.
- KURE-v2의 모델 revision, Python·패키지 버전, CPU·OS·메모리·스레드를 기록한다. CPU float32·질문 batch 1·제한된 문서 batch로 시작한다.
- 단일 문서 벡터로 평균 내지 않고 토큰 행렬을 사용한다. 공식 모델 마스킹·질문 확장·정규화 규약을 유지한다.
- NumPy MaxSim과 LanceDB 정확 검색을 비교한 뒤 다중 벡터·FTS·RRF 검색의 정답 검색 지표를 각각 기록한다.
- 별도의 합성 문서로 규모를 늘려 정확 검색과 ANN의 재현율·지연·색인 크기를 비교한다. 복제 벡터만 늘린 실험을 실제 문서 규모의 품질 평가라고 표현하지 않는다.
- SQLite 상태를 모사하는 작은 기준 테이블로 정정·휴지통·늦은 작업·프로필 변경의 후처리를 시험한다. 이것은 앱의 정합성 구현 검증과 구분한다.

## 사전 판단 기준

아래 수치는 이번 탐색 실험을 위한 엔지니어링 기준이며 사용자에게 약속한 제품 SLA가 아니다. 기준을 만족해도 실제 데이터와 다른 OS에서의 검증이 남는다.

| ID | 항목 | 판단 기준 |
| --- | --- | --- |
| F-01 | 설치와 CPU 출력 | 격리된 Python 환경에서 실제 CPU 인코딩, 가변 길이×128차원·유한값·마스킹과 길이 확인 |
| F-02 | MaxSim 연결 | 기준 점수와 DB 거리 변환이 설명 가능하고 정확 검색 순위가 일치; 동점은 동등 집합으로 평가 |
| F-03 | 한국어 대표 질의 | 다중 벡터 또는 hybrid Recall@5 ≥ 0.85를 초기 검토 기준으로 사용; 유형별 결과와 실패도 공개 |
| F-04 | 대화 검색 지연 | 현재 PC에서 워밍업 후 질문 인코딩+검색 p95 ≤ 2초를 탐색 기준으로 사용; 단계별 지연 분리 |
| F-05 | 메모리 | 해당 프로세스 peak RSS ≤ 4GiB를 탐색 기준으로 사용; 실제 사용량·가중치·색인 크기 구분 |
| F-06 | ANN | 동일 규모 데이터의 정확 검색 대비 평균 Recall@5 ≥ 0.90, 실제 ANN 실행 계획 확인; 훈련 불가·기능 미지원도 기록 |
| F-07 | 변경·삭제 경계 | 낡은 버전·휴지통·프로필·색인 세대가 최종 반환에 포함되지 않음; 준비 중 상태를 성공 검색으로 위장하지 않음 |

## 보존할 결과

환경·모델 정보, 고정 평가 자료, 실행 스크립트, 정확도·시간·메모리·파일 크기, 실패 항목과 로그를 보존한다. 모델 가중치·가상환경·DB는 저장소 밖의 작업 캐시에 둔다. API key나 OAuth 인증은 이 실험에 필요하지 않다.

현재 실행 환경은 WSL Linux x86_64이다. 이 실험만으로 Windows native·macOS·Linux ARM64 지원이나 대규모 실사용 품질이 검증됐다고 결론 내리지 않는다.
