# 홈 그래프 복원과 프로젝트 이름 변경

- 상태: 구현·로컬 검증 완료
- 기준: 2026-11-02 사용자 요청 “차이나는 부분들 개선”, 프로젝트 이름 **Cache Me If You Can**
- 관련: [003 화면 기준](../003-knowledge-space-design/spec.md), [MVP](../../project/mvp-scope.md), [004 명세](spec.md)

## 해결할 차이

003 시안은 홈 그래프 위에 검색·단일 답변을 놓고 오른쪽에서 출처를 연다. 기존 실제 웹은 최근 기록 목록을 홈으로 두고 그래프를 기록 상세 안의 버튼 뒤에 배치했다. 이 축소는 사용자가 그래프 제외를 확정한 결정이 아니므로 실제 웹과 문서를 함께 바로잡는다.

## 수용 기준

- HG-001: 지식 그래프가 홈의 주 작업 공간이다. 검색창의 위치를 유지하고 바로 아래에 단일 답변이 나타나며 검색·출처 열기/닫기가 그래프를 제거하지 않는다. 기록 목록과 작성·수정·병합·관계 편집·확인 후 삭제는 계속 사용할 수 있다.
- HG-002: 홈은 실제 현재 기록·주제·Node·명시적 관계를 최대 50노드/100간선으로 조회한다. 무제한 전체 데이터 로드나 의미 유사도에서 추측한 관계 생성은 하지 않는다. 잘린 결과는 표시하고 기존 선택 기록 주변 탐색으로 이어진다. 임베딩이 준비되지 않아도 정본 기반 연결을 표시한다.
- HG-003: 삭제·오래된 revision·조회 불가 출처가 그래프에 남지 않도록 서버에서 재검증한다. 저장·수정·주제/관계 변경·삭제 후 갱신하고 오래된 요청이 최신 필터/화면을 덮지 않는다.
- HG-004: 기록이 없는 경우에도 그래프 영역과 첫 기록 작성 동선을 보여준다. 사용자의 저장소에 목데이터를 넣지 않는다. 선택적인 예시는 표시를 명확히 구분한 프런트 읽기 전용 모드로만 제공하며 실제 기록·검색 근거로 취급하지 않는다.
- HG-005: 검정 배경·어두운 유리 패널·SUIT·흰 본문·주황 강조·검색 오로라를 유지한다. 패널은 그래프 위에서 읽히며 모바일에서는 목록/검색/출처가 겹쳐 조작을 막지 않는다. 축소 모션과 키보드로 그래프와 동등한 기록 탐색을 제공하고 WebGL 실패를 빈 화면으로 방치하지 않는다.
- HG-006: 화면·탭 제목·새 OAuth 표시 이름·API/MCP 서비스 이름·현재 프로젝트 안내를 `Cache Me If You Can`으로 일치시킨다. 기존 DB 경로·Python 모듈·MCP 연결 키·환경 변수·OAuth 등록/자격 증명은 유지해 기존 기록과 로그인을 이어 쓴다. 역사 자료·기존 검증 결과를 새 이름으로 소급 조작하지 않는다.
- HG-007: 빈 상태, 실제 저장된 기록/관계, 검색 답변+출처 동시 표시, 빠른 전환/삭제, 작은 화면과 축소 모션을 검사한다. 화면 캡처를 직접 검토하고 실제 Canvas/WebGL 성공과 데이터/목록 성공을 구분한다.

## API·실행 계약

- `GET /api/v1/graph?kinds=knowledge&kinds=reflection&concept_ids=<UUID>`: 각 그룹 안에서는 OR, 유형과 주제 그룹 사이는 AND. 현재 Node에만 연결된 주제도 해당 기록의 필터에 포함한다. 본인 조회에는 public/private 모두 포함한다.
- 기존 성공 envelope 안에 `nodes[]`, `edges[]`, `truncated`를 반환한다. ID는 실제 도메인 UUID이며 Capture 노드의 `kinds[]`는 색상·유형 표시용이다. 그래프 라벨은 최대 60 Unicode code point이고 상세 원문은 그대로 보존한다.
- 최근 `updated_at DESC, id DESC` 기준 기록 후보 50개와 잘림 판단용 1개를 읽는다. 주제·Node·관계의 확장 후보도 각각 제한한다. 삭제·현재 revision·출처 상태는 동일 SQLite 읽기 스냅샷에서 검사한다.
- 출처 검증은 요청당 방문/연결 예산 512, 최대 깊이 32와 메모이제이션을 사용한다. 검증 예산을 넘는 항목은 표시하지 않고 `truncated=true`를 반환한다. 기존 주변 탐색에도 같은 검증 제한을 적용한다.
- 홈 결과는 최대 50노드/100간선이다. 전체 개수/커서는 제공하지 않으며 필터·검색·선택 기록 주변 탐색으로 이어진다. 임베딩 모델 호출과 신규 관계 추론은 없다.
- 새 API의 제품 표시는 `Cache Me If You Can`이다. Python·패키지·MCP 연결 키·스킬 호출명·환경 변수·저장 경로는 유지한다. 기존 OAuth 등록을 다시 만들지 않으므로 공급자에 이미 등록된 앱 이름은 이전 값일 수 있다. 다음 신규 등록은 새 제품 이름을 사용한다.

## 검증 기록

2026-11-02, WSL의 Python 3.12·Node 22·Chromium에서 확인했다. 사용자 저장소에는 테스트 기록을 넣지 않았다.

- 백엔드 전체 회귀: 고정 KURE-v2 snapshot으로 **161 passed, 34.36초**. 홈 그래프 13개는 필터, 현재 revision, 삭제·출처 무효화, 상한, 공유 출처 DAG·깊이/방문 예산, 긴 표시 이름과 원문 보존을 포함한다.
- 최종 웹 빌드 성공. UI 계약 회귀 **26 passed, 51.7초**; 실제 서버가 필요한 3개는 이 실행에서 제외하고 격리된 `8012`에서 따로 **3 passed, 23.7초**를 확인했다. 실제 홈 그래프/출처/삭제 갱신, 기존 CRUD·주제 정정·출처 재검토·병합·관계·실패 작업 재시도를 포함한다. 선택 기록을 빠르게 바꿀 때 늦은 주변 그래프 응답을 버리는 회귀도 통과했다.
- 독립 검토에서 발견한 공유 출처의 반복 재검증과 무제한 표시 이름을 수정했다. 기존 주변 탐색도 같은 검증 예산·라벨 제한을 적용했다.
- 격리된 `8012` 실제 API로 만든 8개 기록·3개 주제·13개 간선이 WebGL Canvas에 표시됨을 캡처로 검토했다. Canvas 노드를 실제 마우스로 선택해 정확한 출처를 열었고 WebGL context loss 후 연결 목록에서 같은 출처를 열었다.
- 검색 입력의 세로 위치·Canvas 객체 유지, 답변과 오른쪽 출처 패널의 비중첩, 모바일 가로 넘침 없음, 브라우저 JavaScript 오류 0개를 확인했다. 답변 레이아웃 검사는 SSE 계약 fixture이며 출처는 실제 API로 조회했다. 이번 UI 검사를 새 실모델 응답 검증으로 주장하지 않는다.
- 1440×1000 데스크톱, 1024×768 태블릿, 390×844 모바일과 `prefers-reduced-motion`을 확인했다. 최초 검사에서 발견한 너무 작은 3D 라벨과 축소 모션의 빈 Canvas는 화면 크기를 유지하는 라벨 및 렌더 이후 카메라 맞춤으로 수정했다.
- 실제 `8000` 서버 재시작 후 HTTP 200, 로그인·선택 모델 보존, 임베딩 준비 완료를 확인했다. Windows 측 localhost 조회도 200이었다. 사용자 기록 0개 상태에서 예시 모드의 Canvas 표시와 API 쓰기 요청 0개를 확인했다.
- Codex 스킬 표시 이름도 갱신했으며 기존 MCP 설정 파일과 연결 키는 유지했다. 실계정 로그아웃/재로그인 검증은 기존 사용자 선택대로 보류했다.

### 범위와 한계

- 홈은 제한된 최신 연결 개요다. 예산 때문에 빠진 데이터가 있을 수 있으며 전체 저장소 시각화·전체 개수는 아니다.
- 후보와 출처 검증량은 제한하지만 최근 기록 SQL 정렬에는 현재 임시 B-tree가 사용되어 데이터 규모에 따른 정렬 비용은 남는다. 대규모 부하 성능이나 모든 OS 네이티브 실행을 이번 검증으로 보장하지 않는다.
- 겹치는 그래프 라벨은 일부 숨기며 연결 목록·출처 패널로 내용을 확인한다. 그래프 표시 이름은 60자로 제한하지만 정본은 자르지 않는다.
- 그래프/Three.js 지연 로딩 청크는 약 1.42 MB로 추가 최적화 여지가 있다.
