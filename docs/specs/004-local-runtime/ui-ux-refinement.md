- 상태: 구현·로컬 검증 완료
- 기준: 2026-11-02 사용자 요청 “ui,ux 개선할 부분들 점검해서 개선”
- 유지: 검정 배경·유리 표면·흰 본문·주황 강조·SUIT·검색 아래 단일 답변·오른쪽 출처·실제 홈 그래프
- 관련: [기능 명세](spec.md), [홈 그래프 기준](home-graph-refresh.md)

## 확인한 문제

1. 작성 중 Escape/창 밖 클릭으로 편집기를 닫으면 입력이 사라진다. 저장 중 닫기도 가능하다.
2. 모바일 메뉴가 열려도 키보드 포커스가 배경에 남으며 가려진 배경 버튼으로 이동한다.
3. 목록에서 기록을 열면 메뉴가 닫히면서 포커스가 사라진다. 상세 조회 오류는 닫힌 메뉴에만 표시된다.
4. 태블릿에서 출처 패널을 열면 축소 사이드바가 기록 목록과 필터를 숨기지만 이를 다시 여는 동선이 없다.
5. 그래프에는 hover만 있고 선택을 유지하는 표시가 없다. 많은 연결 중 원하는 제목을 찾기 어렵고 목록 닫기·키보드 복귀가 불완전하다.
6. 그래프 라벨 폭 캐시가 반응형 폰트·폭 변화에 맞춰 초기화되지 않아 위치와 겹침 계산에 이전 화면 크기를 사용한다.
7. 루트 Theme용 최소 높이가 Tooltip의 Theme에도 적용되어 도움말이 화면 높이만큼 늘어나 내용을 가린다.

1~3은 390×844 브라우저와 합성 API로 재현했다. 4는 출처 패널의 반응형 CSS와 기존 화면 캡처로 확인했다. 5~6은 실제 50노드 Canvas와 화면 크기 변경으로 재현했고 7은 태블릿에서 메뉴를 닫은 뒤 캡처에서 발견했다.

## 수용 기준

- UX-001: 새 기록·수정·답변 저장의 미저장 변경이 있을 때만 닫기 확인을 제공한다. 계속 작성/확인 취소는 입력을 보존하고, 버리기를 명시적으로 선택하면 닫힌다. 저장 중에는 닫기·중복 저장을 막고 오류 시 입력과 재시도 멱등성을 유지한다. 초안을 자동 영구 저장하지 않는다.
- UX-002: 좁은 화면의 메뉴는 키보드/터치로 열고 닫을 수 있다. 메뉴를 열면 포커스가 내부로 이동하고 배경 조작을 막으며 Escape로 닫으면 열기 버튼으로 돌아간다. 태블릿에서도 목록·필터·설정에 접근할 수 있다.
- UX-003: 기록 선택 후 상세 제목으로 이동한다. 상세 조회 실패는 본문에서 읽을 수 있고 현재 기록 재시도·홈 복귀가 가능하다. 이전 요청이 새 선택을 덮지 않는다.
- UX-004: 그래프에서 현재 선택은 포인터를 옮겨도 구분된다. 연결 목록은 제목 검색, 빈 결과, 키보드 선택과 Escape 닫기/초점 복귀를 제공한다. 선택은 색상과 텍스트/접근성 상태로 표현한다.
- UX-005: 화면 크기 변경 후 라벨 중심·겹침 계산을 새 크기로 갱신한다. 모바일·태블릿·가로 화면에서 주요 조작이 잘리지 않는다. 입력·아이콘 버튼은 충분한 클릭 영역과 명확한 포커스/disabled 상태를 갖는다.
- UX-006: 검색·그래프·목록에 적용된 조건과 해제 방법이 드러난다. 불필요한 안내 문구는 줄이되 예시·실데이터, 처리 중·실패 상태 구분은 유지한다.
- UX-007: 실제 UI 조작 회귀, 기존 웹 계약, 실제 API 흐름을 검사하고 별도의 시각 검토를 기록한다. 사용자 저장소·로그인·모델 설정은 유지한다. 테스트용 데이터는 격리된 저장소/fixture만 사용한다.
- UX-008: 사용자 후속 요청에 따라 서비스 이름 옆 장식 로고를 제거한다. `Cache Me If You Can`을 읽기 쉬운 굵은 텍스트로 표시하고 두 번째 줄도 설명 문구처럼 흐리지 않는다. 데스크톱·모바일·메뉴에서 같은 이름과 색상 위계를 유지하며 홈 버튼 동작과 좁은 화면의 여유 공간을 보존한다.
- UX-009: 출처 패널에서 기록의 저장일을 확인할 수 있다. `created_at`은 ‘저장일’, 현재 기록의 `updated_at`은 ‘최근 변경’으로 구분한다. 과거 출처에는 현재 기록의 변경일 대신 `revision_created_at`을 ‘이 저장본’으로 표시한다. 브라우저 현지 시간으로 연·월·일과 시·분을 제공하며 사건 시각과 혼용하지 않는다. 같은 분으로 표시되는 중복 날짜와 누락·잘못된 날짜는 생략한다. 데스크톱 오른쪽 패널과 모바일 모달에 같은 정보를 제공한다.

전체 46개에는 위 신규 20개와 기존 26개가 포함된다. 백엔드·데이터 계약을 변경하지 않았으며 이번 결과를 새 실모델 응답이나 모든 OS 네이티브 검증으로 주장하지 않는다. 실제 API 검사는 별도 `8012` 저장소에서 수행했고 사용자 `8000`에는 기록을 저장하거나 삭제하지 않았다. 계정 로그아웃도 수행하지 않았다.

### 실제 개선 동작

- `RecordEditor`가 초안과 Dialog를 함께 관리한다. 새 답변으로 채운 본문도 미저장 상태로 보호하며, Ctrl/Cmd+Enter로 저장한다. 취소/버리기는 원래 버튼으로, 저장 성공은 저장된 내용의 제목으로 초점을 보낸다.
- 1200px 이하에서는 Radix Dialog로 메뉴를 연다. 모바일·태블릿에서 최근 기록과 필터를 함께 사용할 수 있고 메뉴 뒤의 조작은 차단한다. 본문에서 상세 오류를 읽고 다시 조회할 수 있다. 출처 조회에도 재시도를 제공한다.
- 선택 노드·관계·목록 항목을 강조하고 연결 목록에 한글 제목/주제 찾기를 제공한다. 화면 크기를 바꾼 50노드 사례에서 표시 라벨은 수정 전 1개로 줄고 위치가 멈췄으나 수정 후 15개로 갱신되어 모바일 새 로드 결과와 일치했다. 겹치는 라벨은 계속 생략하고 전체 항목은 목록에서 읽는다.
- 적용 중인 필터를 검색창 아래에 표시하고 바로 해제할 수 있다. 조건 변경 시 이전 답변을 접어 다른 조건의 답변으로 오해하지 않게 한다. 불필요한 영문 안내를 제거하고 검색 단축키, 비활성 상태, 한국어 제목 줄바꿈을 다듬었다.
- Theme의 화면 최소 높이를 앱 루트에만 적용해 거대한 Tooltip을 해결했다. 짧은 가로 화면에서는 빈 상태의 장식을 줄여 시작 버튼·예시 버튼을 모두 표시하고, 본문 건너뛰기 링크도 좁은 화면 안에 둔다.

### 후속: 서비스 이름 강조

서비스 이름 옆 로고와 장식 마침표를 제거했다. 기존 로컬 SUIT를 사용하되 데스크톱/메뉴는 `Cache Me` 30px·800 굵기·흰색, `If You Can` 26px·720 굵기·주황색으로 표시한다. 상단의 작은 화면 표시는 20/16px로 맞춰 이름의 두 줄을 모두 읽을 수 있게 했다. 스킬 검색에서는 이 화면에 맞는 서체 조합을 확인하지 못해 추천을 그대로 채택하지 않았으며, 기존 서체의 굵기·명암 조정과 실제 캡처 검토를 기준으로 삼았다.

아이콘 제거 뒤 1181~1200px의 기존 축소 사이드바에서 이름 전체가 숨겨지는 경계도 확인해 메뉴 전환을 1200px로 맞췄다. 빌드 성공 후 실제 웹의 1440·1200·390·320px 화면에서 브랜드 아이콘 0개, 제목 크기, 가로 넘침 없음, 좁은 메뉴의 닫기 버튼과 비중첩, 홈 버튼 동작, JavaScript 오류 0개를 확인했다. 표시 변경 범위로 한정했으며 기존 전체 회귀 결과를 이번에 다시 실행한 것처럼 기록하지 않는다.

### 후속: 출처 패널 날짜 (2026-11-03)

제목 아래에 `RecordDates`로 저장일과 최근 변경을 표시했다. 자동 주제 연결 등 기록 정보 변경도 `updated_at`에 포함되므로 ‘본문 수정일’이라고 표시하지 않는다. 과거 출처에서는 `revision_created_at`을 ‘이 저장본’으로 표시하며 현재 기록의 변경일로 대체하지 않는다. 사건 날짜를 저장일로 추정하지 않는다.

브라우저 현지 시간의 연·월·일·24시간제 시·분을 `<time dateTime>`으로 제공한다. 분 단위 표시가 같으면 중복 행을 생략하고, 누락·잘못된 값도 임의 날짜로 채우지 않는다. 기존 흰 글씨와 보조 명암을 사용하고 좁은 화면에서는 날짜 행이 줄바꿈될 수 있게 했다. 오른쪽 패널과 모바일 출처 모달이 같은 컴포넌트를 사용한다.

TypeScript·Vite 빌드와 기존 출처/웹 계약 **20개(29.0초)**가 통과했다. 실제 `8000`에서 테스트 기록의 저장 시각 일치와 1440px 화면을 확인했다. 합성 출처 응답으로 과거 저장본 날짜, 서울 시간 자정 변환, 같은 분 중복 제거, 과거 시각 누락 시 현재 시각 대체 금지, 잘못된 날짜 생략을 검증했다. 320px 모바일에서도 날짜 가로 넘침과 JavaScript 오류가 없었다. 기록 revision/state가 유지됐으며 데이터 변경·실모델 호출은 없었다. 백엔드는 변경하지 않았다.
