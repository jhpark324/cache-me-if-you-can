# 하나의 답변과 작은 출처

상태: 구현·자동 검증·실계정 화면 확인 완료. 2026-11-02 사용자 요청으로 별도 ‘관련 기록’ 검색을 없애고 읽기 중심의 답변으로 변경한다.

## 수용 기준

1. 웹 검색 제출은 `/questions`만 호출한다. 병렬 `/search`, 그 결과 상태·목록·대기는 제거한다. `/search` API 자체는 MCP 및 명시적 검색 기능을 위해 유지한다.
2. 답변은 하나의 글 영역에서 자연스럽게 이어지는 설명으로 표시한다. 내부 `parts`는 근거 검증·인용 연결을 위한 문단 단위로 유지하며 반복되는 ‘저장한 지식에서’·‘AI 보충 설명’ 제목이나 문단별 카드·구분선은 표시하지 않는다.
3. 생성 모델은 결론부터 설명하고 근거를 문장으로 엮는다. 근거마다 요약 조각을 나열하거나 동일한 서론을 반복하지 않는다. 기본은 산문이며 절차·비교처럼 유용한 경우만 목록을 사용한다. 일반 설명과 사용자 기록의 구분은 문장의 표현으로 드러내며, 검토자는 일반 사실을 사용자 경험으로 오인하게 하는 부분을 제외한다.
4. 검증된 출처는 관련 문단 끝에 작은 숫자 버튼으로 표시한다. 같은 SourceRef는 같은 번호를 사용하고 JSON 키 순서에 의존하지 않는다. 모델이 생성한 임의 출처 번호를 링크로 신뢰하지 않는다.
5. 출처 클릭은 정확한 SourceRef로 기존 오른쪽 패널을 연다. 번호는 작아도 키보드 조작·명확한 접근성 이름·포커스 표시를 제공하고 터치 영역을 확보한다. 좁은 화면에서도 본문과 출처가 잘리거나 가로로 넘치지 않는다.
6. 로딩·오류·취소·이전 요청 무효화·근거 없는 답변의 흐름을 유지한다. 원문 개인정보 마스킹·근거 검증을 마친 결과만 보여주며, 이번 작업에서 토큰 스트리밍을 추가하지 않는다. 검색 한계는 간결한 안내와 펼쳐볼 수 있는 상세로 제공한다.
7. ‘답변을 기록으로 저장’ 초안도 화면의 자연스러운 문단 순서를 유지하고 반복되는 유형별 제목을 붙이지 않는다. 기존 provenance 구분은 필요하면 하나의 주석으로 요약하고 SourceRef 연결은 보존한다. 자동 저장은 하지 않는다.
8. 검색 제출 직후 답변 영역에 검색 전용 회전 표시·본문 자리 표시·경과 시간을 보여준다. 단계 문구는 실제 서버 상태를 따르며 가짜 진행률을 만들지 않는다. 그래프 모션 일시정지는 기능적인 회전 표시를 멈추지 않지만 OS 축소 모션에서는 애니메이션을 없애고 상태 문구·경과 시간을 유지한다. 완료·오류·닫기·취소·새 요청에 따라 대기 표시와 타이머를 정리한다. 단계 안내는 `aria-busy` 영역 밖의 단일 live status로 전달하고 매초 경과 시간을 반복 낭독하지 않는다.

## 설계·작업

- [x] 웹 검색의 중복 요청·관련 기록 상태 제거
- [x] 하나의 본문·작은 문단 출처·간결한 한계 표시
- [x] 생성·근거 검토의 서술 지침 갱신
- [x] 회귀·네트워크·출처 패널·반응형 화면 확인
- [x] 실행 서버와 문서 반영

API의 `AnswerResult.parts`와 `sources`는 유지한다. ‘하나의 답변’은 읽는 경험을 뜻하며, 긴 답변을 억지로 한 문단으로 합치거나 출처 검증 단위를 없애지 않는다. 기존 검정 배경·흰색 본문·주황색 강조와 유리 질감은 유지한다.

## 검증

- 프로덕션 웹 빌드 통과. 기존 그래프 번들 크기 경고는 이번 변경과 별도다.
- 웹 전체 회귀 **64개 통과**, 기존 쓰기/삭제 API 통합 3개는 격리 서버를 지정하는 검사여서 이번 실행에서 제외했다. 새 답변 경로는 아래 실서버 읽기 검사로 확인했다.
- 관련 백엔드 회귀 **35개 통과**. 8회 도구 제한·PII·필터·출처 검증·취소 계약을 유지한다.
- 새로운 UI 회귀 7개 및 기존 모바일 포커스·초안 보존 검사를 포함한 집중 검사 9개 통과. 실제 전체 회귀에 중복 포함되므로 테스트 수를 합산하지 않는다.
- 실제 로그인 모델로 웹에서 질문해 **33.34초**, 연결된 설명 2문단·고유 출처 3개를 확인했다. 브라우저의 `/questions` 요청 **1회**, `/search` 요청 **0회**. 문단별 실제 출처 번호는 5개이며 같은 출처는 같은 번호를 쓴다.
- 실제 답변은 검증용 가상 기록의 내용을 설명하면서 실제 사용자 경험으로 오인하지 않도록 밝혔다. 검색 범위를 제한해 `insufficient` 상태였으며 일반적 답변 정확도·지연 보장은 아니다.
- 데스크톱·390px 모바일·축소 모션에서 본문·번호·오른쪽/모바일 출처 패널과 키보드 초점 복귀를 확인했다. 가로 넘침·브라우저 오류 없음. 현재 기록 12개의 revision/state와 로그인·선택 모델 유지.
- 회귀 중 Markdown의 매번 새로 생성되는 렌더 함수가 출처 버튼 DOM을 교체해 초점 복원을 방해하는 문제를 발견했다. 렌더 함수를 모듈 범위에 고정하고 문단별 출처는 Context로 전달해 해결했다.

## 검색 중 피드백 보완

2026-11-02 후속 요청으로 검색 전용 `SearchLoading`을 추가했다. 작은 공용 로딩과 달리 검색 버튼·답변 영역의 회전 표시, 은은한 본문 자리 표시, 실제 대기 경과 시간을 함께 보여준다. 서버 단계 문구는 유지한다.

기존 전역 모션 정지 규칙이 검색 회전까지 정지시키고 있었다. 그래프 모션을 일시정지해도 기능적인 검색 회전만 유지하며, OS 축소 모션에서는 회전·본문 애니메이션을 모두 멈추고 문구·시간으로 상태를 전달한다. 경과 시간은 별도 컴포넌트에서만 갱신하고 요청 변경·종료 시 타이머를 정리한다. 단계용 단일 live status는 busy 영역 밖에 두며 매초 시간을 반복 낭독하지 않는다.

- 프로덕션 빌드 통과. 답변·검색 그래프 관련 기존 13개 회귀 확인: 최초 12개 통과, Canvas 클릭 검사 1개는 패널 닫기 중 좌표를 너무 일찍 읽어 실패했다. 투영 좌표가 연속 표본에서 안정됐을 때 클릭하도록 검사만 수정한 뒤 해당 검사 3회 연속 통과했다.
- 실제 8000 서버가 제공하는 빌드를 합성 API로 지연시켜 일반 데스크톱, 그래프 일시정지 상태의 375px 모바일, OS 축소 모션 모바일을 확인했다. 일반·일시정지에서는 실제 회전 transform이 변하고, 축소 모션에서는 정지함을 확인했다. 경과 시간·재검색 초기화·늦은 응답 무시·완료/취소/오류 정리·가로 넘침 없음도 확인했다.
- 이번 검증은 모델을 호출하지 않고 사용자 저장소를 변경하지 않았다. 백엔드 실행·답변 생성 계약의 변경은 없다.
