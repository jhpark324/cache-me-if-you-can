# 검색 상단 배치와 검색 근거 그래프

상태: 구현·전체 회귀·실계정 화면 확인 완료. 2026-11-02 사용자 스크린샷의 상단 경로·재생·중복 새 기록 영역을 제거하고, 실제 에이전트 검색에서 읽은 청크를 그래프에 표시한다.

## 수용 기준

1. 데스크톱의 ‘내 공간 > 지식’, 상단 모션 버튼, 중복 ‘새 기록’ 버튼과 빈 헤더 높이를 제거한다. 검색창은 작업 영역 맨 위에 둔다. 새 기록은 기존 사이드바에서 접근하며 모바일 메뉴와 키보드 작성 동선은 유지한다. 모션 제어가 필요하면 그래프 도구 영역으로 옮긴다.
2. 별도 `/search` 요청이나 관련 기록 목록을 다시 만들지 않는다. `completed.result.retrieval`에 서버의 요청별 근거 목록에서 만든 현재 유효한 근거 구간을 반환한다. 검색 도구가 반환했지만 예산 때문에 읽지 않은 후보는 포함하지 않는다.
3. `retrieval.items`는 최대 20개로 각 `{source, label, capture_label, cited}`를 갖는다. `source`는 실제 원문 revision/Node/문자 구간이며, `label`은 짧게 정제한 표시 문자열이다. `cited`는 최종 검증된 답변의 출처에 포함되는지를 서버가 정한다. LLM이 만든 목록이나 인용 여부를 신뢰하지 않는다.
4. 여기서 ‘청크’는 에이전트가 실제 읽은 근거 구간이며 검색 맥락 확장으로 원래 임베딩 청크보다 넓을 수 있다. 같은 기록의 서로 다른 구간을 합치지 않고 SourceRef 전체로 식별한다. 이 임시 시각화는 정본 Node·Concept·Relation을 생성하지 않는다.
5. 답변 완료 후 해당 구간을 임시 그래프 노드로 표시하고 원래 기록과 연결한다. 답변에 인용된 구간은 별도 색/표시로 강조한다. 기존 홈 개요에 없는 기록도 최대 10개 앵커를 보충해 결과가 보이지 않는 일이 없도록 한다. 기본 50노드/100간선에 검색 구간 20개·기록 앵커 10개·연결 20개까지만 추가한다.
6. 노드·키보드 연결 목록에서 청크를 선택하면 정확한 SourceRef로 기존 출처 패널을 연다. 답변의 출처 번호를 선택해도 같은 청크가 강조된다. 기존 검색/출처 열기에서 그래프 Canvas를 불필요하게 재생성하지 않는다. 관련 없는 노드는 구별하되 그래프를 탐색할 수 있다.
7. 새 질문·응답 닫기·취소·실패·필터 변경·명시적 기록 변경에서 이전 검색 그래프를 제거한다. 늦은 이전 요청은 새 결과를 덮지 않는다. 확인된 근거가 없으면 청크를 만들어 표시하지 않는다. 오래된 API 응답에 retrieval 필드가 없으면 기존 홈 그래프를 유지한다.
8. 검색 후 변경·삭제·무효화된 미인용 근거는 그래프에서 제외하고 `retrieval.truncated=true`로 알린다. 최종 답변에 사용한 근거의 무효화는 기존 답변 실패/invalidated 계약을 따른다. 그래프 라벨의 이메일·카드·IP에도 기존 PII 정제를 적용하고 출처 원문 패널은 기존 정책을 유지한다.
9. 데스크톱·모바일·축소 모션·WebGL 실패를 확인한다. 검색창이 위로 이동해도 입력·메뉴·출처·그래프 도구가 겹치지 않고, 결과 그래프는 본문 뒤에서 식별 가능해야 한다.

## 응답 계약

```json
{
  "retrieval": {
    "items": [{"source": {}, "label": "읽은 구간의 짧은 문장", "capture_label": "기록 제목", "cited": true}],
    "truncated": false
  }
}
```

SourceRef는 기존 타입을 따른다. 문서의 빈 객체는 형식 예시일 뿐 유효한 출처가 아니다. 최대 60 Unicode code point 라벨을 사용하며, 원문·PII 정제·정본/파생 구분은 [검색·맥락 계약](../../architecture/retrieval-and-context.md)을 따른다. 근거 payload는 최종 전송 전에 현재 자격을 다시 확인한다.

## 구현과 검증

- `retrieval_view.py`가 서버 근거 장부에서 표시 데이터를 만들고 기존 SSE 재검증 경계에서 갱신한다. 표시용 필드는 모델이 작성하지 않으며, 내부 참조 장부는 공개 응답에서 제외한다.
- `retrievalGraph.ts`는 기존 그래프를 복사해 임시 노드·부모 연결을 합성한다. `Graph.tsx`는 Canvas 초기화와 데이터 갱신을 나눠 검색 결과가 도착해도 같은 Canvas를 사용한다.
- 답변 아래 그래프 영역을 확보하고, 연결 목록에서도 모든 구간을 키보드로 선택할 수 있다. 같은 첫 문장으로 시작하는 청크를 구별하도록 기록 제목과 구간을 함께 표시한다.
- 백엔드 전체 **243개 통과, 50.98초**. 새 집중 21개는 이 전체 수에 포함한다. 동일 기록의 여러 구간·중복 정규화·PII 정제 후 길이 제한·상한·예산으로 제외된 후보·삭제/버전/검토 상태 변경·최종 SSE 비공개 필드 제외를 검사했다. 고정 KURE-v2 CPU 검사도 포함한다.
- 독립 리뷰로 홈 개요에 없던 부모 기록 앵커 선택 시 강조가 빠지는 문제를 발견했다. SourceRef를 실제 합성 앵커 ID에 대응하도록 수정하고 회귀를 추가했다.

- 프로덕션 웹 빌드 통과. 웹 전체 **74개 통과, 기존 격리 서버 CRUD 통합 3개 제외, 2.9분**. 신규 10개는 전체 수에 포함한다. 새 질문·닫기·필터·오류·취소·무효화·늦은 응답·저장 이후 청크 정리, 실제 WebGL 노드 클릭, 같은 Canvas 유지, 키보드 대체 목록, 부모 앵커 선택, 상한·중복·정본 불변을 확인했다.
- 실제 로그인 모델로 최종 화면에서 질문해 **24.20초**, 근거 구간 **10개**, 최종 인용 **3개**를 확인했다. 브라우저 `/questions` 1회, 별도 `/search` 0회. 출처 번호와 그래프 선택은 정확한 SourceRef를 열고, 패널을 닫으면 초점이 돌아온다. 앞선 실모델 점검은 34.67초·10구간·2인용이었다. 이 수치는 개별 응답 증거이며 지연·품질 보장이 아니다.
- 1440px 데스크톱 검색창 바깥 상단 24px, 390px 모바일 메뉴·본문·출처·그래프 도구와 축소 모션을 확인했다. 가로 넘침·브라우저 오류 없음. 긴 답변은 별도 스크롤 영역으로 읽으며 그래프 공간을 유지한다. 라벨은 겹치면 일부를 숨기고 모든 항목은 연결 목록으로 접근한다.
- 실제 서버를 반영한 뒤 기존 가상 기록 12개의 revision/state, 로그인과 선택 모델, 검색 준비 상태를 유지했다. 실제 기록을 생성·수정·삭제하지 않았고 실계정 로그아웃→재로그인은 기존 보류 상태를 유지했다.
- 서비스 계약·요청 흐름 Mermaid와 SVG를 함께 갱신했다. 문서 링크와 등록 후보 검사는 `scripts/preflight.py`로 확인한다.
