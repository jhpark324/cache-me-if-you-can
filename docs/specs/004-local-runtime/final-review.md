## 추가 수용 기준

기존 004 명세의 AC-008(재현 가능한 설치·검증)을 구체화한다.

- FR-001: 설치·검사 명령은 잠금 파일을 사용하며 실행 환경에 따라 의존성을 조용히 변경하지 않는다.
- FR-002: 버전 관리 후보의 민감정보·실행 데이터·의존성 캐시·검증 부산물을 확인하는 반복 가능한 검사를 제공한다. 발견 결과에는 비밀 원문을 출력하지 않는다.
- FR-003: 실제 구현의 모듈 경계·저장 모델·검색/답변·인증·변경 흐름을 다이어그램과 코드 경로로 설명한다.
- FR-004: 재현한 오류를 수정하고 백엔드·웹·실제 검색 검증의 실행 범위와 미검증 영역을 구분한다.
- FR-005: 문서 탐색 경로·현재 상태를 정리하고 제품 제안과 구현된 기능을 구분한다.

## 결과

**정본·출처·공통 서비스의 기반은 적절하며, 실제 경계 오류를 수정했다.** 태그 축을 더 늘리기보다 주제 선택·분류·정정의 일관성을 높이는 것이 우선이다. 대형 모듈·전체 스캔·배포 경험은 후속 개선이 필요하다. 현재 검증 범위를 모든 입력·OS·클라이언트의 무오류 보증으로 해석하지 않는다.

## 유지보수와 문서

- `record_filters.py`, `concept_labels.py`, `background.py`로 공통 선택·비교·반복 실행을 분리했다.

- 구현 전 상태가 남아 있던 지식 계층·스키마·기술 스택·검색·플랫폼 문서를 갱신했다. Authlib 미사용, 제품 정확 벡터 검색과 과거 ANN 실험, wheel의 프런트 미포함을 명확히 했다.

## 리모트 등록 후보·의존성

`scripts/preflight.py`로 작업 파일과 현재 Git index를 검사한다. 이번 작업 폴더는 아직 `.git`이 없으므로 Git 이력·리모트는 존재하지 않으며 새 저장소를 생성하지 않았다. 후보 파일에서 알려진 비밀 형식·실행 데이터·깨진 Markdown 파일 링크는 발견하지 않았다. 이미지 내용·알 수 없는 모든 비밀 형식·외부 URL 응답·Markdown anchor 유효성까지 전수 검사한 것은 아니다.

`npm audit`의 알려진 취약점은 **0건**이다. `pip-audit`는 설치된 공개 패키지 **106개에서 0건**이며, 자체 프로젝트와 PyTorch `2.15.0+cpu`는 조회에서 제외되었다. PyTorch는 공개 기준 버전 `2.15.0`으로 별도 조회해 알려진 취약점 0건을 확인했다. 이는 CPU 전용 빌드 자체의 공급망·바이너리 검사와 다르다. 자체 코드는 이번 코드 검토/시험 범위로 평가했다. 자동 수정으로 lockfile 버전을 일괄 올리지 않았다.

등록 후보에는 합성 데이터·시안·문서 근거가 포함된다. `.venv`, `node_modules`, 사용자 DB·Lance·인증 JSON·환경 파일·개인 캐시·실행 로그·프런트 시험 결과는 제외한다. 일부 보관된 시안 번들과 합성 조사 로그는 문서 재현을 위해 의도적으로 남긴다. [등록 전 가이드](../../guides/repository-readiness.md)를 따른다.

## 제품과 태그 판단

**RecordKind(다시 쓸 목적) + Concept(내용의 주제) + 선택적 Node(본문 의미 구간)를 유지한다.** 주제를 고정 enum으로 만들거나 별도 문자열 태그 필드를 중복 추가하지 않는다. 힌트와 확정 연결, 분류와 진실성을 구분한다.

Obsidian·Logseq·Anytype·SiYuan·Khoj·Mem0의 공식 자료를 비교했다. 로컬·그래프·AI 검색·MCP만으로 독자적 차별성을 주장하기 어렵다. 현재 구현에서 강화할 방향은 **사람이 확인·정정한 정리본을, 현재 유효한 버전/구간 출처로 에이전트가 재사용하는 경험**이다. 경쟁 제품보다 모든 기능이 우수하다거나 해당 경험이 유일하다는 주장은 아니다.

다음 기능은 아직 도입하지 않은 제안이다: **주제 품질 관리 → 검색 근거 설명 → Markdown/JSON 교환 → 목적별 컨텍스트 묶음 → 범위별 기억 변화**. 한국어 실제 사용 평가와 설치 검증을 병행한다. [공식 비교·인용](../../research/second-brain-comparison-2026-11.md), [문제·범위·수용 기준별 제안](../../project/evolution-proposals.md)을 참고한다.

## 남은 관문

1. **공개 저장소 정책·프로젝트 라이선스 선택**: 작성자 결정을 대신하지 않았다. 코드 보관용 remote와 공개 재배포는 구분한다.
2. **원격 CI 첫 실행**: 구성과 로컬 명령은 확인했지만 원격 저장소가 없어 호스팅 결과는 없다.
3. **네이티브 OS**: Windows·macOS·Linux 직접 실행의 지원 목표 유지. Intel Mac/Windows ARM 설치 제약과 OS별 OAuth/MCP 검증은 미해결이다.
4. **실계정 로그아웃→재로그인**: 사용자 보류 유지. 이번 재시작은 로그인 보존 확인이다.
5. **규모·실사용 품질**: 전체 스캔·깊은 출처 체인·상위 100개 주제 후보·큰 그래프 청크, 실제 장기 한국어 자료를 평가해야 한다.
6. **유지보수 후속**: 출처 resolver 공개 경계, 검색/상세 상태 분리, API 타입 생성·lint gate, 프런트 포함 배포 패키징.

이번 범위의 점검은 마쳤으며, 남은 관문이 있어 004 전체 기능 상태는 `in-progress`를 유지한다. 리모트 생성·push·공개 배포는 실행하지 않았다.

## 검색 근거 그래프 후속 변경

검색창 상단 배치와 실제 읽은 청크·최종 인용을 구분하는 현재 구현·회귀·실계정 화면은 [검색 근거 그래프](retrieval-graph.md)를 따른다. 이 그래프는 화면에서만 합성하며 저장된 지식 구조를 변경하지 않는다.
