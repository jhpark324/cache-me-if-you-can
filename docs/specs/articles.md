# 학습 아티클

기록은 공부하며 남긴 원자료다. 아티클은 여러 근거를 엮어 복습하기 좋게 쓴 독립 문서다. 둘은 로컬 SQLite를 공유하지만 식별자에 접근하는 서비스, 저장 테이블, 버전, 조회 경로를 구분한다. 웹에서 아티클 본문을 여는 곳은 **아티클** 페이지다.

| 수용 기준 | 기대 동작 |
| --- | --- |
| AC-001 | Codex는 필요한 공부 기록을 검색하고 사용한 원문 구간을 읽는다. 부족한 설명은 공식 문서·논문이나 설명용 예시로 보강한다. 아티클 요청은 전용 MCP `article_create`로 직접 등록하고 글 링크를 반환한다. 초안만 요청하면 대화에서 작성한다. |
| AC-002 | `#articles`에서 제목·한 줄 요약·주제를 훑고 `#article/<아티클 ID>`에서 본문을 읽는다. 표·단계 도식·긴 글의 접이식 목차로 내용을 살펴볼 수 있다. |
| AC-003 | 인용 번호를 열면 데스크톱은 옆 패널, 좁은 화면은 대화상자를 사용한다. 주소와 읽던 위치를 유지하며, 닫으면 선택한 번호로 초점이 돌아간다. |
| AC-004 | 기록 인용은 작성 때 읽은 버전·구간을 가리킨다. 근거의 변경·삭제 상태를 표시한다. 외부 인용은 제목·참고 요지를 먼저 보여주고 원문은 별도 탭으로 연다. |
| AC-005 | 아티클 작성·수정은 Capture·기록 색인·주제 분류 작업을 만들지 않는다. 기록 목록·타임라인·그래프·지식 검색·질문 근거와 일반 기록 상세에 아티클이 나타나지 않는다. 기록 도구로 아티클을 만들거나 수정할 수 없다. |
| AC-006 | 이전 구현으로 등록한 아티클은 업그레이드 후 같은 글 주소, 본문, 버전, 순서 있는 인용을 보존한다. 일반 기록 경로에서는 기존 글을 열 수 없다. 삭제된 글은 다시 노출하지 않는다. |
| AC-006a | 일반 기록을 수정해 아티클을 발행했던 경우에는 두 주소를 보존한다. 기존 기록 주소는 발행 직전 원자료를, 아티클 주소는 발행한 글을 연다. 원자료의 버전·구간을 인용한 기존 참조, 이후의 기록 수정과 아티클 수정은 각각 독립적으로 동작한다. |
| AC-007 | 등록 요청을 재시도해도 같은 글이 중복 생성되지 않는다. 아티클 수정은 기대 버전을 확인하고 해당 글의 새 버전과 인용을 함께 저장한다. |

## 계약

등록 입력은 `request_id, title, summary, body_markdown, citations`와 선택적 `topics`다. `citations`는 1부터 번호를 매긴 배열로, 기록은 `{kind: "record", source: SourceRef}`, 외부 원문은 `{kind: "external", title, url, note}`다. 본문 인용 링크는 `[1](#cite-1)`, 단계 도식은 한 줄당 한 단계를 쓰는 `article-flow` 코드 블록을 사용한다. 아티클 주제는 글을 찾는 표시용 정보다.

웹은 `/api/v1/articles`와 `/api/v1/articles/<id>`를 사용하고 기록 인용만 기존 출처 확인 서비스를 이용한다. MCP는 `article_create`, `article_list`, `article_get`, `article_update`를 제공한다. 저장 결과에는 커밋한 `article`과 요청 ID·재시도 여부가 있다. 웹 메뉴와 목록 제목은 ‘아티클’이다. [스킬 인덱스](../skills/index.md) · [Astryx 가이드](../guides/astryx.md)
