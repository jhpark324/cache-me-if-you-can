# cache-me 스킬 명세

`cache-me`는 사용자가 요청한 지식·경험·결정·계획을 로컬 기록으로 저장하고 조회·정정하는 Codex 스킬이다. 원본은 [SKILL.md](../skills/cache-me/SKILL.md), 표시·호출 설정은 [openai.yaml](../skills/cache-me/agents/openai.yaml)에서 관리한다.

## 동작

- `$cache-me` 또는 스킬 목록 선택으로 호출한다. 자연어 요청은 스킬 설명에 따른 모델 선택이며 고정 문자열 명령으로 보장하지 않는다.
- 저장할 내용이나 수행할 일이 없으면 필요한 정보를 묻는다. 단순한 이름 언급, 제품 개발 질문, 조회를 저장 동의로 해석하지 않는다.
- 요청한 내용을 정리해 저장하고 실제 커밋 결과를 보여준다. 원문 보존 요청, 사용자 진술과 AI 추측의 구분, 버전 충돌·정확한 출처·삭제 재확인 규칙을 따른다.
- MCP 등록 키는 `cache_me`, 서버 표시 이름은 `Cache Me If You Can`이다. 도구 연결이 없을 때 설치된 비밀 없는 실행 정보와 공식 진단 명령으로 원인을 먼저 확인한다. 사용자의 기록 작업에 필요한 준비된 로컬 서버 시작은 공식 명령으로 수행할 수 있으며, DB나 인증 파일 직접 접근으로 저장을 우회하지 않는다.
- 설치는 사용자 스킬 디렉터리에 본문과 UI metadata를 함께 반영한다. 같은 내용의 반복 설치는 파일을 불필요하게 바꾸지 않으며, 다른 설정·스킬과 사용자 수정본을 보호한다.
- 개발 버전의 설치·진단·실행은 현재 `cache_me` 이름만 사용한다. 이전 MCP 이름·관리 마커·스킬 지문을 감지하거나 자동 이전하지 않으며 다른 MCP 설정과 스킬은 그대로 보존한다. `--replace`는 현재 이름의 관리 설정·스킬 갱신에만 사용한다. Python 패키지·환경 변수·저장 경로는 [명명 규칙](../project/domain-language.md#제품-이름과-실행-식별자)을 따른다.
- 프롬프트는 현재 사용법과 실제 도구 계약을 설명한다. 개발 중 이름 변경과 임시 검증 이력은 포함하지 않는다.

## 저장 범위와 기록 단위

먼저 사용자가 저장하려는 범위를 정한 뒤 그 안에서 기록을 나눈다. `이 내용`의 지시 대상이 최근 대화 흐름으로 명확하면 해당 흐름만 저장한다. `지금까지 모두`처럼 범위를 넓힌 요청에서는 그 범위 안의 독립적인 내용을 각각 저장한다. 범위가 불명확하고 해석에 따라 저장 대상이 달라지면 짧게 확인한다.

한 기록은 나중에 독립적으로 찾아 쓰거나 수정·완료 처리할 내용이다. 같은 세션에 있다는 이유로 다른 프로젝트·문제·결정을 한 기록에 합치지 않는다. 반대로 하나의 문제에 대한 원인·해결·결과나 하나의 결정에 대한 이유·대안·적용 조건은 함께 보존한다. 주제 단어·문단·유형이 여러 개라는 이유만으로 쪼개지 않는다. `한 기록으로`, `원문 그대로` 등 사용자의 묶음·원문 보존 지시가 우선한다.

여러 기록을 저장할 때는 각 기록에 자체적으로 이해할 수 있는 제목·본문과 해당 내용의 메타데이터를 둔다. 기록별로 별도 `request_id`를 사용하여 `capture_create`를 호출한다. 같은 세션이었다는 이유로 관계를 만들거나 기존 기록을 수정·병합하지 않는다. Node는 기록 내부의 본문 구간이므로 독립 기록의 대체 수단이 아니다. 기존 기록의 자동 분할·마이그레이션과 서버의 본문 자동 분할은 이 변경에 포함하지 않는다.

여러 호출은 하나의 트랜잭션이 아니다. 일부만 성공하면 실제 성공 결과와 미완료 항목을 구분해 알린다. 성공 기록을 삭제·재생성하지 않으며, 응답 유실 등 커밋 여부가 불명확하면 해당 기록의 동일 `request_id`와 입력으로 재시도한다. 커밋되지 않았음이 확인된 입력 오류는 원인을 고친 새 요청으로 처리한다.

## 수용 기준

| ID | 기준 |
| --- | --- |
| AC-001 | name·표시 이름·기본 호출이 `cache-me`로 일치하고 스킬의 기본 형식을 검증한다. |
| AC-002 | 저장·조회·정정은 실제 도구 결과로 확인하며, 실패를 성공으로 안내하거나 저장하지 않은 요청 본문을 저장 결과처럼 보여주지 않는다. |
| AC-003 | 이름만 부른 요청과 관계없는 질문으로 기록을 변경하지 않는다. 완료만 요청하면 완료 필드만 변경한다. |
| AC-004 | 설치 충돌은 변경 전에 확인하고 사용자 수정본과 다른 MCP 설정을 보존한다. 원본·설치본과 반복 설치를 검사한다. |
| AC-005 | 실제 모델 검사는 격리된 합성 저장소에서 수행한다. 자동 계약 검사·모델 행동·사람의 삭제 확인을 구분한다. |
| AC-006 | 설치 패키지는 토큰 없는 실행기·데이터 경로·포트 및 진단·시작 명령 정보를 제공한다. 도구 미노출 시 서버 중단과 기존 대화의 도구 탐색 실패를 구분하며, 실제 저장 결과가 없으면 등록 완료를 주장하지 않는다. |
| AC-007 | MCP 등록 키·스킬 의존성·Python 모듈·호출·진단은 `cache_me`로 일치한다. 현재 이름의 반복 설치는 멱등이며, 이전 이름을 위한 호환 분기나 자동 이전을 제공하지 않는다. 사용자 기록·인증 파일을 변경하지 않는다. |
| AC-008 | 현재 이름의 외부 작성 연결과 불완전하거나 다른 설정을 포함한 관리 구간은 변경 전에 거부한다. 거부하면 설정과 설치된 스킬을 그대로 보존한다. 다른 이름의 MCP 연결·스킬은 검사·이전·삭제하지 않으며, 진단은 현재 연결의 미설치·불일치·손상을 구분한다. |
| AC-009 | 동일한 대화에서 주제가 바뀐 뒤 최근 내용을 저장하면 이전 주제를 끌어오지 않는다. 명시한 전체 범위에 독립적인 주제가 있으면 각각의 기록으로 저장한다. |
| AC-010 | 하나의 문제·결정에 속한 설명·이유·해결 과정은 함께 보존하고, 명시적인 한 기록·원문 보존 요청을 우선한다. 독립적인 수정·완료 단위가 다른 내용은 같은 주제어를 공유해도 구분한다. |
| AC-011 | 복수 저장은 기록별 제목·본문·메타데이터와 서로 다른 요청 ID를 사용한다. 일부 실패 시 건별 결과를 알리고 성공분의 삭제·재생성이나 전체 성공 주장을 하지 않는다. 응답 유실·커밋 여부 미확인은 동일 ID·입력으로 재시도하고, 커밋 전 입력 오류는 수정한 새 요청으로 처리한다. |
| AC-012 | 합성 행동 검증에 동일 thread의 주제 전환, 전체 범위의 독립 기록 분리, 관련 맥락 유지, 한 문서 원문 보존을 포함한다. 규칙·검증 코드 추가와 실제 모델에서 관찰한 결과를 구분한다. |

설치·호출은 [로컬 실행 가이드](../guides/local-development.md), 재현 가능한 검사는 [검사 가이드](../guides/testing.md)를 따른다.
