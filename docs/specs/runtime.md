# 로컬 런타임 명세

웹과 Codex가 같은 로컬 기록·검색 서비스를 사용한다. 저장한 원문과 검색 근거의 일관성을 유지하고, 외부 AI 호출과 로컬 저장의 경계를 사용자에게 설명한다.

## 구성과 범위

- FastAPI는 웹 API·정적 웹·MCP를 한 로컬 프로세스에서 제공한다. 웹과 MCP는 [기록 관리 계약](records.md)을 공유한다.
- MCP 등록 키와 Python 패키지는 `cache_me`이며 표시 이름은 `Cache Me If You Can`이다. 설치·스킬 의존성은 [cache-me 명세](cache-me.md)를 따른다. 실행 명령은 `cache-me`, 환경 변수는 `CACHE_ME_*`, 기본 데이터 디렉터리는 `CacheMe`, SQLite 파일은 `cache-me.sqlite3`다. 이전 제품 이름의 별칭·환경 변수 fallback·저장소 자동 탐색을 제공하지 않는다. 기록 스키마와 개별 MCP 도구의 의미는 바꾸지 않는다.
- 기본 포트는 앱의 설정 가능한 기본값 `52761`이며 `CACHE_ME_PORT`로 변경한다. 웹·MCP·OAuth callback·개발 프록시는 같은 설정을 사용한다. 다른 서비스가 포트를 점유해도 임의로 종료하거나 다른 포트로 이동하지 않는다. 포트 선택의 근거와 한계는 [로컬 실행 가이드](../guides/local-development.md#실행-설정)에 둔다.
- 명시적인 `start`는 지정한 Python·데이터 경로·포트로 서버를 백그라운드에서 시작하거나 일치하는 기존 서버를 재사용한다. `doctor`는 설정과 실행 상태를 읽기 전용으로 확인하며 인증 비밀이나 기록 본문을 출력하지 않는다.
- 원문·revision·주제·관계·작업 상태는 SQLite, 파생 검색 청크와 벡터는 LanceDB에 저장한다.
- 검색 모델은 KURE-v2 CPU 실행이다. 모델 준비는 명시적인 동작이며 저장 기능의 선행 조건이 아니다.
- 질문은 본문 키워드·벡터 후보와 질문에 명확히 일치하는 Concept 이름·별칭에 현재 연결된 기록 후보를 독립적으로 병렬 수집한다. 소수 주제와 주제별 후보 상한을 적용하고, 유효한 본문 근거 구간을 선별해 RRF로 결합한다. 검색 구간에 연결된 명시적 관계를 1홉 확장하며, 임의 다중 홉 탐색을 제공한다고 설명하지 않는다.
- LangGraph 에이전트가 읽기 도구로 검색·추가 조회를 수행하고, 답변의 출처를 검토한다. 질문과 답변은 자동 영구 저장하지 않는다.
- 답변 생성·자동 주제 분류는 로그인한 외부 모델을 사용한다. 검색·임베딩·원문 저장은 로컬에서 처리한다.
- 새 주제·실제 주제 정의 변경의 연결 보강은 영속 작업으로 모아 백그라운드에서 수행한다. 기존 본문 벡터·FTS 경로만 재사용하고 주제 연결 후보 경로는 사용하지 않는다. 작업당 최대 20개 고유 기록, 모델 호출당 최대 5개 기록, 재시도를 포함해 작업당 최대 4회 모델 호출로 제한한다. 사용자용 진행·제안 화면은 새로 추가하지 않는다.
- ChatGPT 연결은 현재 계정 하나만 관리한다. 다른 계정 로그인에 성공하면 연결을 교체하고 이전 계정의 로컬 인증 정보를 제거한다. 로그인 실패·취소 때는 현재 연결을 유지한다.
- 모델 목록은 연결된 계정에서 조회하며 서버 재시작 후에도 설정에서 다시 불러온다. 모델별로 공급자가 알려 준 추론 수준만 선택할 수 있고, 지원 정보가 없으면 기본 동작을 사용한다. 선택한 모델·추론 수준은 로컬에 저장하고 이후 모델 요청에 적용한다.
- 모델 스트림 도중 발생한 사용 한도·권한·요청 오류도 일반 연결 실패로 덮지 않는다. 자동 주제 연결에는 안전한 오류 코드만 보존하며, 사용 한도·인증·권한·지원하지 않는 요청처럼 사용자 조치가 필요한 실패는 자동으로 반복하지 않는다. 저장 후 분류는 원인을 해결한 뒤 기존 명시적 주제 연결 재시도로 복구한다.
- 수동 백업은 `cache-me.sqlite3` snapshot과 `manifest.json`을 `cache-me-YYYY-MM-DD.zip`으로 내보낸다. 로그인 비밀·모델·검색 색인은 제외하지만 내부 삭제 이력은 포함할 수 있다.

주제 검색의 첫 범위는 기존 Concept 이름·별칭과 현재 기록 연결의 활용이다. Concept 설명의 의미 검색, 그래프 DB 도입, 전체 기록 재분류와 화면 변경은 포함하지 않는다. 주제 후보가 있어도 검색 모델 준비와 기존 검색 오류 계약을 우회하지 않는다.

## 수용 기준

| ID | 기준 |
| --- | --- |
| AC-001 | 웹과 MCP의 생성·조회·정정·삭제가 같은 도메인 계약을 사용하고 실제 커밋 결과를 반환한다. |
| AC-002 | OAuth PKCE 로그인에서 state·nonce·서명·issuer·audience·계정을 검사한다. 인증 비밀을 브라우저·로그·백업에 노출하지 않는다. |
| AC-003 | 로그인 시작·취소·갱신·로그아웃의 늦은 응답이 이전 계정이나 작업을 되살리지 않는다. 모델은 연결된 계정의 카탈로그에서 선택한다. |
| AC-004 | 본문 전체를 보존하며 모델 입력 한도에 맞게 청크를 만든다. 색인 작업과 조회에서 현재 revision·세대·삭제·출처 상태를 확인한다. |
| AC-005 | 키워드·벡터·주제 연결 후보에 같은 필터를 적용하고 기록별 중복을 묶되 정확한 근거 구간을 유지한다. 색인 준비 실패를 기록 없음으로 처리하지 않는다. |
| AC-006 | 관계 확장은 유효한 양끝 구간과 근거를 확인하고 방향·범위를 보존한다. 대체·상충 체인의 조회 한계를 명시한다. |
| AC-007 | 한 질문의 읽기 도구는 총 8회 이내이며 병렬 호출도 각각 센다. 모델 호출·시간·입력 예산과 요청 간 격리를 적용한다. |
| AC-008 | 긴 질문의 조건·부정·대상·기간을 유지하고, 직접 검색하지 못한 부분을 조사 완료로 표시하지 않는다. |
| AC-009 | 답변의 개인 사실은 읽은 근거와 연결하고 일반 설명과 구분한다. 답변 전 원문 버전·관계를 재검증하며 변경된 근거를 그대로 인용하지 않는다. |
| AC-010 | PII 처리는 모델 입출력 사본에 적용하고 정본을 변경하지 않는다. 모든 개인정보의 완전한 익명화를 보장하지 않는다. |
| AC-011 | loopback 바인딩, Host·Origin 검사, 웹 세션·CSRF와 MCP 인증을 적용한다. 삭제 확인은 클라이언트의 실제 사용자 응답과 연결한다. |
| AC-012 | 자동 주제 분류는 저장 후 별도 작업으로 실행하고 긴 본문 누락·중복 커밋·오래된 작업의 덮어쓰기를 막는다. 분류 실패와 본문 저장 실패를 구분한다. |
| AC-013 | 백업은 일관된 snapshot이며 내보내기 범위를 설명한다. 가져오기·복원·자동 영구 삭제 기능으로 오인시키지 않는다. |
| AC-014 | 예제 데이터는 명시적인 실행에서만 추가한다. 새 설치에 합성 기록이나 실제 사용자 자료를 자동 삽입하지 않는다. |
| AC-015 | 기본 포트와 사용자 지정 포트가 웹·MCP·OAuth callback·개발 프록시에 일치하며 잘못된 포트는 실행 전에 거부한다. 기존 관리 연결의 포트 이전은 명시적인 재설치로 처리한다. |
| AC-016 | 백그라운드 시작은 준비 완료를 확인하며 동일 저장소의 동시 시작을 직렬화한다. 일치하는 서버는 재사용하고 다른 서비스·다른 저장소·이미 다른 포트에서 실행 중인 저장소는 덮어쓰지 않는다. 시작 실패·시간 초과 시 자신이 시작한 자식만 정리한다. |
| AC-017 | 진단은 서버 미실행, 포트 충돌, 저장소 불일치, 인증 준비 및 설치 설정 불일치를 구분한다. 건강 응답만으로 현재 Codex 대화의 도구 목록 갱신을 보장하지 않으며 재연결이 필요한 경우를 안내한다. |
| AC-018 | Codex 실행·검사 스크립트는 `cache_me`를 선택하고 `CACHE_ME_*` 설정만 사용한다. 이전 제품 이름을 위한 감지·이전·fallback은 제공하지 않으며 기존 설정 파일을 자동으로 수정하지 않는다. |
| AC-019 | 기존 여러 계정 정보가 있더라도 현재 계정만 유지하며, 새 계정 연결 성공 후 이전 계정의 인증 정보를 제거하고 선택 목록에 표시하지 않는다. 로그아웃 시 현재 계정의 토큰은 제거하되 재연결에 필요한 앱 등록 정보는 유지한다. 실패·취소한 계정 교체는 현재 연결을 지우지 않는다. |
| AC-020 | 설정에서 연결 계정의 모델 목록을 자동 조회하며 조회 중·실패·빈 목록·재시도를 구분한다. 모델·추론 수준 조합을 서버에서 검증하고, 지원되지 않는 조합은 저장·전송하지 않는다. 모델이나 추론 수준 변경 후 이전 설정으로 진행 중이던 답변을 반영하지 않는다. |
| AC-021 | HTTP 응답 시작 후 SDK가 발생시키는 스트리밍 오류에서도 사용 한도·권한·인증·요청 실패를 구분한다. 주제 작업은 공급자 원문·토큰 없이 오류 코드를 보존하고, 사용자 조치가 필요한 실패의 자동 재시도를 중단하되 명시적 재시도는 허용한다. |
| AC-022 | 질문에 명확히 일치하는 Concept 이름 또는 별칭이 있으면 본문 검색 순위와 독립적으로 현재 연결 기록을 후보로 수집한다. 본문에 주제명이 없어도 근거 선별을 거쳐 검색 결과에 포함될 수 있으며, 주제 일치가 없을 때도 기존 본문 검색은 유지한다. |
| AC-023 | 주제 연결 후보도 현재 revision·색인 세대·삭제·출처와 요청 필터를 검사한다. 주제 일치만으로 기록 전체를 답변 근거로 채택하지 않고 본문 구간을 선별하며, 본문 검색과 겹치는 결과는 RRF 결합 후 중복 없이 정확한 근거 위치를 유지한다. |
| AC-024 | 주제 수와 주제별 기록 수를 제한하고 기존 최종 근거·맥락 예산을 유지한다. 주제 검색을 추가해도 모델 미준비 오류와 명시적 관계 1홉 검증은 유지하며, 주제 후보만으로 모델 준비 실패를 성공한 검색처럼 반환하지 않는다. |
| AC-025 | 주제 정의 변경의 연결 보강은 최대 20개 고유 기록을 후보로 삼고, 제한된 발췌를 최대 5개 기록씩 모델에 제공한다. 재시도를 포함해 작업당 모델 호출은 4회를 넘지 않으며 불확실한 연결은 보류한다. |
| AC-026 | 보강 작업은 재시작 뒤에도 이어갈 수 있고 검색·색인 미준비를 0건 완료로 처리하지 않는다. 지연·일부 처리·호출 예산 소진을 내부 상태로 구분하며 본문 저장과 기존 주제 연결을 유지한다. |
