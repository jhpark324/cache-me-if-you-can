# Cache Me If You Can 아티클

“이 주제로 아티클 써줘”는 완성한 글을 개인 웹 서재에 등록하고 링크를 달라는 요청이다. “초안만” 또는 “먼저 보여줘”라고 하면 대화에서 초안과 출처를 보여준다. 대화용 초안에서는 순서를 번호 목록으로, 인용을 읽을 수 있는 기록 이름·짧은 발췌 또는 외부 원문 링크로 표시한다. 아래의 전용 도식·인용 문법은 서재에 등록할 때 적용한다. 아티클 기능이나 아이디어에 관한 질문은 대화에서 답한다.

## 근거 모으기

1. 글을 읽고 나면 답할 수 있을 질문을 하나 정한다. `cache_me` MCP의 `knowledge_context`로 관련 기록을 찾고, 사용할 후보의 `source`를 `source_get`에 보내 당시 기록 버전·구간을 읽는다. 사용자가 특정한 기록이 있으면 그것부터 읽는다. 기록의 제안, 실제 시도, 결과, 개인 해석을 구별한다.
2. 기록만으로 이해하기 어려운 대목은 배경 설명과 구체적인 예시로 채운다. 수치·버전별 동작·연구 결과처럼 근거가 필요한 내용은 공식 문서, 표준 또는 원 논문을 찾아 해당 부분을 직접 읽고 적용 조건을 설명한다. 외부 검색어는 개념·제품명 위주로 만들고 개인 기록의 사적인 문구나 식별자를 옮기지 않는다.
3. 관련 기록이 없더라도 주제가 분명하면 확인한 원문과 설명용 예시로 쓴다. 서로 다른 실험 조건에서 얻은 결과를 한 사람의 경험으로 합치지 않는다. 외부 원문을 읽지 못했다면 그 출처와 확인이 필요한 주장을 생략하거나 한계를 밝힌다. 지식베이스 연결 실패와 검색 결과가 비어 있는 경우를 구분한다.

## 적은 분량으로 이해시키기

제목은 독자가 알아볼 질문이나 구체적인 선택으로 쓰고, 한 줄 요약에는 그 답을 담는다. 본문은 질문이 생긴 상황 또는 바로 적용할 예시에서 시작한다. 소제목·표·도식만 훑어도 요점을 되살릴 수 있도록, 각 시각 자료 가까이에 읽어낼 결론을 한 문장으로 쓴다.

- 비교라면 같은 사례에 대한 결과나 선택 조건을 좁은 Markdown 표에 나란히 놓는다. 수치를 그리려면 단위와 확인한 값을 함께 쓴다.
- 순서나 인과를 설명할 때는 아래처럼 `article-flow` 블록에 단계당 한 줄을 쓴다. 분기가 있는 절차는 조건별 표나 소제목으로 풀어낸다.

```article-flow
질문에서 관찰할 현상을 고른다
조건 하나를 바꿔 결과를 비교한다
두 결과의 차이로 설명을 점검한다
```

- 개인 기록에 없는 사례는 “예를 들어” 또는 “설명용 예시”로 소개한다. 실제로 배운 계기나 시행착오가 기록에 있으면 해당 근거를 붙여 살린다.

## 번호 출처와 저장

1. `article.citations`에 인용 순서대로 근거를 둔다. 첫 근거를 사용한 문장·표 옆에는 Markdown `[1](#cite-1)`을 붙인다. 같은 근거는 같은 번호를 재사용한다. `article-flow` 안의 텍스트는 그대로 표시되므로 인용은 블록 뒤 설명 문장에 붙인다.
   - 기록은 `{"kind":"record","source":…}`로 연결한다. `source`에는 읽은 `SourceRef` 객체를 그대로 넣어 `capture_id`, `revision_id`와 선택한 구간·노드를 보존한다.
   - 외부 자료는 `{"kind":"external","title":…,"url":…,"note":…}`로 연결한다. 실제로 읽은 원문의 제목과 직접 여는 HTTP(S) 주소를 쓰고, `note`에는 그 자료에서 무엇을 확인했는지 한국어로 짧게 풀어쓴다. 웹의 번호 버튼은 이 정보를 본문 위에서 연다.
2. 제목을 본문에 반복하지 않는다. 마지막으로 각 번호가 정확한 근거를 가리키는지, 도식·표의 사례와 본문 설명이 일치하는지 읽어본다. `capture_create`의 `input`에 UUID `request_id`, `title`, `body_markdown`, `kinds: ["artifact"]`, `article: {summary, citations}`를 넣어 한 번 등록한다. `summary`는 서재에 보일 한 줄 답이다. 본문만 저장하면 서재에 표시되지 않는다.
3. 결과의 `ok`가 참이고 `data.result_state`가 `available`인지, 반환된 `data.capture`에 `article`이 있는지 확인한다. 설치된 이 스킬 옆 `runtime.json`의 `web_url`을 기준 주소로 삼아 fragment를 `#article/<data.capture.id>`로 설정한다. 커밋된 제목을 링크로, `article.summary`를 한 줄로 돌려준다. 사용자 지정 포트도 그대로 보존한다.
4. 응답이 유실되면 같은 입력과 같은 `request_id`로 재시도한다. 저장 결과가 `unavailable`이면 같은 글을 다시 만들지 않는다. MCP가 없거나 저장할 수 없으면 작성한 글과 출처를 보존하고 미등록 상태를 알린다. 연결은 설치된 `runtime.json`의 `commands.doctor`로 진단한다. 이미 등록됐지만 웹 주소만 확인할 수 없는 경우에는 커밋된 기록 ID를 안내한다.
