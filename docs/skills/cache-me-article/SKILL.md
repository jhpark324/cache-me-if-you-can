# Cache Me If You Can 아티클

“이 주제로 아티클 써줘”는 완성한 글을 웹의 **아티클** 페이지에 등록하고 링크를 달라는 요청이다. “초안만” 또는 “먼저 보여줘”라고 하면 대화에서 초안과 출처를 보여준다. 대화용 초안에서는 수치를 표로, 순서를 번호 목록으로, 인용을 기록 이름·짧은 발췌 또는 외부 원문 링크로 보여 준다. 전용 차트·단계 도식·번호 인용 문법은 웹 본문에 사용한다. 아티클 기능이나 아이디어에 관한 질문은 대화에서 답한다.

## 근거 모으기

1. 글을 읽고 나면 답할 수 있을 질문을 하나 정한다. `cache_me` MCP의 `knowledge_context`로 관련 기록을 찾고, 사용할 후보의 `source`를 `source_get`에 보내 당시 기록 버전·구간을 읽는다. 사용자가 특정한 기록이 있으면 그것부터 읽는다. 기록의 제안, 실제 시도, 결과, 개인 해석을 구별한다.
2. 기록만으로 이해하기 어려운 대목은 배경 설명과 구체적인 예시로 채운다. 수치·버전별 동작·연구 결과처럼 근거가 필요한 내용은 공식 문서, 표준 또는 원 논문을 찾아 해당 부분을 직접 읽고 적용 조건을 설명한다. 외부 검색어는 개념·제품명 위주로 만들고 개인 기록의 사적인 문구나 식별자를 옮기지 않는다.
3. 관련 기록이 없더라도 주제가 분명하면 확인한 원문과 설명용 예시로 쓴다. 서로 다른 실험 조건에서 얻은 결과를 한 사람의 경험으로 합치지 않는다. 외부 원문을 읽지 못했다면 그 출처와 확인이 필요한 주장을 생략하거나 한계를 밝힌다. 지식베이스 연결 실패와 검색 결과가 비어 있는 경우를 구분한다.

## 독자가 직접 볼 수 있게 쓰기

제목은 복습할 질문으로, 한 줄 요약은 그 답으로 쓴다. 개요를 잡을 때 독자가 머릿속으로 계산하거나 그려야 하는 대목을 먼저 찾는다. 그 대목에 구체적인 입력·결과를 놓고, 본문은 그림에서 무엇을 읽을지 설명한다. 질문을 이해하는 데 필요한 시각 자료를 첫 설명 가까이에 배치한다.

- **과정**은 그 사례의 상태가 어떻게 바뀌는지 보여 준다. 한 줄에 한 단계인 `article-flow`를 쓰고, ‘처리 → 확인’ 같은 추상어를 ‘제출 SQL → 실행 결과 CSV → 채점할 열 → 문항 점수’처럼 관찰할 수 있는 값으로 바꾼다.
- **규칙이나 반례**는 조건 하나만 바꾼 전후를 좁은 표에 나란히 둔다. 예를 들어 ‘도시와 건수의 짝이 사라진다’는 설명에는 서울·부산 두 행을 두고 정답 열에는 10·20, 제출 열에는 20·10을 놓는다. 캡션에서 ‘도시별 건수는 모두 틀려도, 건수 열에는 양쪽 모두 10과 20이 남는다’고 짚는다.
- **수치 비교**에는 단위와 비교 대상을 붙인다. 비율은 분자/분모를 함께 보이고, 분모가 달라지면 독자가 어떤 질문에 답하고 있는지 나누어 표시한다. 정확한 값을 찾는 표에서는 한 셀에 한 값이나 짧은 구절을 둔다.

각 시각 자료에는 독자가 알아낼 결론을 한 문장으로 붙인다. 측정한 값에는 근거 번호를, 만든 사례에는 ‘설명용 예시’를 붙인다. 등록 전에는 설명 문단을 가리고 제목·라벨·값·캡션만 읽어 본다. 핵심 차이를 여전히 산문에서 찾아야 한다면 예시나 배치를 고치고, 본문을 반복하는 도식은 덜어낸다.

### 웹에서 실제 막대 그리기

크기·순위를 한눈에 비교할 때는 `article-chart`의 `grouped`, 전체가 어떻게 나뉘는지 볼 때는 `stacked`를 쓴다. 누적할 항목은 단위가 같고 서로 겹치지 않아야 한다. 각 그룹의 `values`는 `series` 순서와 맞춘다. 값은 음이 아닌 수로 쓰며, 비교할 비율은 단위를 `%`로 두고 원자료의 분자·분모를 넣으면 리더가 백분율을 계산한다.

아래는 분모에 따라 순위가 바뀌는 **설명용 예시**다. 실제 글에서는 그 글의 근거에서 읽은 값을 사용한다.

```article-chart
{"title":"전체 과제와 완료한 과제의 성공률","mode":"grouped","unit":"%","series":["방법 A","방법 B"],"groups":[
  {"label":"전체 과제","values":[{"part":6,"total":10},{"part":5,"total":10}]},
  {"label":"완료한 과제","values":[{"part":6,"total":9},{"part":5,"total":6}]}
]}
```

이 예시의 캡션은 ‘전체 10건에서는 A가 한 건 더 성공했다. 완료한 과제만 보면 B는 6건 중 5건을 성공해 비율이 더 높다’로 쓸 수 있다. 수치와 캡션의 인용은 코드 블록 **밖**에 둔다. 그림에 꼭 필요한 관계를 막대로 표현하기 어려우면 사례를 좁은 전후 표나 단계 도식으로 그린다. 일반 이미지 링크는 현재 리더에서 대체 텍스트로 표시된다.

## 번호 출처

`citations` 배열에 처음 인용한 순서대로 근거를 둔다. 첫 근거를 사용한 문장·표 옆에는 Markdown `[1](#cite-1)`을 붙인다. 같은 근거는 같은 번호를 재사용한다. `article-flow` 안의 텍스트는 그대로 표시되므로 인용은 블록 뒤 설명 문장에 붙인다. 번호를 누르면 웹에서 읽던 위치를 유지하며 출처를 확인할 수 있다.

- 기록은 `{"kind":"record","source":…}`로 연결한다. `source`에는 읽은 `SourceRef` 객체를 그대로 넣어 `capture_id`, `revision_id`와 선택한 구간·노드를 보존한다.
- 외부 자료는 `{"kind":"external","title":…,"url":…,"note":…}`로 연결한다. 실제로 읽은 원문의 제목과 직접 여는 HTTP(S) 주소를 쓰고, `note`에는 그 자료에서 무엇을 확인했는지 한국어로 짧게 풀어쓴다.

## 아티클 등록과 수정

1. 제목은 본문에서 생략한다. 각 번호가 정확한 근거를 가리키는지, 도식·표의 사례와 본문 설명이 일치하는지 읽어본다. 새 글은 `article_create`의 `input`에 UUID `request_id`, `title`, `summary`, `body_markdown`, `citations`를 담아 등록한다. `summary`에는 목록에서 읽을 한 줄 답을, 선택 항목인 `topics`에는 글의 주제명을 담는다. 지식베이스의 기록은 출처로 참조하고 완성한 글은 아티클로 한 번만 저장한다.
2. 기존 글 수정을 요청받으면 링크의 아티클 ID를 사용하거나 `article_list`로 대상 글을 찾는다. `article_get`에 `article_id`를 보내 현재 글과 버전을 읽는다. 요청한 변경을 반영하고 `article_update`의 `input`에 제목·요약·본문·인용·주제 전체, 새 `request_id`와 `article_id`를 담는다. `expected_revision_id`에는 방금 읽은 글의 `revision_id`를 넣는다. 버전이 충돌하면 최신 글을 다시 읽고 사용자의 변경을 반영한다. 같은 구절을 서로 다르게 고쳐 의도가 모호해지면 사용자에게 확인한다.
3. 등록·수정 응답의 `ok`가 참이고 `data.request_id`가 요청과 일치하면 `data.article`에서 저장된 글을 확인한다. 설치된 이 스킬 옆 `runtime.json`의 `web_url`을 기준 주소로 삼아 fragment를 `#article/<data.article.id>`로 설정한다. 저장된 제목을 링크로, `data.article.summary`를 한 줄로 돌려준다. 사용자 지정 포트도 그대로 보존한다.
4. 응답이 유실되면 같은 입력과 같은 `request_id`로 재시도한다. `data.replayed`가 참이면 앞선 요청의 저장 결과를 사용한다. 도구를 사용할 수 없으면 글과 출처를 대화에 남기고 저장 확인 여부를 알린다. 설치된 `runtime.json`의 `commands.doctor`로 연결을 진단한다. 저장 후 웹 주소만 확인할 수 없으면 아티클 ID를 안내한다.
