# 지식 탐색 디자인 기준

- 상태: 흰색 글자·주황색 강조·더 어두운 무채색 유리의 실제 CSS 값으로 갱신했다. 새 팔레트의 색상·명암·세 화면 크기 확인을 마쳤으며 이전 v4 기능 검증과 구분해 기록했다. 최종 디자인 채택과 실제 제품 구현은 별도다.
- 기준: 검정 메인 배경, 흰색 글자·주황색 강조·더 어두운 유리, 사용자 제공 그래프·검색 응답 참고 이미지, Motion-Driven·검색 오로라 요구, [003 명세](../../specs/003-knowledge-space-design/spec.md)
- 표면 모드: Operate — 지식을 탐색하고 답변의 근거를 확인한다.

## 시각 방향

검정 공간 위에 작은 지식 노드와 얇은 연결선을 배치한다. 왼쪽에는 탐색과 범례를 모으고 상단 검색창의 위치는 응답 전후에 유지한다. 검색하면 같은 표면 안에서 입력 바로 아래로 답변과 출처 목록이 이어진다. 답변이 열렸을 때 그래프 영역의 불투명도는 `.76`으로 낮추되 배경 탐색을 유지한다.

양옆 패널은 화면 가장자리와 떨어진 유리 카드로 구성한다. 이전 v4의 청색·보라색 표면을 더 어두운 무채색 중심으로 바꾸고 뒤쪽 빛과 내부 반사의 강도를 낮춘다. 본문·탐색 글자는 흰색 계열, 핵심 문구·답변 소제목·인용은 주황색으로 구분한다. 검색창의 민트·청록·보라색 오로라와 기존 모션은 유지한다. UI UX Pro Max의 Glassmorphism과 Motion-Driven 방향을 참고하며 메인 그래프 캔버스는 `#000`이다.

프로필·워크스페이스 안내·반복 질문 제목과 중복 설명을 줄인다. 목데이터 표시, 검색 진행 상태, 버튼의 접근 가능한 이름과 출처 정보는 유지한다. 움직임은 상태 변화에 연결하고 읽는 본문은 정지 상태로 둔다.

현재 프리뷰는 React JSX·Radix Themes·Lucide를 사용한다. Radix의 `Theme`, `TextField`, `Button`, `ScrollArea`, `Dialog` 등 실제 컴포넌트에 앱 CSS를 적용한다. 구조·기본 스타일과 유리 테마의 역할은 [UI 라이브러리 선정](ui-library-selection.md)을 따른다.

표면 값은 [styles.css](styles.css), 유형 강조색은 [mock-data.js](mock-data.js)를 기준으로 한다. 반투명 색과 그라데이션이 합성되므로 화면에서 보이는 최종 픽셀색은 배경에 따라 달라진다.

강조색은 이번 목데이터의 시각적 구분이며 제품의 아홉 RecordKind를 바꾸는 스키마 변경이 아니다. 여러 유형이 같은 색을 사용할 수 있다. 색만으로 의미를 전달하지 않고 레이블과 선택 상태를 함께 제공한다.

그래프의 주요 레이블은 `#ffffff`, 기타 레이블은 `#c7c7c7`이며 현재 선택·포인터 강조 레이블은 `#ffad66`이다. 노드의 유형 색상은 유지한다. 출처의 인용 본문은 주황색 글자에 `rgba(255,153,69,.1)` 배경을 더하고, 인용 번호는 `rgba(255,173,102,.08)` 배경을 사용한다.

## 유리 표면

- 양옆 패널의 배경 흐림은 데스크톱 `24px`, 760px 이하 `16px`이며 `saturate(140%)`를 적용한다. 검색 표면은 데스크톱 `24px`·`145%`, 모바일 `16px`·`140%`다. 확대·축소 도구는 `16px` 흐림을 사용한다.
- 양옆 패널 테두리는 `rgba(222,237,255,.22)`, 상단은 `rgba(229,243,255,.42)`다. 내부 구분선은 `rgba(211,225,255,.13)`이며 반사 그라데이션과 내부 그림자를 중첩한다.
- 패널 반사는 흰색 계열로 낮추고 바깥 청록·보라색 빛은 각각 알파 `.08`로 제한한다. 사이드바 안쪽 청록빛은 `.035`, 출처 안쪽 보라빛은 `.045`로 유지해 어두운 표면에서 유리의 경계만 구분한다.
- 양옆 패널의 반경은 기본 `23px`다. 검색 패널은 기본 `21px`, 모바일 `19px`이며 입력의 오로라 테두리는 `1.5px` 두께다. 모바일 출처는 전체 화면에 맞춰 반경을 없앤다.
- 오로라는 `conic-gradient`로 표시한다. 평상시에는 정지하며 입력 포커스·검색 중·기록 읽기 상태에서 `12s` 주기로 회전한다. 별도의 밝은 전체 화면 그라데이션으로 검정 캔버스를 덮지 않는다.
- `backdrop-filter`와 `-webkit-backdrop-filter`를 지원하지 않으면 사이드바 `#0e0e11`, 검색 `#101013`, 출처·확대·축소·예시 질문은 `#111114`의 불투명 배경으로 대체한다. 대체 규칙의 존재와 미지원 브라우저의 검증 완료 여부는 구분한다.

## 타이포그래피와 간격

- 한국어 제목과 본문은 로컬 `SUIT Variable`을 사용하며 가변 굵기 범위는 `100–900`이다. 글꼴 대체 순서는 로컬 Pretendard, 운영체제 기본 글꼴, sans-serif다. [자산·라이선스](assets/index.md)를 함께 보관하고 실행 중 외부 폰트를 요청하지 않는다. 글꼴 파일 로딩과 드문 한글의 대체 렌더링은 시각 검증 대상이다.
- 답변 본문은 `16px`·굵기 `430`·행간 `1.85`, 출처 본문은 `16px`·굵기 `430`·행간 `1.9`다. 모바일에서도 같은 크기를 유지한다.
- 답변 내부 소제목은 `16px`·굵기 `650`, 출처 제목은 `24px`·굵기 `650`·행간 `1.5`다. 질문은 입력에 유지하며 답변 위에 같은 질문을 다시 크게 표시하지 않는다.
- 검색 입력은 `16px`·굵기 `450`, 탐색·유형 항목은 `14px`, 최근 기록은 `13px`, 메타데이터와 인용 번호는 주로 `12px`다. 모바일의 일부 목데이터·그래프 안내는 `11px`다.
- 답변 안쪽 여백은 기본 위·좌우·아래 `24px 30px 26px`, 모바일 `20px 21px 22px`다. 출처 안쪽 여백은 기본 `28px 28px 36px`, 모바일 `27px 27px 38px`다.
- 그래프의 중심 레이블은 화면 기준 `17px`, 주요 노드는 `14px`, 기타 노드는 `12px`이며 기타 레이블은 선택·포인터 강조 시 표시한다. 겹치는 레이블은 숨기며 모든 기록의 제목·본문은 목록에서도 확인할 수 있다.
- 긴 문단은 답변/출처 패널에서 제한된 너비로 읽는다. 탐색 영역은 항목을 빠르게 구분할 수 있는 간격을 유지한다.
- Lucide 아이콘의 기본 크기는 `19px`, 선 굵기는 `1.7`이며 작은 메타데이터와 큰 조작에서는 크기를 조정한다. 포커스 링·텍스트 선택·스크롤바도 어두운 표면에 맞춘다.

## 화면 폭과 레이아웃

| 화면 조건 | 바깥 여백·패널 사이 간격 | 사이드바 | 오른쪽 출처 패널 |
| --- | --- | --- | --- |
| 기본 데스크톱 | 각각 16px | 240px | 400px |
| 1600px 이상 | 각각 20px | 250px | 420px |
| 761–1220px | 각각 12px | 220px | 360px |
| 761–1100px에서 출처를 연 경우 | 각각 12px | 68px의 아이콘 탐색 영역 | 360px |
| 760px 이하 | 작업 영역 0px | 메뉴는 가장자리 12px, 너비 `min(280px, 100vw - 36px)` | 100vw, 전체 화면 |

검색 패널은 기본 최대 `680px`이며 작업 영역 상단에서 `78px` 내려온 위치에 놓는다. 1600px 이상은 최대 `720px`·상단 `84px`, 모바일은 좌우 `16px`·상단 `78px`다. 입력 높이는 모든 크기에서 `64px`이며 답변 유무와 관계없이 유지한다. 긴 답변은 입력 아래 영역만 스크롤한다.

데스크톱에서 출처가 열리면 작업 영역이 패널 너비를 확보해 답변과 출처를 함께 읽게 한다. 761–1100px에서는 사이드바를 줄여 읽기 공간을 확보한다. 모바일 출처는 Radix Dialog를 사용한 전체 화면 모달로 구성한다. 배경 키보드 접근과 닫은 뒤 포커스 복귀를 포함한 실제 결과는 [검증 기록](../../specs/003-knowledge-space-design/validation.md)을 따른다.

## 상호작용과 상태

- 그래프 노드 선택은 선택 표시와 상세 읽기 동작으로 이어진다. 확대·축소 등 노출한 제어는 실제로 동작해야 한다.
- 검색은 질문 하나와 단일 답변을 입력 바로 아래 같은 패널에 보여주며 새로운 검색은 기존 결과를 교체한다. 답변 닫기는 응답 영역만 접고 입력값과 검색창 위치를 유지한다. 목데이터에 없는 질문에는 지원하는 예시와 복구 경로를 안내한다.
- 출처는 오른쪽 슬라이드 패널에서 연다. 데스크톱에서는 답변을 가리지 않고, 다른 출처는 패널 내용만 바꾼다.
- 좁은 화면에서는 출처를 전체 화면 패널로 보여준다. 닫기·Escape와 포커스 복귀를 제공한다.
- 반복되는 프로필·워크스페이스 설명과 답변의 질문 제목을 제거하고, 검색 진행 상태와 출처·목데이터·조작 이름은 유지한다.
- 그래프 읽기·선택을 색상이나 마우스 hover에만 의존하지 않는다. 키보드로 사용할 수 있는 기록 목록이나 동등한 탐색 경로를 제공한다.

## 모션과 전환

- 답변 진입은 `380ms` 동안 위쪽 `9px`에서 이동하며 투명도와 일부 클리핑을 해제한다. 닫기는 `180ms` 동안 위쪽으로 이동하며 사라진다.
- 결과가 준비되면 답변 도입문은 `320ms`, 각 절은 `360ms` 동안 아래쪽 `6px`에서 한 번만 정착한다. 절마다 `50ms`의 순차 지연을 둔다. 출처 본문 교체는 `220ms`·`4px` 이동으로 연결하며 정착한 본문은 계속 움직이지 않는다.
- 출처 진입은 데스크톱 `360ms`, 모바일 `300ms` 동안 오른쪽 `35px`에서 이동한다. 데스크톱 퇴장 CSS는 `180ms`이며 앱은 퇴장 요소를 `220ms`까지 유지한 뒤 제거한다. 답변의 퇴장 유지 시간은 `180ms`다.
- 출처를 열거나 닫아 검색 패널의 수평 위치가 바뀌면 `360ms` 동안 새 위치로 이어 준다. 모바일 탐색 메뉴는 `300ms` 동안 이동한다. 전환의 기본 곡선은 `cubic-bezier(.16,1,.3,1)`이다.
- 새 상태가 들어오면 이전 퇴장 타이머를 취소하도록 구성한다. 검색 요청 식별자와 함께 오래된 답변이 뒤늦게 복원되는 상황을 방지하며, 빠른 열기·닫기·재검색은 별도 검증한다.
- `prefers-reduced-motion` 또는 화면의 모션 끄기 조작이 활성화되면 CSS 애니메이션·전환과 검색 패널 이동을 중지한다. 오로라는 정적 테두리로 남고 퇴장 대기 시간을 없앤다. 시스템에서 동작 줄이기를 선택한 경우 화면 토글로 해제하지 않는다. 그래프는 자동 회전하지 않는다.

## 검증 경계

검정 메인 배경, 흰색 글자·주황색 강조·더 어두운 유리, 검색 바로 아래 응답, 검색 오로라와 상태 전환 모션은 사용자 요구다. 구체적인 색·농도·크기·간격·시간은 현재 시안의 구현 값이며 최종 디자인 승인과 구분한다. 이 문서는 CSS·React·그래프 소스를 확인해 갱신했으며 새 팔레트의 렌더링·대비와 기존 동작 유지 여부는 [검증 문서](../../specs/003-knowledge-space-design/validation.md)에 별도로 기록한다. 이전 v4의 50개 검사와 명암 표본을 새 팔레트의 통과 근거로 사용하지 않는다. 실제 제품의 성능·검색 품질·접근성 인증을 주장하지 않는다.
