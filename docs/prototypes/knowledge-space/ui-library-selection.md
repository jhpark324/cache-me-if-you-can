# 검색·출처 화면의 UI 라이브러리 선정

- 확인일: 2026-11-02
- 상태: 디자인 프리뷰 개정의 구현 기준. 실제 적용·렌더링 검증은 [003 검증](../../specs/003-knowledge-space-design/validation.md)에 기록한다.
- 사용자 요청: 검색창 바로 아래에서 응답이 이어지는 구성과 검정 메인 배경 유지. 후속 요청에 따라 양옆 패널의 유리 질감, 한국어 글꼴·명암, 상태 전환 모션과 검색창의 오로라 강조를 강화하고 반복 문구를 정리한다.

## 이번 구현 기준

React에서 **Radix Themes와 Lucide React**를 실제로 사용한다. Radix Themes는 스타일이 포함된 컴포넌트를 제공하고 Theme를 통해 색상·반경·크기 등을 설정한다. 시안의 버튼·입력·선택 상태·도움말을 같은 기준으로 맞추는 출발점으로 삼는다. [Radix Themes 공식 시작 안내](https://www.radix-ui.com/themes/docs/overview/getting-started)

Lucide는 React에서 SVG 아이콘을 컴포넌트로 사용할 수 있다. 검색·닫기·확대·복사 등 조작 아이콘의 선 굵기와 크기를 통일하는 데 사용한다. 아이콘만 있는 버튼의 이름과 키보드 접근은 앱에서 함께 검증한다. [Lucide React 공식 안내](https://lucide.dev/guide/react)

Radix Themes는 컴포넌트의 구조와 기본 스타일을 제공한다. 유리 질감은 UI UX Pro Max의 Glassmorphism 지침을 참고한 앱의 CSS 테마다. 검정 그래프 바탕 위에 양옆 패널을 띄우고 반투명 표면, 배경 흐림, 밝은 테두리와 반사광을 적용한다. 검색 테두리의 오로라 강조도 앱 CSS로 구성한다.

Motion-Driven 방향은 응답·출처의 열림과 닫힘, 선택 상태의 변화를 보여주는 데 적용한다. 본문을 계속 움직이지 않으며 빠른 전환에서 이전 콘텐츠가 다시 나타나지 않도록 상태와 전환을 함께 관리한다. 감소된 동작 설정에서는 반복 효과와 진입·퇴장 모션을 억제한다. 구체적인 색·크기·시간은 [디자인 기준](DESIGN.md)에 기록하고, 가독성·키보드 접근·상태 전환은 새 화면에서 검증한다.

이 선택은 라이브러리만 설치하면 화면이 세련되거나 접근성이 자동 보장된다는 판단이 아니다. 검색창과 응답의 연결, 글자 크기, 정보 밀도, 출처 읽기 공간은 제품에 맞게 설계하고 실제 화면에서 확인한다.

## 비교한 대안

| 후보 | 공식 문서에서 확인한 제공 방식 | 이 프로젝트에서의 판단 |
| --- | --- | --- |
| [Radix Themes](https://www.radix-ui.com/themes/docs/overview/getting-started) | 미리 스타일이 적용된 컴포넌트와 Theme 설정 | 이번 시안처럼 기존 개별 UI를 한 기준으로 정리할 때 적합하다고 판단했다. 필요한 부분만 앱 스타일로 조정한다. |
| [shadcn/ui](https://ui.shadcn.com/docs) | 컴포넌트 소스를 프로젝트에 가져와 수정하는 방식 | 세부 디자인을 직접 소유·수정하려는 장기 요구에는 좋은 대안이다. 이번 개정은 구성 요소의 일관성을 먼저 확보하기 위해 Radix Themes로 시작한다. |
| [Mantine](https://mantine.dev/getting-started/) | React UI 컴포넌트·상태 관련 hooks 등 패키지와 Vite 안내 | 폼·오버레이 등 여러 UI를 구성하는 대안이다. 이번 좁은 검색·출처 흐름에서는 추가 패키지 범위보다 같은 화면 규칙을 정리하는 데 집중한다. |

표의 적합성 판단은 프로젝트 요구에 대한 설계 판단이다. 라이브러리 간 성능·번들 크기·접근성 순위를 실측한 결과가 아니다.

## 적용 경계

- 프리뷰는 React JSX와 esbuild의 정적 번들로 실행한다. 실제 제품의 TypeScript·Vite 구성 및 FastAPI 연결을 완료했다는 뜻이 아니다.
- Radix Themes의 실제 컴포넌트와 CSS, Lucide의 실제 아이콘 import를 사용한다. 이름이나 시각 패턴만 빌려온 구현을 라이브러리 적용으로 기록하지 않는다.
- 검정 그래프 배경, 기존 `3d-force-graph` 계열, 목데이터 기록과 인용 의미를 유지한다. 이 선택으로 채팅 기능을 추가하지 않는다.
- 데스크톱 출처는 답변과 함께 읽는 비모달 영역으로 구성한다. 모바일 모달의 포커스·닫기·복귀는 별도로 확인한다.
- 구체적인 패키지 버전은 설치 결과의 lockfile로 남긴다. 아직 하지 않은 빌드·브라우저 검사를 통과로 기재하지 않는다.
- 이번 구현 기준과 사용자가 최종 디자인을 채택하는 것은 별개다.
