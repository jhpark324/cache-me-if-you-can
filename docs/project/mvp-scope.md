- 상태: 현재 제품 범위. 재현 가능한 확인 절차는 [검증 안내](../guides/testing.md) 참조
- 갱신일: 2026-11-02
- 용어: [도메인 용어](domain-language.md)
- 기준: [제품 기획](product-brief.md), [기록 유형](record-types.md), [공통 계약](../architecture/service-contracts.md)

웹은 기록 탐색과 검색 기반 단일 응답을 제공하며 출처는 오른쪽 패널에서 확인한다. 이 문서는 사용자 동선과 기능 경계를 설명한다. 실제 계정·클라이언트·운영체제 호환성은 별도 검증한다.

## 첫 버전의 완성 조건

사용자가 Codex Skill 또는 자체 웹에서 기록을 저장하고 실제 저장본을 확인한다. 이후 웹과 MCP에서 관련 지식을 찾아 질문하며, 잘못된 내용과 출처를 정정하고 필요하면 재확인 후 삭제할 수 있다. 다른 대화에서 같은 지식을 읽어도 제안·선택·경험·개인 조건의 맥락을 유지해야 한다.

| 포함 | 첫 버전의 경계 |
| --- | --- |
| 기록 관리 | Markdown 본문, 선택적인 제목·여섯 기록 유형·주제·세부 항목·출처, 생성·조회·수정·완료 변경·명시적 병합 |
| 삭제 | 재확인 후 `deleted_at` 설정. 내부 데이터는 보존하고 제품에서는 조회·수정·답변에 사용하지 않음 |
| 검색 | 본문·제목의 키워드/의미 검색, 유형·주제·알려진 사건 시각 조건, 세부 항목 상세와 저장본 출처 |
| 검색 기반 응답 | 검색 한 번마다 FastAPI의 LangGraph가 읽기 도구로 근거를 찾아 단일 답변 생성. 이전 검색의 대화 이력을 넘기지 않고 저장 지식과 일반 설명을 구분 |
| 정정 | 변경 이력, 충돌 감지, 원출처 정정 후 파생 기록 재검토, 명시적인 조건 변경 관계 |
| 연결 탐색 | 홈의 제한된 지식 개요와 선택 기록 주변 1홉 그래프, 주제·명시적 관계·세부 항목 연결과 출처 상세 |
| 실행 | Windows·macOS·Linux 직접 실행, CPU 임베딩 기본, 자체 모델 로그인, 로컬 MCP |
| 운영 | 검색 준비 상태·실패 재시도·로컬 데이터 경로 확인·수동 백업 생성 |

휴지통 화면·삭제 기록 목록·삭제 내용 조회·복원·실행 취소·자동 삭제·물리적 영구 삭제는 제공하지 않는다. 채팅·멀티턴 대화·대화 목록은 첫 버전 범위에서 제외한다. 일정·알림, 상한 없이 저장소 전체를 한 번에 로드하는 그래프, 공유, 자동 프로필 통합, 파일 첨부도 후속 범위다. 제한된 홈 그래프는 현재 범위에 포함한다.

## 화면과 기본 동선

| 화면 | 사용자가 할 일 | 기본 동작 |
| --- | --- | --- |
| 지식 공간 | 연결 탐색·검색·메모 추가 | 3D 그래프와 검색을 제공하고 핵심 메뉴로 라이브러리·타임라인·설정에 접근한다. 입력 중 LLM을 호출하지 않으며 실행 시 독립적인 답변 흐름을 시작 |
| 라이브러리·타임라인 | 저장 기록을 목록·시간 순서로 탐색 | 본문 영역에서 검색·유형·주제 조건으로 기록을 좁히고 상세를 연다. 탐색 필터는 질문 실행과 별도로 사용할 수 있다 |
| 기록 상세 | 본문·유형·주제·세부 항목·출처 확인, 수정·삭제 | 실제 저장된 본문과 현재 구조 상태를 표시. 이력은 삭제되지 않은 기록에 한해 명시적으로 열람 |
| 검색 결과 | 하나의 검색어·질문에 대한 답변과 관련 기록 확인 | 검색 실행으로 시작. 질문 하나·답변 하나·출처 목록을 표시하며 채팅 말풍선·이전 턴 목록을 만들지 않음 |
| 오른쪽 출처 패널 | 답변에 인용된 기록과 본문 구간 확인 | 출처 클릭으로 오른쪽에서 열림. 답변을 유지하고 선택 출처의 저장본·강조 구간·메타데이터를 표시 |
| 연결 탐색 | 현재 기록과 관련된 지식으로 이동 | 홈 개요에서 기록을 선택하거나 상세에서 1홉 주변 그래프를 연다. 홈과 주변 탐색 모두 노드·간선 상한을 지키며 잘린 범위를 표시 |
| 설정 | 모델 연결, 로컬 실행 상태, 저장 위치, 수동 백업 | 로그인·모델 준비·검색 준비 상태를 구분. 연결 실패가 기록 생성 실패로 표현되지 않음 |

기록 생성은 실제 커밋된 정리본을 보여주는 것으로 완료한다. 저장을 요청한 사용자에게 다시 저장 승인까지 요구하지 않는다. 변경 충돌이면 현재 저장본과 사용자의 편집 내용을 비교할 수 있게 하고 자동 덮어쓰지 않는다.

삭제 확인은 대상의 제목 또는 본문 일부와 “삭제하면 앱에서 다시 조회하거나 복원할 수 없다”는 결과를 보여준다. 성공 후 목록·열려 있는 상세·관련 그래프를 갱신한다. 내부 구현인 soft delete를 사용자용 동작 이름으로 노출할 필요는 없으며, 데이터가 디스크에서 완전히 지워졌다고 표시하지 않는다.

## 검색 결과와 오른쪽 출처 패널

검색 결과는 질문·단일 답변·출처 목록으로 구성하고 출처 선택은 오른쪽 패널로 연결한다. 시각 규칙과 반응형 동작은 [웹 명세](../specs/workspace.md)를 따른다.

1. 사용자가 검색어 또는 질문을 입력하고 검색을 실행한다. 현재 질문, 검색/답변 진행 상태, 관련 기록을 표시한다.
2. 검색창의 위치를 유지한 채 바로 아래에 해당 검색의 답변 하나와 번호가 붙은 출처 목록을 펼친다. 검색창과 응답은 같은 패널로 이어지고 뒤의 지식 그래프를 유지한다. 답변 닫기는 응답만 접고 입력한 질문은 유지한다. 본문의 인용 번호와 하단 출처가 같은 저장본을 가리키게 한다. 모델 응답이 실패해도 유효한 검색 결과는 유지한다.
3. 본문 인용이나 출처 항목을 클릭하면 오른쪽 패널을 연다. 넓은 화면에서는 답변과 출처를 나란히 읽을 수 있도록 구성한다. 패널을 열어도 검색어·답변·스크롤 위치를 유지한다.
4. 패널은 실제 인용한 `capture_id + revision_id + 선택적 node_id/span`을 조회한다. 제목, 실제 저장 본문, 인용 구간 강조, 유형·주제, 저장본 시각과 근거 상태를 보여주며 전체 본문도 읽을 수 있게 한다. 요약을 원본 내용인 것처럼 대신 보여주지 않는다.
5. 다른 출처를 클릭하면 같은 패널의 내용을 교체한다. 여러 상세 패널을 겹쳐 열지 않는다. 닫기·Escape 후 이전 출처 버튼으로 포커스를 되돌리고 원래 답변 읽기를 이어간다.
6. 좁은 화면은 동일한 출처 내용을 전체 화면 패널로 보여주고 뒤로/닫기로 검색 결과에 돌아간다. 구체적인 너비·애니메이션은 시각 디자인에서 정한다.
7. 클릭 시 현재 삭제·소유·공개·출처 상태를 다시 확인한다. 삭제된 출처는 본문을 열지 않고 더 이상 조회할 수 없음을 표시한다. 더 최신 revision이 있으면 인용 당시 저장본과 최신본을 구분하며 조용히 최신 본문으로 바꾸지 않는다.

## 웹 검색 요청의 수명

- 각 검색은 독립적인 단일턴 요청이다. 이전 질문·답변·채팅 이력·대화 ID를 다음 검색의 모델 입력에 자동 포함하지 않는다. 한 요청 안에서 근거 보강을 위한 여러 검색·도구 호출은 가능하다.
- 현재 탭은 현재 검색어·답변·선택 출처·진행 상태를 화면 상태로만 보관한다. 새 검색은 새 request ID로 실행하고 이전 작업을 취소한다. 늦게 도착한 이전 응답·패널 조회가 새 결과를 덮어쓰지 않게 한다.
- 서버는 진행 중 요청 상태를 메모리에서 관리한다. 대화 테이블, 영구 LangGraph 체크포인트, 브라우저 영구 저장소에 검색 질문·응답 전문을 저장하지 않는다.
- 요청·응답 본문이나 모델 내부 추론을 로그로 복제하지 않는다. 운영 로그는 요청 ID·상태·시각·오류 코드 등으로 한정한다.
- 검색 실행 중 근거가 바뀌거나 삭제되면 완료 전에 다시 검증한다. 이미 표시한 진행 중 답변을 최종 검증된 결과로 남기지 않도록 무효화·다시 검색 안내를 처리한다.
- 답변 저장은 사용자의 별도 동작이다. 선택한 내용과 출처를 새 Capture로 저장하며 검색 질문·응답 전체가 자동으로 장기 지식이 되지 않는다.
- 모델 문맥 예산을 넘으면 필요한 근거를 선정하고 포함하지 못한 범위를 알린다. 임베딩 질의의 64토큰 한계를 웹 질문 글자 수 제한으로 사용하지 않는다.

## 세부 항목과 연결 탐색

세부 항목이 없는 메모도 정상 저장·검색한다. 긴 본문에 세부 항목이 있으면 검색한 구간에서 필요한 항목과 주변 문맥을 읽는다. 세부 항목 갱신이 필요한 상태는 본문 저장 실패와 구분하고, 현재 잘못된 구간을 조용히 재사용하지 않는다. 세부 규칙은 [검색·맥락 계약](../architecture/retrieval-and-context.md)에 둔다.

홈 그래프는 최근 현재 기록과 실제 연결의 개요이며 상한은 노드 50개·간선 100개다. 기록 선택 시 1홉 주변 조회로 상세 탐색을 이어 간다. 잘린 결과를 모든 관계가 없다는 뜻으로 표현하지 않으며 다른 기록 선택·필터·검색 경로를 제공한다. 유사도가 높다는 이유만으로 인과나 확정 관계를 만들지 않는다. [웹 명세](../specs/workspace.md)의 그래프 계약을 따른다.

## 로컬 운영과 백업

개발·초기 배포는 Python 서버와 정적 웹 번들을 같은 제품 단위로 제공하는 방식으로 준비한다. uv와 프론트 lockfile로 검증된 의존성 조합을 고정한다. 모델은 첫 사용 때 준비 상태와 진행을 표시하고, 다운로드가 끝나지 않아도 기록 관리 화면을 사용할 수 있게 한다.

수동 로컬 백업 파일 생성을 제공한다. 백업에는 일관된 SQLite 정본, 스키마·모델 프로필 등의 manifest를 담고 재생성 가능한 검색 색인·모델 가중치·로그인 비밀정보는 제외한다. 모델·색인은 다시 준비할 수 있지만 삭제 표시는 백업에서 보존해야 한다. 백업은 내부 보존된 삭제 기록까지 포함하는 개인 전체 사본이며 공유용 내보내기가 아니다.

실행 중 DB 파일을 그대로 복사하는 방식으로 일관성을 가정하지 않는다. 일관된 스냅샷 생성과 별도 검증용 위치에서의 무결성 확인을 구현 작업에 포함한다. 앱의 백업 가져오기·데이터 전체 복구 UI·기기 동기화는 후속 범위이며, 백업 생성을 개별 삭제 기록의 복원 기능으로 연결하지 않는다.

## 실험으로 확정해야 하는 항목

기획으로 결정할 수 있는 동작과 실제 환경에서 확인할 조건을 구분한다. 다음 사항은 문서만으로 완료할 수 없다.

| 검증 | 통과해야 할 조건 |
| --- | --- |
| 자체 로그인·모델 | 실제 계정의 로그인·갱신·사용 가능한 모델 확인·서버 답변·도구 왕복·취소. 답변 모델명은 이 결과로 선택 |
| Codex MCP | SDK v2 연결·구조화 입출력·오류·사용자 삭제 재확인의 실제 동작 |
| 검색 품질 | 한국어 실제 사용 사례, 긴 본문·질문, 미분류·혼합 기록, 출처 정정·삭제 후 재노출 방지 |
| 운영체제 | [지원 목표](../architecture/platform-support.md)의 네이티브 설치·추론·경로·종료·재시작. 미해결 CPU 아키텍처의 설치 경로 포함 |

로그인 또는 클라이언트 확인 수단이 실제 요구를 충족하지 못하면 이를 검증 결과로 기록하고 영향을 받은 계약을 수정한다. 확인되지 않은 연동을 성공으로 기록하거나 기존 사용자 요구를 조용히 다른 인증·삭제 동작으로 바꾸지 않는다.
