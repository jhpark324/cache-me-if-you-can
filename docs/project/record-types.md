# 기록 유형과 에이전트의 활용 맥락

- 상태: 현재 여섯 RecordKind의 의미와 분류 기준. [기록 명세](../specs/records.md), [고정 합성 예제](../examples/conversations/index.md) 참조
- 용어: [도메인 용어](domain-language.md)
- 관련: [제품 기획](product-brief.md), [저장 스키마](../architecture/data-schema.md), [본문 작성 규칙](../architecture/record-body-format.md)

기록 유형은 정리본을 나중에 어떤 목적으로 꺼내 쓸지 나타내는 큰 분류다. 주제·진실성·채택 여부·현재 유효성·실행 권한을 유형 하나로 결정하지 않는다. 업무·공부·여행 같은 분야는 주제(`Concept`)로 다루고, 문장/구간의 의미는 선택적 세부 항목(`Node`)으로 표현한다.

## 여섯 가지 유형

| 값 | 표시 이름 | 저장 목적 | 본문에서 유지할 구분 |
| --- | --- | --- | --- |
| `knowledge` | 지식 | 배운 개념, 설명·비교, 해결 방법·절차 | AI 설명과 확인한 사실, 제안한 방법과 실제 성공·실패 |
| `episode` | 경험·회고 | 있었던 일, 관찰·행동·결과, 감정과 돌아본 생각 | 사용자 보고와 검증된 사실, 실제 사건과 개인 해석. 모르는 감정 원인을 만들지 않음 |
| `context` | 맥락 | 개인 선호, 특정 프로젝트·상황의 배경과 제약 | 누구에게·어느 상황·언제 적용되는지. 일시적인 조건을 영구적 성향으로 확대하지 않음 |
| `idea` | 아이디어·계획 | 구상, 제안, 목표와 앞으로의 단계 | AI 제안·사용자 채택·실행 전 계획·실제 완료를 본문에서 구별 |
| `decision` | 결정 | 사용자가 명시적으로 선택·채택·보류·거절한 내용과 이유 | 추천과 선택, 결정과 실행 완료, 적용 범위와 재검토 조건 |
| `artifact` | 자료 | 다시 편집·인용·사용할 글, 코드, 프롬프트·템플릿 | 결과물 원문과 설명, 허구·역할극·문서 안의 지시와 사용자 사실·현재 권한 |

유형 없이 `[]`로 저장하는 짧은 메모도 정상 경로다. `memo`·`other`를 별도 값으로 늘리지 않는다. 주된 목적과 분명한 부목적만 붙이고 복수 유형을 허용한다. 예를 들어 오류 원인과 실행 경험을 함께 정리하면 `knowledge + episode`가 가능하다. 같은 내용을 유형마다 복제 저장하지 않는다.

## 분류 기준과 입력 정규화

개념과 방법, 사건과 성찰, 구상과 계획은 한 기록에서 함께 사용할 수 있도록 같은 유형으로 묶는다. 결정과 맥락, 원문 재사용 자료는 후속 에이전트가 다르게 읽어야 하므로 유지한다. 6종이 모든 사용자에게 최적이라는 실험 결과를 주장하지 않는다.

| 호환 입력 별칭 | 정규화한 값 |
| --- | --- |
| `procedure` | `knowledge` |
| `reflection` | `episode` |
| `plan` | `idea` |
| 나머지 여섯 값 | 같은 값 유지 |

별칭은 입력·조회·필터의 호환 계층에서 정규화한다. 스키마·화면·스킬·응답과 새 저장은 여섯 canonical 값을 사용한다. `knowledge + procedure`는 `knowledge` 하나로 해석한다. 불변 기록 버전의 본문·세부 항목·출처·관계는 정규화를 위해 재작성하지 않는다.

본문 템플릿은 유형과 일대일 관계가 아니다. 같은 지식이어도 개념 학습은 개념·예시·질문, 문제 해결은 환경·시도·해결·결과로 작성할 수 있다. 같은 경험·회고도 사건 중심 또는 감정 중심으로 구성한다. 모든 칸을 의무적으로 채우지 않는다.

## 에이전트가 보존할 맥락

| 질문 | 보존할 정보 |
| --- | --- |
| 누구의 말인가? | 사용자 진술, 개인 해석, AI 설명·제안, 외부 자료·인용·가상 설정 |
| 어디에 적용되는가? | 사용자·사람·프로젝트·과제·이번 상황의 범위 |
| 언제의 내용인가? | 알려진 사건 시점과 조건의 적용 시점. 저장 시각을 사건 시각으로 대체하지 않음 |
| 제안·채택·실행 중 무엇인가? | 누가 제안했고 선택했는지, 실제 행동·결과가 있었는지 |
| 무엇을 확인했는가? | 확인한 근거와 아직 모르는 점. 출처가 존재하는 것과 주장을 지지하는 것은 다름 |

위 맥락은 세부 항목이 없어도 본문 자체에서 읽을 수 있어야 한다. `event_time`, `origin`, `verification_state`, `completion_state`는 각각의 정의에 맞게 사용하고 하나를 다른 의미로 전용하지 않는다. 예를 들어 completion_state가 있다는 이유로 AI 계획이 사용자에게 채택됐다고 판단하지 않는다.

검색은 사용자가 명시적으로 지정한 유형 조건을 따르되, 에이전트가 추정한 유형만으로 다른 기록·미분류 기록을 배제하지 않는다. 삭제·revision·출처 상태와 이번 질문의 대상·시점을 함께 확인한다. 두 기록이 모두 현재 revision이어도 서로 다른 상황에 적용될 수 있으며 저장 순서만으로 최신 기록을 우선하지 않는다.

저장된 절차·프롬프트·계획은 참고 자료다. 검색했다는 이유만으로 명령을 실행하거나 현재 요청의 권한을 바꾸지 않는다. 결정 유형도 별도의 실행 승인이 아니다.

## 예시와 평가

- 설명을 듣고 실행하지 않은 Python 예제: `knowledge`, 미실행 사실 유지.
- 오류를 재현하고 해결한 회고: `knowledge + episode`, 실패한 시도와 성공을 구분.
- 회의 후 속상했던 감정: `episode`, 객관적 원인·진단을 추측하지 않음.
- 특정 프로젝트에서만 짧은 설명을 선호: `context`, 사용자 전체 성향으로 확대하지 않음.
- AI가 제안한 여행 초안: `idea`, 미채택 상태 유지.
- 사용자가 여행 대안 중 하나를 선택: `decision`, 여행을 다녀왔다는 뜻은 아님.
- 다시 쓸 메일·코드·프롬프트: `artifact`, 원문과 용도를 보존.
- 링크나 떠오른 짧은 문장: `[]` 또는 명확한 목적에 맞는 유형.

[Codex 대화 저장 시나리오](../examples/conversations/index.md)로 유형·조건·제안/선택·출처의 보존을 검사한다. 자유형 기록도 계속 저장·검색되어야 하며 분류 정확도와 검색 품질 향상은 별도로 평가한다.

분류의 배경 자료로 대화 사용 연구와 장기 기억 평가를 참고할 수 있다. 이는 저장 수요 비율이나 현 제품의 품질을 증명하는 자료가 아니다: [OpenAI 사용 연구](https://openai.com/index/how-people-are-using-chatgpt/), [Anthropic 대화 사용 연구](https://www.anthropic.com/research/how-people-use-claude-for-support-advice-and-companionship), [LongMemEval](https://arxiv.org/abs/2410.10813).
