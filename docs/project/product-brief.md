# Cache Me If You Can 제품 기획

Cache Me If You Can은 AI와 대화하며 정리한 지식, 경험, 일상과 감정, 메모를 로컬에 쌓고 그 지식을 바탕으로 질의응답하는 개인용 세컨드 브레인이다. 사용자는 대화를 다른 도구에 옮겨 적는 부담을 줄이고, 필요한 순간에 저장된 내용과 맥락을 되찾는다.

- 상태: 현재 제품 범위
- 갱신일: 2026-11-02

## 현재 제품 방향

학습 정리, 일상과 감정 기록, 간단한 메모, 프로젝트 경험·결정·행동·회고를 모두 제품의 사용 사례로 다룬다. 직업이나 기록 목적 하나를 전체 제품의 제한으로 삼지 않는다. 일정과 할 일에 관한 내용을 메모로 남길 수는 있지만, 일정 관리 기능은 제공하지 않는다.

지원 목표는 Windows·macOS·Linux에서 로컬 서버와 CPU 임베딩을 직접 실행하는 것이다. WSL은 선택 가능한 개발·실행 환경이며 필수 설치 조건으로 두지 않는다. Codex의 Skill과 로컬 MCP를 통해 데이터를 생성·조회·수정·삭제하고, 자체 웹에서도 저장·조회·정정과 삭제를 지원한다. 웹에서 질의하면 FastAPI 서버 내부의 LangGraph가 관련 지식 조회와 모델 호출을 포함한 답변 생성 흐름을 관리한다. 모델 연결은 자체 웹의 ChatGPT OAuth 로그인으로 제공하며 별도 API key 입력을 기본 절차로 요구하지 않는다.

운영체제 지원 목표와 실제 검증 완료를 구분한다. CPU 아키텍처·최소 OS 버전·의존성 설치 제약은 [운영체제 지원 설계](../architecture/platform-support.md)에서 관리한다. 한국어 중심 검색의 모델 비교는 [검색과 임베딩 설계](../architecture/search-and-embedding.md#한국어-중심으로-사용할-때의-재검토)를 따른다.

자신의 Second Brain을 다른 사람과 공유하는 기능은 장기 확장으로 둔다. 지금은 저장 단위에서 공개 범위를 구분할 수 있는 구조를 고려한다. 공유 기능의 출시 시점이나 구체적인 방식은 정하지 않았다.

## 사용자와 사용 사례

| 사용 목적 | 저장 요청 예시 | 다시 활용하는 장면 |
| --- | --- | --- |
| 학습과 지식 정리 | 오늘 배운 트랜잭션 개념과 아직 헷갈리는 부분을 정리해줘 | 지난 설명·예제·질문을 찾아 복습하고 이해의 변화를 확인한다. |
| 일상과 감정 기록 | 오늘 있었던 일과 내가 느꼈던 감정을 남겨줘 | 특정 날의 사건과 당시 감정을 돌아보고 자신의 표현을 확인한다. |
| 계획에 관한 메모 | 오늘 이야기한 계획을 메모로 남겨줘 | 과거에 무엇을 계획했고 어떤 맥락이었는지 질의한다. 일정 관리 화면이나 알림은 제공하지 않는다. |
| 빠른 메모 | 이 아이디어와 링크를 기억해줘 | 짧게 남긴 문장·링크·아이디어를 관련 주제에서 다시 찾는다. |
| 경험과 회고 | 이번 선택의 이유와 실제로 해본 결과를 남겨줘 | 결정의 배경과 실제 행동을 구분해 회고나 글쓰기에 활용한다. |

한 사람이 여러 목적을 함께 가질 수 있고, 한 대화에도 여러 종류의 내용이 섞일 수 있다. 사용자가 저장 전에 고정된 유형이나 긴 양식을 반드시 선택하게 만들지 않는다.

기록 유형은 [재사용 목적에 따른 여섯 유형](record-types.md)으로 구체화한다. 지식·경험과 회고·맥락·아이디어와 계획·결정·자료를 구분하고, 유형만으로 사실성·채택 여부·현재 유효성을 추정하지 않는다. 개인의 조건을 다음 대화에 활용하거나 완성한 글·코드를 다시 사용하는 사례도 포함한다. 유형은 여러 개 또는 미분류를 허용하며 연구의 대화 사용 비율을 장기 저장 수요로 간주하지 않는다.

## 공통 사용 흐름

1. 사용하던 AI 대화에서 저장할 내용을 지정한다.
2. AI가 현재 확인할 수 있는 내용을 정리하고, 선택한 범위만 저장한다.
3. 저장 성공 후 실제 저장된 내용을 사용자에게 보여준다. 사용자는 내용을 확인하고 필요하면 정정을 요청한다.
4. 자체 웹에서 검색어·질문을 실행하면 FastAPI 서버가 저장된 지식을 바탕으로 해당 검색의 단일 응답을 생성한다. 출처를 클릭하면 오른쪽 패널에서 인용한 저장본과 구간을 확인한다.
5. 학습, 회고, 일상 정리 등에 활용하고 명시적으로 요청한 내용이나 완료 상태를 갱신한다.

명시적인 저장 요청을 중심으로 하며 대화 세션을 자동 수집하지 않는다. 원문을 그대로 저장하도록 요청한 경우에는 그 본문을 기록으로 보존한다. 저장 후 보여주는 내용은 다시 생성한 요약이 아니라 실제로 저장된 정리본이다. 사용자에게 내용을 보여주는 절차가 매번 별도의 저장 승인 절차를 뜻하지는 않는다. 빠른 메모는 본문만으로 저장할 수 있어야 하며, 긴 기록은 필요한 경우 여러 항목으로 나눠 찾을 수 있게 한다.

## 변경과 삭제

Skill과 웹에서 명시적으로 요청한 추가·수정·완료 상태 변경을 허용하고 결과를 보여준다. 완료 상태는 기록 내용의 상태를 표현하며 전용 할 일 관리 기능을 뜻하지 않는다.

같은 주제의 새 내용은 기본적으로 별도 기록으로 추가하고 관련 주제·기록에 연결한다. 사용자가 기존 기록에 합치거나 수정하라고 요청한 경우에만 해당 기록을 갱신한다. 유사하다는 이유로 기존 내용을 덮어쓰지 않는다.

삭제는 Skill과 웹 모두에서 제공한다. 삭제할 대상을 제시하고 사용자에게 다시 확인한 뒤 `deleted_at`에 서버 시각을 기록하는 soft delete로 처리한다. 본문·버전·관계는 내부 저장소에 보존하지만 삭제된 기록과 그 이력은 목록·상세·검색·그래프·질의응답·수정 대상에서 제외한다. 휴지통이라는 제품 개념, 삭제 목록·조회 필터, 복원·실행 취소 기능은 제공하지 않는다. `deleted_at`은 일반 수정으로 비우거나 변경할 수 없다. 보관 기한·자동 삭제·수동 영구 삭제도 두지 않는다.

## 답변의 범위

저장된 지식을 우선 활용하며 근거가 된 저장 기록을 확인할 수 있게 한다. 설명이 부족하면 AI의 일반 지식으로 보충하되, 저장된 내용과 추가 설명을 구분한다. 개인 경험이나 행동에 관한 기록이 없으면 이를 추정해서 채우지 않는다.

AI 답변이나 추가 설명은 자동으로 장기 지식에 저장하지 않는다. 사용자가 별도로 저장을 요청하면 기존 기록을 재사용한 부분과 AI의 추가 설명을 구분해 정리한다. 웹은 검색 기반 단일턴 응답으로 동작하며 이전 질문·답변을 다음 요청의 대화 맥락으로 자동 전달하지 않는다.

## 기록의 의미를 보존하는 원칙

- 학습 기록에서는 설명, 개인의 해석, 가설, 미해결 질문을 구분한다. AI가 설명했다는 사실만으로 내용이 검증됐다고 표시하지 않는다.
- 일상 기록에서는 사건과 사용자가 직접 표현한 감정을 연결한다. 기록에 없는 감정·성격·원인을 확정해서 추가하지 않는다.
- 계획에 관한 기록에서는 예정, 고려 중인 제안, 실제 완료를 구분한다. 기록을 저장했다고 일정이나 알림을 생성하지 않는다.
- 경험 기록에서는 AI의 제안, 사용자의 결정, 실제 행동과 결과를 구분한다.
- 정리본에서 사용자의 표현과 의미를 유지하고, 모르는 시점이나 결과를 임의로 채우지 않는다. 원문을 보관·대조했다는 의미로 표현하지 않는다.
- 답변에서 근거를 표시할 경우 실제 저장된 지식을 가리킨다. 저장되지 않은 원문이나 발췌를 근거로 제시하지 않는다.

저장 단위와 공개 범위의 구체적인 원칙은 [기록과 공개 범위 설계안](record-and-visibility.md)에서 관리한다.

## 현재 범위와 확장 경계

첫 실사용에서는 각 사용 사례의 대표 기록을 같은 저장·질의응답 흐름으로 다룰 수 있는지 확인한다. 에이전트용 지식 계층은 [지식 계층 설계](../architecture/knowledge-layer.md)에 정리한다. 일정 관리와 외부 전송 정책 설계는 현재 범위에 포함하지 않는다.

로컬 MCP CRUD, 자체 웹의 저장·조회·정정·삭제와 검색 기반 단일턴 응답, 오른쪽 출처 패널, 저장 후 내용 표시, soft delete, 삭제 전 재확인은 현재 범위다. 첫 화면·주변 그래프·운영 범위는 [MVP 기획](mvp-scope.md)을 따른다. 구현 기준과 실제 통합 검증 조건은 [기술 스택 선정](../architecture/technology-stack.md)에서 확인한다.

웹은 검정·회색·흰색 중심의 화면에서 핵심 메뉴와 검색을 유지하고 본문에서 기록 라이브러리·타임라인·3D 그래프를 탐색한다. 그래프는 `3d-force-graph` + Three.js + `three-spritetext`를 사용하며 노드·연결선 상한을 둔다. [웹 명세](../specs/workspace.md), [ADR-004](../decisions/ADR-004-graph-visualization-library.md)

| 단계 | 다룰 범위 |
| --- | --- |
| 지원 목표 | Windows·macOS·Linux 네이티브 CPU 실행,  Codex + 자체 웹, 로컬 MCP CRUD, FastAPI의 지식 기반 답변 생성, 저장 후 확인과 삭제 전 재확인 |
| 채택한 동작 | 자체 ChatGPT OAuth 로그인, 새 기록 우선과 명시적 갱신, 보충 설명 구분, 사용자 재확인 후 soft delete |
| 현재 구현 | 공통 기록 서비스·검색·맥락 계약, 기록 라이브러리·타임라인·3D 그래프·출처 패널 |
| 장기 확장 | 다른 사람과의 공유, 공개용 기록 모음, 공유 권한과 회수 방식 |
| 현재 제외 | 일정 관리, 알림·반복·외부 캘린더 연동, 대화 세션 자동 수집, 외부 전송 정책 설계, 휴지통·삭제 기록 조회·복원·실행 취소, 자동 삭제·영구 삭제 |

## 검증할 질문

- 학습 정리와 간단한 메모 모두 저장 부담이 충분히 낮은가?
- 사용자가 기대한 내용이 저장되고, 개인 표현과 AI 설명이 섞이지 않는가?
- 기록을 다시 찾아 복습·회고·일상 이해 등 실제 용도로 사용하는가?
- 정정이나 완료 상태 변경 후 현재 정보와 과거 맥락을 구분할 수 있는가?
- 저장 후 보여주는 내용이 실제 저장 결과와 일치하고, 삭제는 양쪽 진입점에서 재확인 후 실행되는가?
- 서로 다른 종류의 내용이 섞였을 때 필요한 부분을 찾고 분리하기 쉬운가?
- Windows·macOS·Linux에서 WSL·Docker·GPU 없이 설치·실행하고 같은 저장·검색·정정·삭제 흐름을 사용할 수 있는가?

첫 검증 상황을 개발자의 주간 회고로 고정하지 않는다. 초기 사용자와 대표 질문을 선정하면서 여러 사용 목적을 평가 데이터에 포함한다.
