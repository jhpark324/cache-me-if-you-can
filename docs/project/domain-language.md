# 도메인 용어

제품 문서·화면·스킬에서는 아래 한국어 이름을 사용한다. 설계와 코드에서 타입·필드·도구를 가리킬 때에는 대응하는 식별자를 그대로 쓴다. 저장 계약은 [기록 명세](../specs/records.md), 필드와 제약은 [데이터 스키마](../architecture/data-schema.md), 입출력은 [서비스 계약](../architecture/service-contracts.md)을 따른다.

## 저장과 탐색의 단위

| 표준 용어 | 코드·계약 대응 | 의미와 구분 |
| --- | --- | --- |
| 기록 | `Capture`, `capture_id` | 사용자가 명시적으로 저장한 내용과 맥락의 묶음. 생성·수정·삭제의 기본 단위다. |
| 기록 버전 | `CaptureRevision`, `revision_id`, `revision_no` | 한 시점의 불변 내용. 수정 후에도 이전 기록 버전은 바뀌지 않는다. 특정 버전의 실제 내용을 설명할 때는 **저장본**이라고 표현할 수 있다. |
| 상태 버전 | `state_version` | 공개 범위·삭제 등 기록의 상태 변경까지 포함하는 충돌 검사 값. 기록 버전 번호와 같다고 가정하지 않는다. 주제 수정에도 별도의 상태 버전을 사용한다. |
| 세부 항목 | `KnowledgeNode`, API의 `NodeInput`·`NodeView`, `nodes` | 기록 버전의 본문 안에서 설명·질문·결정 등의 의미를 가진 선택적 구간. 별도 원문이나 독립 기록이 아니다. |
| 주제 | `Concept`, `concept_id` | 기록과 세부 항목에 연결하는 자유로운 주제. 이름·설명·별칭을 가지며 같은 이름만으로 합치지 않는다. |
| 주제 힌트 | `concept_hints` | 저장 요청자가 제공하는 주제 후보. 실제 연결된 주제 ID와 구분한다. |
| 기록 유형 | `RecordKind`, `kinds` | 재사용 목적에 따른 큰 분류. [여섯 유형과 표시 이름](record-types.md)을 사용하며 복수 유형과 미분류를 허용한다. |
| 관계 | `Relation`, `relation_type` | 기록 버전·세부 항목·본문 구간 사이에 명시적으로 만든 방향·종류·근거가 있는 관계. 종류별 표시는 아래 표를 따른다. |
| 출처 참조 | `SourceRef` | 정확한 기록 버전과 선택적인 세부 항목·본문 구간을 가리키는 값. 원본 AI 대화나 외부 URL을 가리키는 필드가 아니다. |
| 출처 연결 | `ProvenanceLink` | 파생 기록 버전이 사용한 출처 참조를 보존하는 연결. 답변의 출처 표시와 저장된 출처 연결을 구분한다. |
| 검색 청크 | `Chunk`, 검색 색인의 청크 | 저장 본문에서 검색을 위해 분할한 파생 구간. 세부 항목의 의미 경계와 일치할 필요가 없다. |
| 로컬 저장소 | `LocalBrain`, `brain_id` | 기록·주제·관계가 속하는 데이터 경계. 웹 화면 이름과 구분한다. |
| 지식 공간 | 웹의 홈 화면, `workspace` 관련 화면 명세 | 기록·주제·세부 항목의 연결을 탐색하고 검색하는 화면. 별도의 저장 엔터티나 공유 권한 단위가 아니다. |

## 혼동하기 쉬운 표현

- **지식**은 제품이 다루는 정보를 일반적으로 설명하거나 `knowledge` 유형을 가리킬 때 사용한다. 모든 저장 대상을 뜻하는 CRUD·목록·상세 문구는 **기록**을 사용한다. 경험·아이디어·자료도 기록이다.
- **메모**는 짧게 기록하는 사용 사례이며 별도 엔터티나 `RecordKind` 값이 아니다. **정리본**은 정리해서 저장한 본문의 표현이며 모든 기록에 요약·재작성을 요구하지 않는다.
- **세부 항목**을 화면마다 세부 지식·내용의 맥락·정리된 내용으로 바꾸어 부르지 않는다. `context` 유형의 **맥락**과 구분한다. 기술 설명에서 `Node`를 쓸 때는 이 대응을 따른다.
- **그래프 노드**는 화면 그래프의 점, **실행 노드**는 LangGraph의 실행 단계를 뜻한다. 둘 다 저장 도메인의 세부 항목과 일대일로 대응하지 않는다.
- **연결**은 주제 연결·출처 연결·그래프 연결선을 설명하는 일반 표현이다. 저장된 `Relation`을 가리킬 때는 **관계**를 사용한다. 검색 유사도나 같은 주제라는 사실만으로 명시적 관계가 생기지는 않는다.
- **출처**는 사용자가 근거로 읽는 저장본·구간이다. **답변 출처**는 그중 답변이 인용한 항목이다. 출처 참조가 유효하다는 사실만으로 주장의 진실성이나 원본 대화와의 일치를 보장하지 않는다.
- **태그**를 현재 주제와 별개의 저장 필드처럼 설명하지 않는다. 일반 분류 방식이나 다른 제품의 기능을 비교할 때는 원래 의미로 사용할 수 있다.

## 관계 유형과 표시 이름

웹의 관계 선택·표시와 MCP·API·DB는 같은 일곱 `relation_type` 값을 사용한다. 한국어 표시 이름은 다음과 같으며, 방향·근거·철회 규칙은 [데이터 스키마](../architecture/data-schema.md#relations--저장본-사이의-근거-있는-관계)를 따른다.

| 값 | 표시 이름 |
| --- | --- |
| `related_to` | 관련 있음 |
| `clarifies` | 명확히 설명함 |
| `corrects` | 정정함 |
| `supports` | 뒷받침함 |
| `contradicts` | 상충함 |
| `merged_from` | 병합해 옴 |
| `supersedes` | 이전 조건을 대체함 |

표시 문구를 바꾸어 새로운 관계 종류를 만들지 않는다. 관계 생성은 기록 병합·수정·삭제를 대신 실행하지 않는다.

## 제품 이름과 실행 식별자

제품 이름과 MCP 서버 표시 이름은 **Cache Me If You Can**, 스킬 이름과 호출 이름은 **`cache-me`**, MCP 등록 키와 스킬 의존성 ID는 **`cache_me`**다. 일반적인 개인 지식 관리 방식은 세컨드 브레인이라고 설명할 수 있지만 현재 제품 이름으로 `Second Brain`을 섞어 쓰지 않는다.

개발 버전의 Python 패키지와 MCP 등록 키는 `cache_me`, 배포 패키지와 실행 명령은 `cache-me`, 웹 패키지는 `cache-me-web`, 환경 변수는 `CACHE_ME_*`, 기본 데이터 디렉터리는 `CacheMe`, SQLite 파일은 `cache-me.sqlite3`를 사용한다. 백업 ZIP도 `cache-me-YYYY-MM-DD.zip`으로 내려받는다. 이전 제품 이름의 별칭·환경 변수 fallback·설정 및 스킬 자동 이전은 제공하지 않는다.

이 이름 변경은 기록 스키마나 `capture_create` 같은 개별 도구의 의미를 바꾸지 않는다. 기존 개발 데이터는 원본을 보존한 상태에서 새 경로로 명시적으로 복사할 수 있으며, 실행기가 이전 경로를 자동 탐색하거나 초기화하지 않는다. 설치와 데이터 배치는 [로컬 실행 가이드](../guides/local-development.md)를 따른다.

새 문서·화면 문구는 이 기준을 참조하고 의미를 바꾸는 경우 관련 명세를 먼저 갱신한다. 인용·연구·외부 제품·기술 라이브러리의 용어는 해당 맥락을 보존한다.
