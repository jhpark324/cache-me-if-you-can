주제 매칭과 등록

TCP와 UDP를 각각 한 건씩 저장하면 서재에 두 기록이 생긴다. 두 기록을 ‘전송 계층’이라는 주제에 묶을지는 서버가 그다음에 본문과 기존 주제를 읽어 결정한다.

단계별 책임

Codex 스킬 · 입력 정리
저장할 Markdown 본문을 만들고 필요하면 concept_hints에 주제 후보를 적는다. 주제 ID 조회는 생성의 선행조건이 아니다.
로컬 서버 · 저장과 후보 수집
capture_create는 본문 저장본, 검색 색인 작업, 주제 분류 작업을 한 SQLite 트랜잭션으로 기록한다. 분류 상태는 우선 pending이다.
분류 모델 · 의미 판단
서버가 선택된 모델에 본문 구간, 힌트, 기존 후보의 정의를 제공한다. 모델은 기록 전체와 해당 세부 항목의 연결을 각각 제안한다.
로컬 서버 · 확정
모델이 고른 ID가 실제 후보인지, 서버가 앞서 읽은 버전이 그대로인지 검사한다. 유효한 새 주제와 연결만 함께 저장하고, 그래프는 확정된 연결을 읽는다.
입력과 결과후보 선별검증·실패정정·교체기존 기록 보강그래프 탐색

TCP·UDP 입력과 분류 결과

네 테스트 서재에서 실제 MCP로 기록을 저장했다. 사례마다 아래의 모델 제안을 고정하고, 분류가 끝난 뒤 어떤 주제와 그래프 연결이 남았는지 확인했다.

사례 선택

다른 이름으로 같은 주제를 지목한 경우

기록 입력
“TCP는 순서가 어긋난 데이터를 정리해 전달한다.” concept_hints: ["Transport Layer"]
기존 서재
UDP 공부 기록이 ‘전송 계층’에 연결되어 있다. 이 주제에는 별칭 ‘Transport Layer’가 있다.
모델 제안
본문이 주제 정의에 맞으므로 ‘전송 계층’의 기존 ID를 선택한다.
확정 결과
TCP 기록과 UDP 기록이 같은 주제에 연결된다. 새 주제는 0개다.

기존 정의가 공부한 범위를 담지 못한 경우

기록 입력
“UDP는 데이터그램 단위로 보내며 순서와 재전송을 보장하지 않는다.” concept_hints: ["전송 계층"]
기존 서재
‘파일 내려받기’만 있다. 그 정의는 파일을 가져오는 작업 절차에 한정된다.
모델 제안
새 이름 ‘전송 계층’, 설명 ‘TCP·UDP가 애플리케이션에 제공하는 전달 방식을 다룬다’, 연결 대상은 이 UDP 기록이다.
확정 결과
주제 1개와 UDP 기록의 연결 1개가 함께 생긴다. 다른 과거 기록과의 연결은 별도 작업에서 검토한다.

힌트 없이 본문만 저장한 경우

기록 입력
“TCP는 누락된 데이터를 재전송한다. UDP 자체에는 그 보장이 없다.” concept_hints: []
기존 서재
‘전송 계층’의 설명에 TCP·UDP의 전달 보장 차이가 들어 있다.
모델 제안
본문과 정의를 읽고 기존 ‘전송 계층’을 선택한다. 힌트가 비어 있어도 분류 작업은 실행된다.
확정 결과
이 비교 기록은 ‘전송 계층’에 연결된다. 본문이 어느 후보에도 맞지 않으면 연결 0개로 마칠 수도 있다.

한 단어로 범위를 정하기 어려운 경우

기록 입력
“다음 회의에서 전송 문제를 다시 살펴보기로 했다.” concept_hints: ["전송"]
기존 서재
‘전송 계층’과 ‘파일 전송’이 있다. 메모에는 프로토콜을 다룬다는 설명도, 어떤 파일을 보낸다는 설명도 없다.
모델 제안
두 후보의 범위를 결정할 근거가 부족해 ‘전송’ 힌트를 보류한다.
확정 결과
회의 메모는 남고 주제 연결은 0개다. 분류 상태는 ready가 될 수 있고, 보류된 힌트는 내부 작업에 남는다.

후보를 고르는 규칙과 모델의 판단

주제 100개 이하

같은 서재의 모든 주제를 후보로 보낸다. 모델은 ID, 이름, 설명 발췌, 별칭을 읽는다. 본문에 이름이 직접 적혀 있지 않아도 범위를 대조할 수 있다.

주제 100개 초과

구간마다 최대 100개를 고른다. 현재 기록에 붙은 주제와 해당 구간에 걸친 세부 항목의 주제를 우선하고, 본문·힌트에 등장한 이름·별칭의 개수와 갱신 순서를 활용한다. 같은 별칭을 반복해도 한 번으로 센다. 준비된 경우 의미 검색 후보 최대 30개도 이 100개 안에 포함한다.

문자열 일치나 의미 유사도는 검토할 후보를 찾는다. 모델은 정의와 본문을 비교해 기존 주제 ID를 고르거나, 새 이름·설명·연결 대상을 제안하거나, 근거가 부족한 후보를 보류한다.

긴 본문과 새 주제의 추가 검토

본문을 최대 12,000 유니코드 코드 포인트씩 연속된 구간으로 나눠 겹치는 세부 항목과 함께 읽는다. 구간 한도는 20개이며 구간당 새 주제 제안은 최대 5개다. 여러 구간이면 결과를 통합한 뒤 한 번만 반영한다.

새 주제 제안의 이름·설명·별칭으로 다시 후보를 찾았을 때 앞에서 보지 못한 기존 주제가 있으면, 모델이 한 차례 더 기존 주제 재사용·새 제안 유지·보류 중에서 판단한다. 의미 검색이 실패해도 이름·별칭 후보로 분류를 계속한다.

후보 순위와 저장 시 이름 충돌 비교표

서버 재검증과 실패 상태

  1. 작업 자격실행 중인 작업의 임대 토큰·기한을 확인한다.
  2. 기록과 주제현재 기록 버전·상태·삭제 여부, 선택된 주제의 상태 버전, 세부 항목의 소속을 검사한다.
  3. 한 번에 반영새 주제 이름·별칭 충돌을 검사한 뒤 연결을 확정한다. 연결 집합이 달라지면 같은 본문의 새 메타데이터 저장본을 만든다.
동시에 같은 이름을 만들거나 기록을 고친 경우

새 이름과 별칭의 충돌 키는 유니코드 NFC, 대소문자 접기, 연속 공백 정리를 적용한다. 제안 중에 같은 이름·별칭이 생기거나 선택한 기존 주제의 버전이 바뀌면 VERSION_CONFLICT로 처리한다. 대상 기록이 이미 수정·삭제됐으면 옛 작업을 superseded로 종료한다. 두 경우 모두 옛 제안 전체를 버린다.

로그인 전 대기, 모델 오류, 연결 0개의 차이

분류에 사용할 계정·모델이 준비되기 전에는 대기(pending)하고, 작업을 맡으면 실행 중(running)이 된다. 유효한 결과를 반영하면 연결이 없어도 완료(ready)다.

모델 호출이나 응답 검증 실패가 failed로 남으면 오류 원인을 해결하고 현재 작업 ID와 기대 버전으로 capture_retry_concepts를 호출해 같은 작업을 재시도할 수 있다. 본문 저장과 검색 색인은 별도여서 이미 저장한 기록은 목록에서 읽을 수 있다.

입력 수정과 주제 연결 교체

기록 본문·힌트·세부 항목 수정
일반 수정에 body_markdown, concept_hints, nodes 중 하나가 들어가면 현재 저장본을 다시 분류한다. 기존 연결도 후보로 포함한다. 힌트를 생략하면 기존 값을 유지하고 []는 힌트만 비운다.
제목·완료·공개 범위 변경
이 변경만으로 완료된 기록을 새로 분류하지 않는다. 이전 작업이 대기·실행 중이면 새 버전을 대상으로 이어간다.
사용자가 지정한 연결 정정
capture_set_concepts는 현재 버전을 확인하고 지정한 기록 주제 집합으로 교체한다. node_concepts를 생략하면 세부 항목 연결을 보존한다. 제공하면 전체 세부 항목 집합을 교체해 빠진 항목의 연결도 비운다. 정정 자체는 다시 분류하지 않는다.

주제 정의가 바뀐 뒤의 기존 기록 보강

‘전송 계층’을 새로 만들거나 이름·설명·별칭을 실제로 바꾸면, 그 정의에 맞는 과거 기록을 찾아 연결하는 작업이 등록된다. 새로 저장한 기록 한 건을 분류하는 작업과 입력 방향이 반대다.

  1. 새 정의 → 본문 검색주제 이름·설명·별칭으로 기존 본문을 검색해 최대 20개 고유 기록을 고른다.
  2. 발췌 → 모델 판단최대 5건씩 발췌를 보고 연결·제외·보류한다. 재시도 포함 모델 호출은 작업당 최대 4회다.
  3. 확정 → 연결 추가현재 정의와 기록 상태를 다시 확인하고 확정된 기록 수준 연결만 더한다. 기존 주제와 세부 항목 연결은 보존한다.
보강에서 제외하거나 기다리는 기록

이미 해당 주제와 연결된 기록, 삭제되거나 출처가 무효인 기록, 수동 주제 정정 이력이 있는 기록, 일반 분류가 실패한 기록은 제외한다. 검색 색인과 일반 분류가 준비 중이면 기다린다. 단지 기록에 연결을 추가했다는 이유로 새 보강을 반복하지 않는다.

지식 공간에서 연결 확인

‘지식 공간’에서 ‘전송 계층’을 고르면 현재 그래프의 실제 주제 연결이 강조된다. 기록 전체에 붙은 주제와 세부 항목에 붙은 주제를 구분하며, 둘 다 이어진 기록도 한 건으로 센다.

점이나 이름을 누르면 해당 기록 또는 본문 구간의 출처를 읽는다. ‘이 주제의 모든 기록’은 주제 필터가 적용된 목록을 연다. 그래프 안의 수는 현재 표시 범위의 연결 수다.
