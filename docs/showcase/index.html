제목 없이 본문만 저장해도 됩니다. 연결된 모델이 있으면 저장 뒤에 주제를 분류합니다. 힌트는 선택 사항이에요. 범위가 맞으면 기존 주제를 쓰고, 뚜렷한 새 주제가 있으면 만듭니다. 애매하면 연결을 보류합니다.

잘못 붙은 주제를 고치려면?

Codex에 어느 기록의 주제를 어떻게 고칠지 알려 주세요. 웹에서는 연결된 주제를 확인하고, Codex에서는 capture_set_concepts 도구로 정정할 수 있습니다.

당시 결정에 달린 인용은 여전히 두 명이 버튼을 찾았던 문장을 엽니다. 최신 기록을 열면 다섯 명의 결과가 보입니다. 아티클의 인용도 작성할 때 읽은 버전과 구간을 가리킵니다.

  • 가까운 뜻

‘벌’이라는 낱말과 꽃가루를 옮기는 행동의 뜻으로 본문을 찾습니다. ‘꽃가루받이’처럼 주제 이름이나 별칭이 맞으면 거기에 연결된 기록도 살핍니다. 현재 저장본에서 확인한 구간이 답변의 근거가 됩니다.

내 기기 밖으로는 어떤 내용이 가나요?

내 기기원문 보관 · 검색
↓ 모델을 쓰는 작업에서 전달
외부 모델답변 ← 질문과 근거 발췌
주제 분류 ← 기록 본문과 후보 주제

정원 노트를 다시 열거나 검색하는 일은 내 기기에서 처리합니다. 웹에서 질문하면 답에 필요한 맥락이, 자동으로 주제를 붙일 때는 분류할 기록의 본문과 후보 정보가 연결된 외부 모델로 갑니다.

내 기기 안에서
어떻게 이어질까?

Codex에 말하거나 웹에서 직접 적으면 같은 로컬 서버가 요청을 받습니다. 서버는 기록을 보관하고, 나중에 찾을 수 있도록 검색용 색인을 만듭니다.

Codex가 서재에 말을 거는 방법 MCP

MCP는 Codex가 로컬 서버의 도구를 호출하는 통로입니다. capture_create는 요청한 내용을 기록으로 저장하고, article_create는 완성된 글을 별도 아티클로 발행합니다. source_get은 인용할 기록의 정확한 버전과 구간을 읽습니다.
