# ADR-006: 휴지통·복원 없는 soft delete

- 상태: `accepted`
- 작성일: 2026-11-02
- 관련 설계: [제품 기획](../project/product-brief.md#변경과-삭제), [저장 스키마](../architecture/data-schema.md), [서비스 계약](../architecture/service-contracts.md)

## 배경

삭제 기록의 이력과 출처 정합성을 내부에서 보존하면서 제품의 삭제 동작은 단순하게 유지한다. 삭제 전 대상을 제시하고 재확인하며, 삭제 후 제품에서 다시 조회하거나 복원하는 경로는 제공하지 않는다.

## 검토한 대안

| 대안 | 판단 |
| --- | --- |
| 휴지통·복원 제공 | 조회·복원 상태와 권한의 복잡도를 늘리므로 현재 범위에서 제외 |
| `deleted_at`으로 삭제 표시, 제품에서 접근 제외 | 채택. 내부 정본·이력·출처 정합성을 유지하고 제품 동작을 단순화 |
| 즉시 물리 삭제 또는 자동 만료 | 내부 이력·출처 보존 정책과 맞지 않아 제외 |

## 결정

서버가 삭제 대상·현재 버전·사용자 재확인을 검증한 뒤 `deleted_at`을 설정한다. 기록의 본문·모든 revision·관계는 내부에 보존하며, 제품의 목록·상세·과거 버전·Node·그래프·검색·질의응답·수정에서 삭제 기록을 제외한다.

삭제 목록, `include_deleted` 같은 조회 우회, 복원, 실행 취소, `deleted_at`을 null로 바꾸는 일반 PATCH를 제공하지 않는다. 삭제 기록의 본문·제목은 출처 응답을 통해서도 노출하지 않는다. 정상 삭제 요청의 재시도에는 본문 없는 최초 커밋 영수증만 반환할 수 있다.

자동 보관 기한·자동 삭제·수동 영구 삭제는 두지 않는다. 다른 독립 기록을 연쇄 삭제하지 않으며, 파생 기록의 출처가 삭제되면 근거 사용을 제한하고 명시적인 출처 재검토 경로로 처리한다.

## 결과와 후속 조치

- UI·MCP에 휴지통·복원 기능이 없어야 한다. 삭제 확인에서는 사용자가 제품에서 다시 조회·복원할 수 없다는 결과를 알린다.
- 색인 정리가 늦어져도 SQLite 상태 확인으로 즉시 노출을 차단한다. 프로세스 재시작이나 오래된 요청 재시도가 삭제 상태를 되돌리지 못하게 한다.
- 백업은 삭제 표시를 포함하는 내부 데이터 사본이며 개별 기록 복원 기능으로 연결하지 않는다. 디스크 완전 소거를 제공한다고 표현하지 않는다.
- 연구에서 사용한 상태 모형과 현재 제품의 삭제 계약을 구분한다.

## 대체 관계

- 대체하는 결정: 이전 제품·공통 스키마의 휴지통 조회·복원 동작. ADR-001·002·003·005의 기술 선택은 유지하며 삭제 관련 후속 동작에만 이 결정을 적용한다.
- 이 결정을 대체한 기록: 없음.
