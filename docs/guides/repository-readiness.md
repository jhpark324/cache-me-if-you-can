# 저장소·배포 전 점검

코드와 문서를 배포하기 전에 포함할 파일, 재현 가능한 설치, 라이선스와 지원 범위를 확인한다. 검사 실행 방법은 [테스트 가이드](testing.md)를 따른다.

## 포함할 파일

프로젝트 루트에서 실행한다.

```sh
python scripts/preflight.py
```

이 검사는 작업 트리의 등록 후보와 현재 Git index에서 민감한 파일 경로, 일부 알려진 비밀 패턴, 큰 파일, 심볼릭 링크, Markdown 상대 링크를 확인한다. 파일을 stage하거나 설정을 변경하지 않는다. `.gitignore`에 추가해도 이미 추적하거나 stage한 파일은 자동 제외되지 않는다.

검사는 Git 과거 이력, 원격 상태, 이미지 안의 글자, 모든 형태의 비밀을 확인하지 않는다. 공개할 이미지와 첨부 파일은 내용도 살핀다. 사용자 DB·색인·인증 파일·백업·실제 대화와 로컬 실행 로그는 공개 저장소에 넣지 않는다. 개발 기록과 재사용할 예제를 구분하는 기준은 [공개 문서 관리](documentation.md)에 있다.

## 설치와 자동 검사

`python scripts/manage.py setup`은 uv의 `--locked` 설치와 `npm ci`를 사용한다. 의존성을 바꿨다면 관련 잠금 파일도 갱신하고 [자동 검사](testing.md#기본-검사)를 실행한다.

[CI 워크플로](testing.md#ci와-수동-확인)는 외부 계정 자격증명 없이 저장소, 백엔드, 프런트엔드를 각각 검사한다. 원격 실행 결과는 [해당 커밋의 Actions](https://github.com/jhpark324/cache-me-if-you-can/actions)에서 확인한다.

CI 통과만으로 실제 모델의 답변 품질, 공급자 로그인, 사용자 확인창 또는 모든 운영체제의 네이티브 실행을 보증하지 않는다. 배포할 버전에서 지원한다고 명시할 환경은 별도로 확인한다.

## 의존성과 라이선스

`npm audit`와 Python `pip-audit`는 실행 시점의 알려진 의존성 취약점을 확인하는 보조 수단이다. 실행 결과의 날짜·대상 버전·제외 항목을 릴리스 검토에서 확인하며, 전체 애플리케이션의 안전성 인증으로 취급하지 않는다.

프로젝트 코드의 배포 라이선스는 아직 선택되지 않았다. 공개 배포 전에 저작권자가 결정해야 한다. 배포에 포함하는 글꼴·라이브러리의 라이선스 고지를 유지하고, 모델의 라이선스와 배포 조건도 확인한다. 모델 가중치와 개인 데이터는 저장소에 포함하지 않는다.

## 지원 범위

[플랫폼 지원 문서](../architecture/platform-support.md)의 확인한 환경과 미검증 사항을 그대로 반영한다. 소규모 합성 데이터의 성공률을 일반 검색 정확도나 서비스 수준 보장으로 확대하지 않는다. 기능·동작이 달라졌다면 [현재 명세](../specs/index.md), 사용자 가이드와 예제를 함께 갱신한다.
