# 공개 문서 관리

문서는 처음 사용하는 사람과 기여자가 현재 제품을 이해하고 같은 절차를 재현할 수 있게 작성한다. 프로젝트 문서는 `docs/`, 에이전트 진입점은 루트 `AGENTS.md`에서 관리한다.

## 공개 문서의 범위

| 위치 | 내용 |
| --- | --- |
| `README.md`, `guides/` | 제품 소개, 설치·사용·기여·검사 방법 |
| `specs/` | 현재 기능의 범위와 관찰 가능한 수용 기준 |
| `architecture/` | 현재 구조, 데이터·API 계약, 동작 원리와 한계 |
| `decisions/` | 유지보수에 필요한 기술 선택과 이유 |
| `examples/` | 재사용할 수 있는 합성 자료와 실행 방법 |
| `research/` | 조건과 재현 방법을 명시한 기술 조사·평가 |
| `assets/` | 현재 제품을 설명하는 이미지와 필요한 고지 |
| `skills/` | 배포할 에이전트 스킬 원본 |

개인 계정의 로그인 상태, 대화별 요청·승인·보류 사유, 개인 저장소의 데이터 추가·초기화 이력, 임시 절대 경로, 폐기한 디자인 시안과 회차별 실행 로그는 공개 문서에 누적하지 않는다. 필요한 개발 기록은 체크아웃 밖의 비공개 작업 기록이나 CI 산출물에 보관한다.

## 유지할 정보

제품 문서·화면·스킬의 이름은 [도메인 용어](../project/domain-language.md)를 기준으로 한다. 같은 저장 대상을 서로 다른 이름으로 부르지 않으며, API·DB·MCP의 호환 식별자는 표시 문구와 구분한다. 연구·인용·외부 제품의 원래 용어와 일반적인 지식·메모 표현은 해당 맥락을 유지한다.

- 미지원 환경·알려진 제한·재현 가능한 테스트 명령을 남긴다. 검증 기록을 정리하면서 미검증 기능을 지원 완료로 바꾸지 않는다.
- 합성 데이터는 실제 사용자 자료와 구분한다. 재사용할 데이터셋과 실행에서 생성된 ID·manifest·응답 로그를 분리한다.
- 코드가 참조하는 예제 경로와 문서 생성기 입력은 함께 변경하고 실행으로 확인한다.
- 필요한 라이선스·저작권 고지는 배포하는 코드·자산과 함께 유지한다.
- 공개 문서에서 같은 사실은 한 곳을 기준으로 삼고, 관련 문서는 링크한다.

## 변경 확인

문서를 이동하거나 제거할 때 가장 가까운 `index.md`와 진입 링크를 갱신한다. Markdown 링크, 코드의 문서·예제 참조, 생성된 HTML/SVG의 이전 경로를 확인한다. `python scripts/preflight.py`와 변경한 생성기·예제 검사를 실행한다. 공개 상태 변경, 배포, Git 이력 재작성은 문서 정리에 포함하지 않는다.
