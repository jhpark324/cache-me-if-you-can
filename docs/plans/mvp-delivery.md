- 상태: 후속 1~4번 구현·검증 완료. 실제 로그인·응답·갱신·Codex 사용자 삭제 승인까지 확인. 원격 로그아웃 후 재로그인·네이티브 OS 관문은 남음
- 갱신일: 2026-11-02
- 제품 범위: [MVP 범위](../project/mvp-scope.md)
- 공통 계약: [저장 스키마](../architecture/data-schema.md), [서비스 계약](../architecture/service-contracts.md), [검색·맥락](../architecture/retrieval-and-context.md)

P0가 미확정이어도 모델과 무관한 기록 도메인·명세·입출력 검증은 진행할 수 있다. P0를 통과하기 전에 모델 연동이나 Codex 삭제 확인을 완료로 표시하지 않는다. P2 이후 기능은 공통 계약을 출발점으로 삼되 실제 착수할 때 기능 명세를 생성한다. 아직 착수하지 않은 기능 폴더를 자리표시자로 만들지 않는다.

## 단계별 구현 범위

### P0 — 실행 기반·로그인·MCP

- FastAPI 진입점, 설정, 사용자 데이터 경로, 로컬 접근 경계와 공통 오류 응답을 준비한다. 웹·MCP가 같은 도메인 서비스를 호출하게 한다.
- ChatGPT 자체 로그인 시작·callback·상태·로그아웃과 토큰 갱신을 모델 어댑터에 연결한다. 계정 자격 증명은 기록·색인·응답 본문·백업과 분리한다.
- 실제 계정에서 사용할 수 있는 모델을 확인하고 응답·도구 호출·스트리밍·취소를 검증한다. 구체적인 기본 모델 이름은 이 결과에 따라 고정한다.
- 공식 MCP Python SDK v2와 Streamable HTTP를 연결한다. SDK의 메이저 버전과 날짜 형식의 MCP 프로토콜 버전을 별도로 기록한다.
- Codex에 연결할 설정과 기록 관리 Skill을 준비하고, 구조화 결과·오류·삭제 재확인 왕복을 실제 클라이언트에서 확인한다. 어댑터 단위 시험만으로 사용자 재확인이 검증됐다고 표시하지 않는다.

### P1 — 기록과 지식 계층

- SQLite 정본, SQLAlchemy 모델과 Alembic 마이그레이션을 구성한다. 저장·revision·색인 작업의 트랜잭션 경계를 함께 구현한다.
- Capture 추가·목록·상세·수정·명시적 완료 상태 변경을 연결한다. 저장 응답에는 실제 반영된 내용을 반환하고, 예상 revision을 통한 충돌과 멱등 요청을 처리한다.
- 주제 연결·별칭·명시적 병합, Node와 본문 구간, 관계·SourceRef와 변경에 따른 재검토를 구현한다. 도메인 계약을 웹과 MCP에 중복 구현하지 않는다.
- 삭제는 확인 요청과 실행을 구분한다. `deleted_at`을 기록한 뒤 목록·검색·상세·이력·그래프·출처·MCP에서 제외한다. 휴지통·복원·자동 삭제 기능을 추가하지 않는다.
- 실제 임시 DB에서 저장 후 재시작, 충돌·중복 요청, 삭제와 파생 출처의 상태 변경을 검증한다. 상세 수용 기준과 결과는 [002 검증 문서](../specs/002-record-management/validation.md)에 둔다.

### P2 — 색인·검색·에이전트 맥락

- [수집·청크 계약](../architecture/ingestion-and-chunking.md)에 따라 전체 Markdown을 구간으로 나눈다. 임베딩 입력의 제목·마커와 원문 위치를 분리하고, 본문 누락 없이 각 청크의 revision·span을 보존한다.
- KURE-v2의 `MultiVectorEncoder`와 CPU float32를 기본으로 연결한다. 프로필·모델 revision·정규화·다중 벡터 차원을 기록하고 준비 중·실패·재시도 상태를 노출한다.
- SQLite 색인 작업을 재시도 가능한 처리기로 실행하고 LanceDB에 반영한다. 수정·삭제·재시작으로 낡은 세대가 남아도 검색 시 SQLite 현재 상태로 다시 검사한다.
- 키워드·다중 벡터 검색과 RRF, 기록 유형·주제·시점 필터, 부모 기록 중복 제거와 Node span 매핑을 구현한다. 초기에는 정확 검색을 기준으로 삼고 ANN은 품질·지연 근거가 있을 때 활성화한다.
- 모델 로그인 없이 `knowledge_search`·`knowledge_context`·상세 출처 조회를 제공한다. 현재 근거와 과거 출처를 구분하고 변경·상충·확인 필요 상태를 보존한다.
- 긴 본문·긴 질의·한영 혼합·부정·미분류·정정·삭제 사례를 평가한다. 64토큰 임베딩 질의 제한을 웹 질문 글자 제한으로 바꾸거나 입력을 조용히 자르지 않는다.

### P3 — LangGraph 단일 검색 응답

- 원 질문과 명시 필터를 보존해 짧은 검색 질의를 만들고, 필요한 추가 조회·근거 선택·답변 생성을 LangGraph에 연결한다.
- [검색·맥락 계약](../architecture/retrieval-and-context.md)의 호출·근거·시간 예산을 적용한다. 근거가 부족하면 확인된 범위와 한계를 보여주며 저장된 사실과 일반 설명을 구분한다.
- 요청별 ID, 이벤트 스트리밍·취소·오류·종료를 구현한다. 새 검색에 이전 질문이나 답변을 전달하지 않고, 원문 질문·답변을 영구 체크포인트나 본문 로그에 저장하지 않는다.
- 출처를 보내기 전과 완료 시 현재 상태를 다시 검사한다. 답변 도중 근거가 정정·삭제되면 무효화 이벤트를 보내고 정상 완료로 처리하지 않는다.
- 답변의 기록 저장은 사용자의 명시적 동작에만 연결한다. 실행 흐름 시험과 실제 로그인 모델의 근거 품질 시험을 구분해 기록한다.

### P4 — 실제 데이터로 사용하는 웹

- 003 시안의 검정 배경·어두운 유리 패널·흰 글씨·주황 강조·검색 오로라·모션을 실제 React 화면에 옮긴다. 제한된 홈 그래프 위에 검색·답변과 출처 패널이 공존하게 한다.
- 홈에는 제한된 지식 그래프·검색·새 기록을 두고 최근 기록을 탐색 패널에서 제공한다. 선택한 기록에서 제한된 주변 그래프를 연다. 그래프 기본 1홉·50개 노드·100개 관계와 초과 표시를 지킨다.
- 기록 작성·저장 결과 확인·정정·상세·이력·충돌·재확인 삭제를 실제 API에 연결한다. 소프트 삭제의 내부 구현 용어 대신 사용자가 겪는 결과를 안내한다.
- 검색 입력 바로 아래에 단일 응답을 표시하고, 출처 클릭 시 오른쪽 패널에서 해당 revision·구간을 보여준다. 좁은 화면에서는 패널을 전체 화면으로 전환한다.
- 로그인·모델 준비·색인 실패/재시도·데이터 경로·수동 백업 상태를 연결한다. 모델 연결 실패 시에도 기록 관리와 가능한 검색 결과를 사용할 수 있게 한다.
- 키보드 탐색·패널 포커스·모션 감소 설정·글자 대비·모바일 레이아웃과 빈 상태를 확인한다. 목데이터의 클릭 동작과 실제 저장·삭제 검증을 구분한다.

### P5 — 배포·운영·수동 백업

- Python 서버와 정적 웹 번들의 실행·빌드·개발 명령, 의존성 고정 및 첫 실행 안내를 마련한다. 프로젝트 운영 문서는 `docs/`에서 관리한다.
- GPU·WSL·Docker 없이 CPU로 실행하는 설치 경로를 검증한다. 초기 모델 다운로드·로딩 중에도 기록 CRUD를 사용할 수 있게 준비 상태를 분리한다.
- SQLite의 일관된 스냅샷과 스키마·모델 프로필 manifest를 수동 백업한다. 파생 색인·모델 가중치·로그인 비밀은 제외하고, 격리된 위치에서 백업 무결성을 확인한다.
- 백업에는 내부 보존 중인 삭제 기록도 포함된다는 점을 알린다. 이는 개인용 전체 백업이며 공개 공유나 삭제 기록 복원 UI로 취급하지 않는다. 백업 가져오기·전체 복원 UI는 후속 범위다.
- [플랫폼 지원 기준](../architecture/platform-support.md)에 따라 OS 버전·CPU 아키텍처·Python·패키지·모델 revision을 기록한다. 한글·공백 경로, 종료·재시작과 중단 작업 복구를 함께 시험한다.

## 현재 구현 상태

[002 기록 관리](../specs/002-record-management/validation.md)와 [004 로컬 런타임](../specs/004-local-runtime/validation.md)에 실제 결과를 기록했다. 기록 저장소, 주제/Node/관계와 출처 정정, KURE/Lance 검색, LangGraph 실행, 자체 로그인 어댑터, MCP 22개 도구, 실제 웹/백업이 구현되어 있다. P0~P5 전체 완료는 아래 외부 관문 및 004의 남은 구현 항목을 마친 뒤 판정한다.

## 기획·설계 기준

- 제품 범위·아홉 기록 유형·soft delete 정책
- 공통 저장 구조와 MCP·웹 입출력 계약, 검색·맥락 선택 기준
- 첫 기능 002의 명세·설계·작업·검증 계획
- 기존 KURE-v2의 제한된 WSL CPU 실험과 그래프 라이브러리 기술 실험 이력

문서가 있다는 사실은 구현이나 수용 기준 통과를 뜻하지 않는다. 실제 체크 상태는 각 기능의 작업·검증 문서에서 관리한다.

## 첫 구현의 우선순위

1. P0에서 계정·모델·클라이언트의 실제 제약을 확인하면서 P1의 SQLite 모델·마이그레이션·도메인 계약을 구현한다.
2. 본문만 저장→상세 조회→수정→재확인 삭제의 최소 흐름을 먼저 연결한다.
3. 주제·Node·관계·출처 재검토와 멱등성·수정 충돌을 같은 공통 서비스에 추가한다.
4. 정본의 동작이 확인되면 검색과 질의응답을 붙이고 각 단계에서 삭제·정정된 근거가 돌아오지 않는지 확인한다.

| 검색 정합성 | 장문 저장→색인→질문/주제/Node로 조회→본문 정정→재색인 실패/재시도→삭제→출처 재조회 | 실행한 데이터·모델 프로필·환경에서의 색인·검색·출처 상태 |
| 단일 응답 | 로그인→질문→검색 아래 답변→출처 패널→새 질문/취소→근거 수정/삭제→실패 및 무효화 | 실제 모델을 썼다면 모델 결과까지. 테스트 어댑터 결과만으로 실제 모델 품질을 주장하지 않음 |
| 백업·운영 | 사용 중 백업→격리 무결성 검사→재시작→중단 작업 재처리 | 검증한 백업 형식·데이터·환경. 복원 UI나 기기 동기화는 포함하지 않음 |
| 배포 | OS별 깨끗한 설치→CPU 모델 준비→웹·Codex·로그인→CRUD·검색·삭제·재시작 | 수행한 OS·아키텍처 조합만. WSL 시험을 Windows/macOS 네이티브 검증으로 확대하지 않음 |

각 기능의 `tasks.md`와 `validation.md`가 실제 진행·실행 결과의 정본이다. 이 문서는 기능 간 순서·완료 조건을 관리한다. 실패와 미실행 항목은 남기고, 사용자에게 보여주는 구현 완료 범위를 검증 범위와 함께 설명한다.

## 남은 제품 결정과 외부 검증 관문

착수를 막는 새 제품 결정은 현재 없다. 기록 유형·공개 범위·삭제·단일 응답·출처 패널·제한된 그래프·수동 백업은 기존 계약대로 구현한다. 사용자가 시안과 실제 웹의 차이 개선을 요청하여 제한된 홈 그래프·검색·답변·출처 공존을 현재 MVP 명세에 반영했다. 무제한 전체 그래프 로드는 포함하지 않는다. 상세 수용 기준은 [홈 그래프 개선](../specs/004-local-runtime/home-graph-refresh.md)을 따른다.

답변 모델의 구체적인 이름, Python·패키지 버전 조합, 미해결 플랫폼 설치 경로, 실제 한국어 검색의 품질·지연 예산은 실험 결과로 확정한다. 기획에서 임의 수치로 성능 통과를 선언하지 않는다. 사용자 입력 상한·페이지 크기 등 제품 기본값은 공통 계약의 값으로 시작해 실제 사용 결과에 따라 변경 이력을 남긴다.

다음 항목은 소스 구현이나 로컬 자동 시험만으로 완료할 수 없다.

- 실제 ChatGPT 로그인·계정 모델 카탈로그·대표 응답은 004에서 확인했다. 실계정 갱신과 실행 앱의 로그인 시도 취소도 확인했다. 원격 로그아웃 후 재로그인은 남아 있다. 공급자 등록이나 계정 설정이 필요한 경우 연결 코드를 준비한 뒤 필요한 입력을 구체적으로 안내한다. 자동으로 다른 인증 방식으로 바꾸지 않는다.
- 실제 Codex MCP 연결·구조화 결과·삭제 거부와 사용자 승인 왕복은 확인했다. 사람의 응답을 검증 클라이언트로 전달했으며 네이티브 폼의 시각 렌더링 검사는 별도다.
- Windows·macOS·Linux 네이티브 CPU 실행. 현재 WSL 실험을 전체 OS 통과로 표시하지 않으며, Intel Mac·Windows ARM64의 설치 경로를 해결하기 전에 지원을 완료했다고 선언하거나 해당 대상을 임의 제외하지 않는다.
- 고정 한국어 합성 15사례와 실제 모델 3사례를 평가했다. 더 큰 실사용 자료의 품질·자원 측정은 별도이며 작은 자료의 수치를 일반 성능으로 확대하지 않는다.

이 관문이 남아 있어도 관련 없는 구현·로컬 검증은 계속 진행한다. 검증으로 확정 요구와 충돌이 드러나거나 지원 범위·로그인 방식·검색 모델을 바꿔야 할 때에는 근거와 선택지를 제시하고 해당 명세·결정 기록을 먼저 갱신한다.
