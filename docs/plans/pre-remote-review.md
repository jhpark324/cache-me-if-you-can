# 리모트 등록 전 통합 점검

- 요청: 기능 오류·주제 구조·차별화 조사·유지보수성·문서·리모트 등록 준비 점검과 필요한 수정.
- 상태: 점검·수정·로컬 검증 완료. 남은 공개/OS/실계정 관문과 최신 결과의 기준은 [2026-11-03 재점검](../specs/004-local-runtime/prepublish-review-2026-11-03.md)이다.
- 기존 제품 범위와 공개 범위 기본값을 유지한다. 새 제품 기능은 근거와 우선순위를 제안하고 확정 기능으로 기록하지 않는다.

2026-11-03 사용자 후속 요청에 따른 현재 코드의 재점검과 README·스크린샷 보강을 완료했다. 이 후속 회차의 범위·체크리스트·최신 결과는 [재점검 기록](../specs/004-local-runtime/prepublish-review-2026-11-03.md)에서 관리한다.

## 작업 분담과 순서

1. 백엔드: 기록·주제·검색·근거·동시성 계약을 코드와 시험으로 대조하고 재현한 결함을 수정한다.
2. 프런트엔드: 필터·출처·편집·오류 복구를 점검하고 변경의 영향 범위에 맞게 구조를 정리한다.
3. 제품 조사: 공식 자료로 비교하고 실제 구현과 제안 기능을 구분한다.
4. 통합: 실행·의존성·민감정보 제외·문서 링크와 상태를 점검하고 현재 아키텍처를 시각화한다.
5. 최종: 격리 저장소의 자동 시험과 실제 화면 읽기 검증을 수행하고 남은 관문을 기록한다.

현재 로그인과 실제 저장소는 유지한다. 시험 데이터 변경·삭제는 격리 저장소에서 수행한다. 리모트 생성·push는 이번 점검의 범위가 아니다.

## 검증 기준

- 재현한 기능 결함의 수정에는 실패 경로를 검증하는 회귀 시험을 남긴다.
- 사용자 데이터·로그인 파일·로컬 캐시·빌드 결과가 리모트 등록 후보에서 제외되도록 한다.
- 잠금 파일을 사용한 설치와 검사 절차를 제공한다. 실행하지 않은 네이티브 OS·실계정 재로그인은 미검증으로 유지한다.
- 설계 초안과 현재 구현을 구분하며 문서 링크와 다이어그램의 참조 경로를 확인한다.
- 경쟁 제품의 공식 자료를 인용하고, 고유성·성능·품질을 실험 없이 단정하지 않는다.
